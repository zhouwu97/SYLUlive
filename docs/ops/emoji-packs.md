# 表情包投稿存储与审核运维

正式部署统一使用 [DEPLOY.md](../../DEPLOY.md)，本文件不构成生产操作授权。接口与额度见 [API](../../server/API.md#表情包导入投稿与审核)，产品流程见 [资源契约](../design/emoji-resource-contract.md)。

## 存储与迁移

启动 AutoMigrate 新增 `community_emoji_packs`、`community_emoji_pack_assets`，不修改旧表情、收藏和消息表。文件写入现有 `UPLOAD_DIR/.emoji-submissions`，按服务端生成的包 ID 分目录，先 staging 再 rename、事务入库；失败回收 staging 和未提交目录。该目录跟随现有持久上传卷备份与恢复；目录和数据库必须在同一备份批次中保全。

免费商城增量通过同一 AutoMigrate 新建 `emoji_creators`，并为投稿兼容增加版本族、服务端版本号、创作者来源、封面/图标、标签、派生资源版本与实际存储大小等列。历史记录的 version 默认为 1、family_id 缺省时回退自身 ID，不重新计算旧 Manifest。不得批量把历史投稿作者或管理员自动标为创作者；新申请经管理员处理后才开放新增投稿，存量待审记录保留原审核路径。当前方案见 [ADR-003](../design/adr/003-free-emoji-store-and-creator-access.md)。

缩略图、封面、图标仍在各投稿私有目录内，与主图一起回收和备份；只允许通过同样鉴权的 API 读取。派生图不进入既有 Manifest，目录通过独立字段声明。100 MiB 账号投稿空间包括派生图。下架当前公开版时关闭该作品历史版本入口；待审更新不改变旧版，审核通过才切换。

该子目录没有普通 File 公开授权记录。必须继续由 Go `ServePublic` 授权 `/uploads/*`，禁止 Nginx alias、CDN、对象存储或文件服务器新增可直接访问本目录的静态入口；专用 API 按投稿状态和账号归属读取。代理须允许上传请求体的部署目标上限，发布前核对当前 Nginx 配置；本次没有修改任何生产代理配置。

作者撤回后先在事务内标为 withdrawn 并删除资源关系，再清理文件；文件清理失败可再次撤回重试。注销账号会在既有注销事务内撤回全部投稿，立即停止公开和私有图片访问。规范化图片不保留上传原图/EXIF；旧消息仍引用原有独立 File，已安装本机副本不远程擦除。

## 清理与观察

启动和每小时执行专用孤儿目录清理，只处理本功能生成、超过 24 小时且无有效投稿的目录及 `.stage-*`；运行正常时孤儿文件最多约 25 小时清理。数据库不可用时停止清理，避免把正常文件当作孤儿；失败日志含 `emoji pack maintenance unavailable` 或 `emoji pack orphan cleanup unavailable`，恢复数据库/存储后自动重试。

正常已关联投稿不按目录年龄删除。待审、已驳回、已下架的图片继续私有保存，作者可撤回；元数据与操作日志按既有账号匿名化及内容治理记录保留。备份保留期、值守与审核时效仍需维护者在正式发布记录中确认，不以本地代码测试代替运营验收。

## 发布与回退

1. 在可丢弃的 PostgreSQL 和独立上传卷验证首次启动、重复启动、旧客户端官方包/收藏、用户上传、管理员审核及 Range 下载。
2. 从真实代理入口验证匿名和他人不能读取待审/下架图片，直接 `/uploads/.emoji-submissions/...` 不能访问；检查公开资源不被 CDN 缓存。
3. 验证两位管理员同时处理仅一个成功，撤权后旧 JWT 无法读取/处理他人投稿，上传超时重试不重复入库，撤回和注销后公开资源立即 404。
   同时覆盖创作者申请/开通/驳回/暂停、本人不能自审、暂停后在途投稿和审核通过被阻断；检查他人无法读取静态缩略图/封面/图标、下架后旧 version URL 不能绕过。验证旧 v1 升级和重复启动仍能按原 Hash 下载。
4. 按 DEPLOY.md 发布服务端，通过人工验收后发布客户端，并记录责任人、不可变提交、构建物及明确放行决定。

回退只切换代码/客户端入口，保留新增表与私有卷，不删除或重写审核记录；旧服务端只暴露原内嵌官方包。需要恢复新功能时重新部署对应代码并核验 DB 与文件完整性，不通过手工改状态绕过审核。

回退到不理解版本族的旧服务端前，须先在正式发布入口阻断社区目录、新投稿、创作者和社区资源路由，新客户端停止获取社区包；旧官方目录、收藏和历史消息继续使用原协议。仅回退二进制而继续开放新版社区目录不安全，旧代码可能把版本记录 ID 当成独立作品。新表、版本与私有文件全部保留，不做破坏性逆迁移。
