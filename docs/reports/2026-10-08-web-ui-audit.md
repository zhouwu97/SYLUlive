## 已复现的缺陷

P1 表示应优先处理的核心操作、数据呈现或可读性问题；P2 表示应随后处理的局部交互、窄屏或状态表达问题。这里的优先级不是开发风险等级。

### 1. P1：集市图片溢出，覆盖商品信息

前置：真实集市中有商品图片。操作：查看商品卡片。预期：图片限制在独立图片区，标题、价格及发布时间位于下方信息区。实际：图片的渲染高度超过图片区，文字直接叠在复杂照片上；部分时间文字难以辨认。

实测一张卡片的图片区约 145px 高，图片约 283px 高，图片区 `overflow: visible`。图片确实加载成功，属于布局问题。位置：`web/src/community.tsx:160`、`web/src/styles.css:135`、`web/src/prototype.css:3696`。

修改：让图片区拥有明确的尺寸与裁切边界，约束 Grid 图片的最小尺寸和实际高度；信息区采用不透明底色并保持正常文档流。覆盖横图、竖图、无图和加载失败。证据：`market-image-overlap.jpg`。

### 2. P1：手机 AI 输入框被挤到约 20–28px 宽

前置：390px 宽度。操作：打开 AI，输入问题。预期：输入区有足够宽度可阅读和编辑。实际：输入框近似一根竖条。内置浏览器测得约 20px，独立 Chromium 诊断测得 28.125px。

原因：输入框与含发送按钮、长提示文字的 `.inline-actions` 共用横向 Flex，后者占据大部分宽度。位置：`web/src/ai.tsx:166`、`web/src/prototype.css:1326`。

修改：将提示单独放在输入栏下方；输入栏按“可伸展输入框 + 固定宽度按钮”布局，手机输入框占主要宽度。证据：`ai-mobile.jpg`；诊断用例“手机 AI 输入框应有可用宽度”。

### 3. P1：学分要求查询结果切换栏目后丢失

前置：使用合成教务返回值成功读取“学分要求”。操作：切到“成绩”，再回到“学分要求”。预期：已取得的模块及获取时间仍在。实际：模块消失，重新显示要求更新资料的空状态。

原因：`main.tsx` 的页面 section 以 pathname 和 search 共同作为 key；改变 tab 参数会卸载并重新挂载 Grades，而学业快照存在组件内 `extra` state。位置：`web/src/main.tsx:304`、`web/src/academic.tsx:706`、`web/src/academic.tsx:754`。与 `web/README.md` 中“切换栏目保留本次查询结果”的说明不一致。

修改：避免栏目切换卸载页面，或将辅助快照提升到账号及学期范围的状态容器；同时保留退出清理和账号隔离。证据：`requirements-before.png`、诊断失败截图和 JSON 结果。

### 4. P1：旧 AI 历史请求能覆盖新会话

前置：登录合成测试账号，历史会话响应延迟。操作：点击历史会话，在响应到达前点击“新建会话”，随后放行旧响应。预期：新会话保持清空状态。实际：旧回答出现在新会话页面。

原因：历史读取使用直接 fetch；响应提交没有绑定当前会话代次，也没有在新建时取消该读取。位置：`web/src/ai.tsx:92`、`web/src/ai.tsx:109`。

修改：历史加载与新建操作共用请求取消或代次校验，只有仍属于当前会话的响应才能更新状态。此处实际复现的是“历史读取 → 新建”的竞态，未据此宣称已复现跨账号泄露。证据：诊断用例“新建会话后旧历史请求不能覆盖新会话”。

### 5. P1：手机隐藏 AI 会话侧栏后，没有替代操作入口

前置：手机宽度。操作：打开 AI。预期：可新建会话，并在登录后访问历史。实际：`.ai-side` 被整体隐藏；“新建会话”在手机不可见，历史区域也一同消失。

位置：`web/src/ai.tsx:87`、`web/src/prototype.css:4828`。修改：在手机页头保留新建按钮，历史会话改为抽屉或弹层。证据：内置浏览器 visibility 检查、诊断用例“手机 AI 应能开始新会话”。历史入口消失由侧栏整体隐藏及 DOM 结构确认，未测试真实账号历史查询。

### 6. P1：深色主题选中态和部分链接过暗

前置：食堂页切换深色主题。预期：当前导航、选中页签和动作链接清晰可读。实际：“食堂与菜品”“食堂主页”“查看全部店铺”使用偏暗的青绿色，在深色背景上难以辨认。

实测导航选中文字为 `rgb(14,98,91)`；最终深色 token 没有覆盖浅色的 `--brand-strong: #0e625b`。位置：`web/src/styles.css:1185`、`web/src/styles.css:1202`、`web/src/styles.css:473`。

修改：为深色主题提供单独的品牌前景色、选中背景和焦点颜色，逐项核对导航、页签、链接和输入焦点。证据：`canteen-dark.jpg`。本次未计算全页面 WCAG 合规分数。

### 7. P2：手机关闭导航后，Tab 仍能进入屏幕外链接

前置：390px 宽度，导航关闭。操作：从顶部登录或账号按钮按 Tab。预期：焦点进入当前可见内容。实际：焦点进入 `.sidebar:not(.open)` 内的“校园工作台”，其横坐标在屏幕外。

位置：`web/src/main.tsx:276`、`web/src/prototype.css:4535`。修改：关闭抽屉时使其内容不可聚焦，打开时管理焦点范围，关闭时归还焦点；同时兼容桌面常驻导航。证据：内置浏览器焦点矩形、诊断用例“手机关闭导航后键盘不能进入屏幕外链接”。

### 8. P2：320px 宽度下顶部登录按钮被裁切

操作：在 320×740 打开首页。实际：菜单、品牌、搜索和右侧操作的总宽度超过容器；右侧登录按钮被切掉。实测顶部内部宽约 310px、scrollWidth 339px。

位置：`web/src/main.tsx:210`、`web/src/styles.css:1001`。修改：保留账号、菜单等必要动作，将次要动作移入更多菜单；验证 320、360、390px 及放大文字。证据：`dashboard-320.jpg`。

### 9. P2：集市默认“最新发布”显示与实际排序不一致

前置：直接打开 `/web/market`，没有 sort 参数。实际：下拉框显示“最新发布”，代码默认请求 `sort=all`；真实列表日期并非降序。手动切换其他排序再选择最新后，URL 变为 `sort=time&page=1`，列表按发布时间降序排列。

位置：`web/src/community.tsx:266`、`web/src/community.tsx:346`。修改：市场页默认使用 `time`，社区页保留自己的默认排序；让 URL、下拉选项和接口参数始终一致。证据：默认页 DOM、`market-sort-time.jpg`、源码和实际排序切换。

### 10. P2：食堂空数据状态有多块无解释的空白

前置：合法空列表响应。实际：综合推荐有空状态，但“今日热门”只剩大空卡片，“今天吃什么”只剩标题，“最新点评”只剩标题和空容器。

位置：`web/src/canteen-page.tsx:20`。修改：分别显示短空状态和下一步动作，或在整体无数据时合并为一个紧凑引导；不要保留无内容的固定高度容器。证据：`canteen-empty.jpg`。

## UI 与展示效果的调整顺序

先修上述功能和渲染问题，然后在当前暖白底、青绿品牌色的基础上收敛视觉。

1. **首页提高内容密度。** 未连接教务时展示紧凑连接提示；今日课程数量显示“未连接”或破折号，避免把尚未读取的数据表达为零。连接后再展示真实下一节课。缩减日程卡和六个快捷入口的总高度，让校园动态在首屏有更多内容。
2. **卡片层级减到一层。** 降低普通快捷按钮和列表卡片的阴影，优先用留白与细边框区分；空状态无需在卡片内再画一层卡片。日程卡左侧渐变条和多处装饰性渐变可减少。
3. **集市采用独立图片区和信息区。** 图片比例统一，信息区保证标题、价格、状态、作者与时间的对齐和可读性，不能依赖照片底色。
4. **手机按任务调整结构。** AI 保留宽输入框和会话操作；课表考虑增加按日视图或定位今天，横向周表保留为可选视图，并说明左右滑动。不要只缩小桌面布局。
5. **语义色及字体按主题分别校验。** 品牌色与错误、成功、警告分开；提高小字号元信息的可读性。主要动作、次要动作和普通链接形成明确层级。
6. **整理 CSS 权威入口。** `prototype.css` 与 `styles.css` 中存在多轮同名 token、媒体查询和皮肤覆盖；后续修复宜将生效 token、基础组件及响应式规则收敛到明确入口，避免继续追加整套皮肤。本次没有重写样式表。

Hallmark 视觉审查仅作为辅助判断：Card-in-card（major，食堂空状态）、装饰性侧条（major，首页日程卡）、重复阴影及图标卡层级（major，快捷入口）、语义不明的零值统计（minor，未连接主页）、小字号弱层级（minor，元信息）。视觉项共 **0 critical · 3 major · 2 minor**；这些是改进建议，不替代上面的功能缺陷优先级，也不要求更换项目品牌。
