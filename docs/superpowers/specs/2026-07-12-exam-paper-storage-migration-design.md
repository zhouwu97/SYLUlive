# 试卷库大流量文件服务迁移设计

## 1. 背景与目标

当前试卷 PDF 由主服务器接收、校验、保存并回传。主服务器同时承担账号、数据库、审核和其他业务，月流量有限，无法承载试卷库增长后的上传和下载流量。

目标是把试卷 PDF 的上传、预览、下载和文件清理迁移到专用大流量服务器，同时保持主服务器继续负责用户、数据库、审核、奖励和下载计数。

已确认约束：

- 主服务器域名为 `couqie.ccwu.cc`。
- 文件服务器使用 `paper.couqie.ccwu.cc`，指向 `139.196.148.174`。
- 大流量服务器为 Ubuntu 24.04，约 35 GiB 可用磁盘、1.6 GiB 内存。
- 允许要求用户升级到新版客户端。
- 现有试卷记录、投稿人、审核状态和下载次数必须保留。
- 现有 2 份 PDF 需要迁移并进行 SHA-256 校验。

本设计不记录或提交任何服务器密码。部署前应轮换已在聊天中暴露的密码，并优先改用 SSH 密钥。

## 2. 方案选择

采用独立 Go 文件服务方案。主服务器签发短时凭证，客户端直接连接 `paper.couqie.ccwu.cc` 上传或下载 PDF。

未采用以下方案：

- 目录挂载：文件虽然存到大服务器，但 PDF 流量仍经过主服务器。
- MinIO：可实现预签名 URL，但在当前文件规模和内存条件下会引入额外组件与运维复杂度。

## 3. 架构与职责

### 3.1 主服务器

主服务器继续负责：

- 用户登录、权限和教务认证
- 试卷元数据、审核、奖励和下载计数
- 创建上传会话并签发短时上传/下载凭证
- 验证存储回执并写入试卷数据库记录
- 写入远端文件清理任务并重试

主服务器不再接收或回传新版客户端的 PDF 文件体。

### 3.2 大流量文件服务器

大流量服务器负责：

- 流式接收 PDF 上传
- 校验扩展名、文件头、PDF 结构、加密状态和 20 MiB 大小限制
- 以随机文件 key 保存 PDF
- 校验下载、预览和内部清理凭证
- 在本机完成文件发送和垃圾文件清理

服务以非 root 用户运行，文件目录不放在 Nginx 公共静态目录中。

### 3.3 文件后端抽象

`ExamPaper` 增加内部字段 `storage_backend`：

- `local`：主服务器旧文件或过渡期本地文件
- `remote`：大流量文件服务器上的文件

`file_key` 继续保存随机私有 key，不在 API 响应中暴露。文件服务通过接口抽象本地和远端操作，迁移期间两种后端可并存。

## 4. API 与数据流

### 4.1 上传

新增主服务器接口：

- `POST /api/exam-papers/upload-sessions`
- `POST /api/exam-papers/upload-sessions/:id/complete`

流程：

1. 客户端向主服务器提交课程元数据和文件大小，主服务器校验登录、教务认证、隐私确认、上传频率和大小限制。
2. 主服务器创建一次性上传会话，返回 `session_id`、大服务器上传地址和短时凭证。
3. 客户端直接向大服务器流式上传 PDF。
4. 大服务器验证 PDF，保存随机 key，返回包含 key、大小、SHA-256 和会话 ID 的签名回执。
5. 客户端把回执提交给主服务器。
6. 主服务器验证回执和会话归属，在数据库事务中创建 `pending` 试卷并把 `storage_backend` 设为 `remote`。
7. 重复 SHA-256、会话过期或回执错误时，不创建试卷，并写入远端清理任务。

文件服务不信任客户端提供的课程、投稿人或审核字段，只接受主服务器会话中的元数据。

### 4.2 预览与下载

保留主服务器现有路径：

- `GET /api/exam-papers/:id/preview`
- `GET /api/exam-papers/:id/download`

主服务器检查登录、发布状态和文件后端：

- `local`：继续使用本地文件服务。
- `remote`：签发大服务器短时签名地址并返回 `302` 跳转。

下载签发时原子增加下载量，预览不增加下载量。大服务器验证签名后发送文件。签名地址绑定文件 key、操作类型、过期时间和随机数，有效期建议为 2 分钟。

### 4.3 删除、撤回和下架

主服务器在数据库事务中写入文件清理任务，不在事务内等待远端 HTTP 请求。后台任务调用大服务器内部接口，操作必须幂等：

- 首次删除把文件移入 `.trash`。
- 数据库状态已经提交后，任务再执行物理清理。
- 网络失败会自动重试。
- `.trash` 文件保留 7 天后再永久删除。

### 4.4 错误约定

统一返回以下错误码：

- `upload_session_expired`
- `upload_receipt_invalid`
- `storage_signature_invalid`
- `storage_unavailable`
- `storage_capacity_low`
- `client_upgrade_required`

大服务器不可用时，主服务器的列表、详情、审核等非文件功能继续可用。

## 5. 鉴权与安全

使用主服务器和文件服务器之间的专用存储签名密钥，凭证采用 HMAC-SHA256，包含：

- `purpose`：上传、下载、预览或内部删除
- `session_id` 或 `file_key`
- 用户/试卷标识
- HTTP 方法和路径
- `iat`、`exp` 和随机 `jti`

文件服务器不保存主服务器 JWT 密钥和数据库密码。上传凭证建议 10 分钟有效，预览/下载凭证建议 2 分钟有效。

上传安全要求：

- 最大 PDF 大小为 20 MiB，multipart 额外空间单独限制。
- 检查 `.pdf` 扩展名、`%PDF-` 文件头和 pdfcpu 结构校验。
- 拒绝加密 PDF。
- 临时文件验证成功后原子改名，文件名使用随机 UUID。
- 文件目录权限为 `0700`，文件权限为 `0600`。
- 不允许目录浏览、路径穿越或直接按任意 key 读取。
- 响应设置 `Cache-Control: private, no-store`，Cloudflare 对试卷路径禁用缓存。

网络与运行要求：

- Cloudflare 为 `paper.couqie.ccwu.cc` 提供 TLS 和代理，Nginx 只开放 HTTPS 文件服务。
- UFW 只开放 `22`、`80`、`443`；SSH 完成密钥配置后关闭 root 密码登录。
- 文件服务和 Nginx 工作进程使用专用非 root 用户；Nginx 通过同一专用用户读取 `0600` 文件并执行内部文件发送。
- 大服务器增加约 2 GiB Swap，并限制 PDF 校验并发数。

## 6. 数据模型与后台任务

新增上传会话表，至少包含：

- `id`
- `submitter_id`
- 规范化课程元数据
- `expected_size`
- `status`：`open`、`completed`、`expired`、`failed`
- `storage_key`、`size`、`sha256`
- `expires_at`、`completed_at`

新增文件清理任务表，至少包含：

- `id`
- `storage_backend`
- `file_key`
- `operation`
- `attempts`、`next_attempt_at`
- `completed_at`、`last_error`

任务消费者必须支持重复执行，不因网络重试产生重复奖励、重复删除或错误状态。

## 7. 部署与迁移

大服务器目录建议：

- `/opt/sylg-paper-storage/bin/paper-storage`
- `/opt/sylg-paper-storage/data/exam-papers`
- `/opt/sylg-paper-storage/data/exam-papers/.trash`
- `/etc/sylg-paper-storage.env`

部署顺序：

1. 安装 Go 运行时依赖、Nginx、Certbot 或 Cloudflare Origin 证书、UFW 和 Swap。
2. 创建专用服务用户及 `0700` 数据目录。
3. 部署文件服务和 systemd 单元，先只开放健康检查。
4. 创建 `paper.couqie.ccwu.cc` DNS 记录并验证 HTTPS。
5. 部署主服务器双后端代码，保持旧记录 `local`。
6. 复制现有 2 份 PDF 到大服务器，逐个比较源文件与目标文件的大小和 SHA-256。
7. 校验通过后，把对应数据库记录更新为 `remote`。
8. 发布新版客户端并启用上传会话直传。
9. 旧版 multipart 上传接口返回 `426` 和 `client_upgrade_required`，下载接口仍可跳转到远端。
10. 本地旧文件只读保留 7 天，确认稳定后再清理。

回滚方式：通过配置开关暂停新远端上传；由于 `storage_backend` 按记录保存，本地和远端文件可同时服务，不需要重新解释 `file_key`。

## 8. 监控、备份与容量

- 磁盘使用率 70% 告警、85% 禁止新上传、95% 进入只读保护。
- 每日核对数据库引用的 key、远端文件存在性和 SHA-256。
- 定时清理过期上传会话和超过 7 天的 `.trash` 文件。
- systemd 日志启用轮转，记录上传、删除、验签失败和存储容量错误。
- 建议开启云厂商磁盘快照，每日一次、保留至少 7 天。
- 当前约 35 GiB 可用空间，按每份 20 MiB 估算可保存约 1700 份最大体积文件。

## 9. 测试与验收

### 9.1 自动化测试

- 上传、预览、下载签名的生成、过期、篡改和操作类型隔离。
- 路径穿越、伪造 key、重复提交、重复删除和幂等重试。
- PDF 扩展名、文件头、结构、加密、大小和并发限制。
- 上传会话归属、一次性完成和重复完成。
- 存储回执伪造、错误 SHA-256 和重复文件。
- `local` 与 `remote` 两种后端的读取、删除和迁移。
- 下载签发只增加一次下载量，预览不增加。
- Flutter 客户端直传、进度、过期凭证、失败重试和下载跳转。
- Docker/Nginx/systemd/目录权限和上传大小配置检查。

### 9.2 上线验收

- 新版客户端上传时，主服务器不接收 PDF 请求体。
- 预览和下载的 PDF 响应来自 `paper.couqie.ccwu.cc`。
- 两份历史试卷的业务记录和 SHA-256 完全不变。
- 过期、篡改和未登录请求无法获取有效文件。
- 远端不能列出目录或按任意 key 访问文件。
- 旧版上传快速返回升级提示。
- 大服务器短暂不可用时，主服务器其他业务仍可使用。
- 测试、迁移校验和生产冒烟检查全部通过后才完成切换。
