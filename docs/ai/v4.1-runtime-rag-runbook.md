# v4.1 P1/P2 运行与回滚手册

## 已部署组件

- Go 服务负责认证后的 AI Run 状态机、幂等、SSE 事件回放、取消、滚动配额、预算结算和审计哈希。
- `python-rag-service` 只监听回环地址，使用独立 systemd 用户和内部 Token，负责文档解析、中文分词、FastEmbed 向量和批量 embedding。
- PostgreSQL 使用 `vector` 与 `pg_trgm`，知识分块固定 1536 维；检索采用向量、全文和 trigram 三路 RRF，任一路不可用时降级并记录计量。

## 发布顺序

1. 先做 custom-format 全量备份，并校验文件大小和 SHA-256。
2. 依次执行 `server/sql/20260719_ai_runtime_rag.sql`、`server/sql/20260719_ai_privacy_quota.sql`。
3. 启动或替换 RAG 服务，确认 `GET /health` 返回 `status=ok`，未带内部 Token 的请求返回 401。
4. 替换 Go 二进制；启动时只读校验 AI 表、扩展、索引和配额账本无 Run 外键。
5. 通过认证用户检查 `/api/ai/capabilities`，再用测试知识文档完成导入、检查、索引、发布、问答、SSE 回放和撤销。

知识文档只有在 `inspect -> indexing -> indexed -> publish` 后才进入检索。重建索引失败时保留旧的 published 分块；新版本未完成前不会让旧内容失效。

## 回滚

Go 服务回滚只需停止服务、恢复上一个二进制、启动并检查 `/health`。RAG 服务和数据库迁移不随 Go 二进制回滚；若必须回滚数据库，先停止写入，再使用备份恢复到独立实例并切换连接串，禁止在线删除生产表。

## 运行检查

```bash
systemctl is-active shenliyuan shenliyuan-rag
curl --fail http://127.0.0.1:8080/health
curl --fail http://127.0.0.1:18001/health
journalctl -u shenliyuan --since "10 minutes ago" --no-pager
```

不要在日志、健康响应、客户端请求或事件 payload 中输出 DeepSeek/RAG Token、原始问题、完整提示词或完整工具结果。删除 AI 会话会删除正文、事件、工具调用和 usage 明细，但会匿名化保留已消耗的配额账本记录，避免通过删会话绕过小时限额。

## P3 门禁

课表 Skill 当前默认关闭。只有在校历 schema v2、唯一 `edu_semester_code`、人工审核的 `class_period_profiles` 和完整异常日覆盖均满足后，才允许在配置中启用；v1 校历必须稳定返回 `data_unavailable`，不得猜测节次或日期。
