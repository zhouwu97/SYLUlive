# AstrBot 多用户授权与默认权限

当前插件统一使用 0.4.1 多用户实现。旧 owner 的安装 ID、凭据身份哈希和安全凭据库不迁移；其他发起人由 `Accounts` 按服务 origin、平台配置、机器人 ID 与发送者建立独立随机安装 ID 和凭据槽。插件数据目录只保存安装 ID，Token 留在系统安全凭据库；缺少安全后端时仅进程内保存。不修改服务端已有 scope。

## 默认规则

| 入口 | 默认允许条件 | 额外条件 |
| --- | --- | --- |
| 私聊绑定、连接状态 | 当前 QQ 平台，开启多人功能；旧 owner 与原生管理员兼容 | 绑定仍须用户自行在官网确认；只选择发起人凭据 |
| 私聊解绑 | 当前平台的本人请求 | 仅撤销本人；服务端失败保留本地状态供重试 |
| 群内绑定、状态、解绑 | 群名单内且开启 `allow_group_binding` | 独立允许／禁止规则可覆盖默认，凭据仍按发起人隔离 |
| 本人签到／状态 | 多人私聊或群名单内 | `allow_checkin`、本人 `checkin:write` 和服务端资格全部满足 |
| 成绩、二课和草稿 | 私聊或显式允许的群规则 | 独立总开关、本人 scope；社区人格模式继续关闭这些入口 |
| 后台 Agent 管理、创建者长期记忆 | 配置的创建者本人私聊 | 普通成员的账号权限不能取得此身份 |

`access_default=inherit` 使用上表兼容默认；`deny` 只接受显式允许。显式禁止优先于任何允许和管理员角色。`public_read_all_sessions` 只扩大匿名查询，不能扩大群账号操作默认范围。AstrBot 自身的接收白名单、平台路由与唤醒条件在插件之前生效。

社区人格的账号命令门禁与创建者记忆身份分开判断：多人绑定、状态、解绑与签到可用，不把其他用户或群当创建者。群模型没有签到提交工具；个人签到状态只可由群发起人通过确定命令查询。

## 提醒和恢复

绑定请求按服务端至少 5 秒间隔轮询，遵守 `slow_down`，最长 10 分钟。成功、拒绝、超时各有不同提示；超时只表示尚未确认，不能假报已撤销。请求和授权代次、当前权限在通知前复核。每个客户端最多一个任务，全实例最多 512 项；重载终止等待，不承诺离线补发，用户可 `/sylu-status` 核实。

群内签到结果 @ 原发起人，显示日期、连续天数、本次奖励，不显示学号、用户数据库 ID 或总经验。无绑定、无 scope、权限禁止和网络不确定分别提示下一步。绑定成功不代表签到授权成功；需要新增 scope 时由本人先解绑、重连并在官网勾选。没有新增每日定时提醒或自动代签。

## 群发起与链接转发风险

`binding_link_delivery=auto` 先私发，未获确认时可把同一临时链接展示到原群；`private` 不回退群；`group` 直接展示并标注发起 QQ。临时链接不含设备秘密或访问令牌，但看见链接的其他人可能在官网登录自己的账号并批准。因此发起人必须核对设备代码、QQ 和校园账号，不转发链接；误绑由原 QQ `/sylu-disconnect` 取消后重新申请，不能靠输入另一人的 QQ 改绑目标。

成功通知沿本次实际投递渠道，只通知原发起人；群通知只 @ 此人。投递超时不自动重发、不转发其他群。群内已经公开的结果可能保存在 QQ、AstrBot 和模型侧，不能通过插件清理逆向收回。

## 升级与回退

使用仓库打包脚本生成完整 ZIP，不能只复制 `main.py` 而漏掉账号、权限、投递、通知和确认模块。升级前备份原插件源码、配置和本机安装 ID，凭据按系统安全库机制备份；配置保留，不清空旧账号。重载会使待确认分享和授权通知失效，用户可查询状态或重新申请。

回退恢复升级前源码与配置，不清安全凭据库、不删已有安装 ID、不改线上 scope。Go/Web 服务端发布另走正式部署入口；本机插件升级不代表生产服务已发布。
