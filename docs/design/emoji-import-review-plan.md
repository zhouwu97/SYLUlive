# 表情包导入与投稿审核方案

状态：初版实施记录。后续创作者权限、免费商城、缩略图及版本发布以 [当前实施方案](emoji-creator-store-plan.md) 和 [ADR-003](adr/003-free-emoji-store-and-creator-access.md) 为准；以下保留初版本机导入与投稿的设计背景。本文件不授权部署、生产迁移或生产开关调整。

## 用户流程

表情管理 → 添加 → 从相册选择 / 导入 ZIP 或 sylupack / 浏览表情库。图片和普通图片 ZIP 自动生成资源清单；导入前预览并命名，确认后安装到当前账号的本机目录。相同内容重复导入复用原安装；包内自称 official 不产生官方身份。导入本机无需公开审核。

表情管理 → 我的投稿 → 选择本地表情包 → 编辑名称、说明并确认分享权限 → 上传 → 待审核。管理员在现有管理中心预览全部资源后通过或填写原因驳回；通过后进入表情库，下架及用户撤回立即阻断后续公开访问。用户可看到状态和原因。已安装副本和既有消息引用按原资源契约保留。

## 状态与边界

| 入口 | 必须处理的状态 |
| --- | --- |
| 导入 | 空、选择取消、权限拒绝、读取/校验中、预览、名称无效、损坏/超限、安装中、失败重试、成功、重复、账号切换、离页 |
| 投稿 | 未登录、空、加载/失败/重试、上传进度、重复请求、取消、待审核、已上架、已驳回、已下架、已撤回、账号/会话切换 |
| 审核 | 非管理员、加载/空/失败/重试、预览失败、必填原因、处理中、过期状态冲突、权限撤销、下架 |

## 服务端约束

- 新增投稿及资源表，不改旧收藏、消息、内嵌官方包协议。目录兼容新增审核通过的社区包，使用服务端生成的独立 ID、不可变 v1 和规范化 Manifest Hash；不信任客户端路径、MIME、Hash、角色或状态。
- 上传最多 100 张、单张 10 MiB、请求体 50 MiB；限制尺寸、GIF 帧数及累计解码像素后再解码，规范化保存 PNG/JPEG/GIF。用户同时最多 5 份待审核，服务端事务锁定用户行并校验账号空间。
- 投稿使用账号内唯一的幂等键，并校验内容摘要；审核/撤回使用事务与状态条件防止并发覆盖。权限由现有认证/管理员中间件和 handler 的归属/角色检查共同约束；禁止审核自己投稿。
- 文件放在现有持久上传卷内的独立私有子目录，不写普通 `files` 公开记录。仅专用授权 API 读取，禁止新增 Nginx 静态目录。待审/驳回/下架仅作者和管理员可预览，公开路由只返回 published。
- 撤回释放资源，保留投稿状态和审核操作日志；上传失败回收 staging。崩溃孤儿目录采用服务端受控清理，不扫描或删除既有上传资源。
- 所有异步客户端请求绑定账号和 session epoch；切号后取消并隐藏旧预览。旧账号的本地安装始终只写原账号目录。

## 验证与发布

定向导入安全/幂等/恢复测试，投稿→审核→目录→下载的隔离 API 测试，以及普通用户/他人/管理员/撤权/并发冲突反例。Flutter 覆盖 loading/empty/error/retry、取消、切号、明暗主题、360px、1.3× 和 1.5× 字号及真实渲染；Windows 证据不更新 Linux canonical Golden。

新表通过现有启动 AutoMigrate 增加，重复启动不改旧表数据。发布顺序：服务端及私有目录授权验收 → 新客户端 → 人工验收放行。责任人为当前仓库维护者；发布须另行明确批准并记录不可变提交及构建物。

回退客户端仅隐藏新入口；回退服务端前必须阻断新投稿/社区包路由，保留新表与私有目录，使用上一稳定二进制恢复旧官方表情/收藏。不得通过删除投稿或迁移回滚抹掉审核记录。
