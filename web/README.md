# 沈理校园 Web 与教务助手

React + TypeScript + Vite，复用 Go API；Web 当前视觉入口为 [design.md](design.md) 与 [tokens.css](tokens.css)，桌面沿用用户提供的 v3.2 亮蓝品牌与三栏结构，并按后续要求通过组件外框、内部细分隔线和任务分组建立层次，首页与社区使用独立描边帖子卡片，公共帖子沿用服务端置顶数据。760px 以内的手机 Web 对照实际 Android App，由 `src/mobile-app.css` 与手机组件还原暖白／青绿配色、五项底栏及各主入口。历史结构参考保留在 `web/reference/prototype-v3.html`。当前产物用于开发联调，尚未满足完整方案的最终验收门槛。

## 运行

在仓库根目录执行：

```powershell
pnpm install
pnpm dev
```

访问 `http://127.0.0.1:5173/web/`。默认代理仓库中的 `https://sylulive.online`，会访问真实业务服务。需要本地 Go 服务时先设置 `$env:SYLULIVE_API_ORIGIN='http://127.0.0.1:8080'`，再启动。Go 启动沿用服务端原有环境配置，不把生产密钥复制到前端。

浏览本地页面期间保持 `pnpm dev` 运行；测试临时启动的开发服务会在测试结束时退出，不能代替日常开发进程。网络连接失败时，社区、集市和其他读取页显示中文说明与重试入口；重试保留当前搜索和筛选，不将故障当作空数据。

## 登录与本机账号记录

登录面板提供账号选择、密码显隐、注册和找回密码。按表单选择在当前浏览器保留最近 5 个成功登录账号，邮箱大小写和首尾空格统一去重；密码须额外勾选「记住密码」，默认不保存。重新打开时可回填最近账号，历史账号中可逐条移除或清空。取消记住密码会移除该记录的保存密码，退出登录保留此前已选择保存的记录。

记录位于本站 origin 的 IndexedDB `sylulive-login`。密码以 AES-GCM 密文与不可导出 CryptoKey 保存，不写入 localStorage／sessionStorage；不保存会话 Token，不同步到服务器。这是浏览器本机保存，不是操作系统凭据库，仍受同源脚本安全边界约束。清理可使用面板操作，或清除站点数据并刷新。本站密码与教务助手保存的学校密码分开管理。

存储不可用、配额不足或密码无法解密时可继续手动登录，不降级保存明文。修改本站密码或通过邮箱重置成功后清理能匹配到的旧保存密码，账号历史保留；清理失败会明确提示。历史记录移除优先于在途写回。验收入口为 `e2e/login-history.spec.ts` 与 `src/login-history.test.ts`，所有认证写入测试使用合成账号和本地接口夹具。

## AstrBot 授权、机器人与草稿确认

机器人后台运行区通过本人 `/api/connected-apps/bot/runtime` 每30秒独立核验，显示离线／暂停／缺授权／运行／失败、最近浏览和服务端成功发言；失败保留表单草稿并将状态降为未知。后台任务属于常驻 AstrBot，不以网页开关推断正在执行；多账号运行与新版接口依赖见插件及运维入口。

机器人管理表单可新建暂停账号、编辑名字和本人上传的公开头像、保存公共阅读／自动文字评论／内置表情／自动发帖／公开配图权限、板块白名单、屏蔽词、禁链接及更严限频。创建与启用分开，保存后由服务端执行；独立连接scope及平台总开关仍须满足。发帖和配图默认关闭，旧评论选择不扩大权限；文字评论与发帖分别展示服务开关和授权结果。App 提供同等权限设置与原生设备授权入口，两端共用数据。社区作者旁显示服务端确认的创建者公开归属；无接口或旧服务不显示虚假成功。契约见 [API](../server/API.md) 与 [插件说明](../astrbot_plugin_sylulive/README.md#社区机器人账号管理)。

「已授权助手」同时提供一人一个独立 AI 机器人的创建、命名、启用和暂停。页面分别显示服务端自动评论开关与专用授权，启用账号不代表 AstrBot 后台运行。自动评论 scope 默认不选，须本人在新连接中明确选择；不改旧授权。记忆只在本机 AstrBot 保存，群不进长期库，公共后台无法读取私聊记忆。

个人主页“已授权助手”进入 `/web/connected-apps`，核对设备代码、选择 scope、替换/撤销连接；`/web/connected-apps/actions/:id` 显示不可变草稿并由本人确认。提案权限默认不选，模型不能直接发布。近期登录失效时重新登录后再加载；token refresh 不延长近期认证。帖子来源或授权变化时，页面禁止发布并要求重读。

详见 [插件安装与本地配置](../astrbot_plugin_sylulive/README.md)。本地开发务必设置前述 `SYLULIVE_API_ORIGIN`，插件与 `INTEGRATION_PUBLIC_ORIGIN` 均指向本地网页 origin 5173。未启用后端新集成时，这些页面不会伪装成功。该入口不改变现有 Web/Flutter 校园 AI。

页面可预览并确认同步当前学期最小成绩和二课摘要，成功后仍需另行授权本人查询 scope。个人服务开关关闭、查询失败或旧服务时不可新增私有授权；删除只清对应同步副本，失败/退役不能报告已删除。切换账号或类型会取消旧预览确认，重复提交受控。App 原生授权同样将成绩、二课和发帖默认关闭，并根据当前服务端状态限制选择。反复验收入口见[完整测试清单](../docs/ai/astrbot-full-chain-test-checklist.md)，其中的跨运行时命令串联实际 Web、Go 与原生 AstrBot SDK，使用合成数据和确定性测试模型。

## 扩展安装与本机查询

```powershell
pnpm --filter @sylulive/extension dev
```

Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，目录为 `browser-extension/dist-dev`。生产域名使用 `browser-extension/dist`；生产包不注入 localhost。

维护者也可照常手工装载上面的目录；普通用户不必再自己找目录。页面检测不到教务助手时，连接弹窗与工具箱“教务连接诊断”会给出本站同源的安装包下载入口、SHA-256 校验值和自助安装步骤；用户在扩展管理页装载后，扩展会主动向已打开的站点标签页补注入握手脚本，页面自动复检并提示可以继续，不需要刷新。复检只确认通道建立，读取学校资料仍由用户点“连接并读取资料”触发。

该引导依赖 `web/public/assistant/`：本地 5173 用 `pnpm assistant:dev` 产出开发通道包，`pnpm build` 自动产出生产通道包。两个通道的授权域名不同，页面会拒绝在错误环境安装错误通道的包。已知限制：在扩展管理页把扩展由“停用”改为“启用”不会触发补注入，此时仍需刷新页面一次。

在网站登录后，进入课表或成绩的“连接教务助手”。点击“连接并读取资料”后，新助手在缺少权限或学校会话过期时自动打开登录助手。首次需在扩展页授权学校域名，并输入学号、教务密码；二课分别输入 WebVPN 统一认证密码和二课系统密码。勾选“授权在此浏览器保存凭据”后，仅在学校身份核对成功时保存。后续会话过期再连接时，自动填写、经学校原按钮登录，成功后自动返回原网页并继续拉取本次选择的资料。只打开页面或完成安装握手不会自动读取资料。

验证码、滑块、学校拒绝登录和未知页面保留学校页人工处理，每次尝试的每一步最多自动提交一次；密码有误时可在助手页点击“修改登录信息并重试”，在同一任务中修正后重新登录，原网页继续等待。等待最长五分钟，可在网页或助手页取消；关闭发起页面、切换账号或重新连接后旧任务不能回填。研究生保留手动学校登录后自动返回；体测沿用独立 HTTP 风险确认和原有手动返回流程。

网页在开始读取前核对本站会话，access Cookie 过期时通过既有同源刷新接口恢复；等待学校登录途中会话过期也继续原任务。账号发生变化则停止。身份绑定请求携带 `X-Expected-App-User`，由服务端核对预期本站账号。助手只向网页回报固定进度阶段；每 1.5 秒发送的扩展内部心跳仅确认绑定助手页存活，不访问学校或本站网络，也不新增 `tabs` 权限。每次注入凭据前和完成登录时均核对任务及本站账号。

正方页面会重写原生数组方法，学校页注入脚本使用 NodeList 遍历，避免依赖页面改写后的 `Array.some` / `Array.find`。注入异常时改为提示手动登录，该阶段不反复填写；测试同时覆盖原生数组方法被学校脚本替换的环境。

凭据只在扩展 IndexedDB 以 AES-GCM 密文和不可导出的浏览器密钥保存，按站点、本站账号和学校系统隔离，关闭再打开浏览器后仍可使用；这不是操作系统安全凭据库。助手页可清除已保存凭据，损坏密文也可清除恢复；网页“断开并清除当前资料”同时清除当前系统凭据，卸载扩展也会清除。退出本站会取消本人任务并清除连接、资料缓存及提醒，保留曾明确保存的凭据，供同一本站账号再次登录后使用。取消、学校网络故障和资料读取失败不覆盖旧凭据或旧资料。密码、原始响应和学校会话不交给网站；本科与研究生仅向 Go 提交现有接口要求的学校类型、学号和本机身份声明。

二课身份取自已登录系统的顶部栏 `top.aspx`，要求存在退出入口和唯一账号；成绩页不包含学号，不能用于身份识别。读取前后仍分别核对当前账号，顶部栏为空、登录过期或账号有歧义时保留原资料并要求重连，不读取完整个人档案来推测身份。更新已解压扩展的构建目录后，需要在浏览器扩展管理页重新加载，再回到网页重试读取。

个人资料默认保留在页面会话中。勾选“在此电脑保存”后，扩展 IndexedDB 才保存查询得到的结构化资料。课程提醒另行确认通知权限及本机保存，依赖浏览器运行；修改课表后需重新同步提醒。独立课程窗口不提供系统置顶。

## 认证链路的错误码与授权状态

扩展的回包 `error.code` 是可判定的分类，页面按分类给下一步动作，不再只丢一句文本：

| code | 含义 | 页面动作 |
| --- | --- | --- |
| `extension_unavailable` | 握手超时，本机没有助手 | 展示下载与自助安装步骤，自动复检 |
| `authorization_required` | 助手未获准访问该学校域名 | 提示打开助手页授权；次按钮变成“打开助手完成授权”，授权完成后免刷新自动恢复 |
| `school_login_required` | 学校登录过期或会话被踢 | 提示打开学校登录页后重试 |
| `site_login_required` | 站点账号已失效 | 先由同源网页尝试恢复会话；无法恢复时退回未连接，要求重新登录沈理校园 |
| `connection_stale` / `identity_changed` | 连接代次被接管或本机教务身份换了人 | 清空连接、退回第 2 步并提示重新连接 |
| `unsupported_query` / `invalid_argument` / `failed` | 该系统不提供该资料、参数无效、其他异常 | 原样展示消息 |

兼容性：`BridgeResponse.error.code` 仍是 `string`，`hello` 的 `connections`、`authorized`、`automaticLogin` 都是可选字段。旧扩展回的未知错误码按 `failed` 处理，读不到 `authorized` 时不为授权继续轮询。新助手 `connect` 可返回 `flowId`，网页仅对有此字段的任务使用新增 `loginStatus` 轮询；旧助手没有 `flowId` 时保留手动返回重试。旧页面仍可使用原来的连接命令。任务状态不包含凭据；扩展内部助手消息只接受绑定标签页的扩展页面，并再次核对本站账号和学校身份。

请求计数（本科、学校和本站会话均有效）：一次“连接并读取资料”= 网页本站会话预检 → `hello`（本地）→ `session`（站点 `account` + 学校身份页）→ 站点 `bind` → `query`（前置 `account`、前置身份核对、抓资料、后置身份核对、后置 `account`），共 9 次网络，其中 3 次抓的是同一个本科身份页。`hello` 会报告扩展已保有的连接代次和本机授权位（只读 `chrome.storage.session` 与 `chrome.permissions.contains`，不发任何网络请求），所以重开弹窗再点“查询并更新资料”需 6 次。过期会话另有刷新和登录等待请求；等待期间 `loginStatus` 每秒核对本站账号，助手每十秒及各注入/完成边界另行核对。`query` 内部的前后置核对一次都没有减少，账号被切换仍能在写入前检出。

课表拉取：默认学年学期由 `defaultAcademicTerm()` 按月份推导（正方以秋季起算学年，春季学期归属上一学年，直接取日历年份会在 2–8 月拉到上一学期）；JSON 接口返回登录页时按“重新登录”提示，返回坏数据时提示原资料已保留。学校对某学期返回空列表且本机已有非空课表或成绩时，页面拒绝替换，弹窗保持打开并说明原因，扩展侧仍照常记录快照。

明确未做的优化：身份结果的同代次 TTL 复用、成绩分页并发抓取、用课表响应自带的学号代替独立身份复核。

## 构建、测试与打包

```powershell
pnpm check
pnpm test
pnpm build
pnpm --filter @sylulive/extension dev
pnpm exec playwright install chromium
pnpm test:e2e
pnpm package
cd server
go test ./internal/handlers ./internal/middleware ./internal/ai
```

`artifacts/web-build/` 包含静态网站、生产扩展、开发扩展及 Windows 下生成的 ZIP。包为联调候选包，不表示学校链路或商店审核通过。扩展发布前还需按实际商店补齐展示素材与隐私披露。

`pnpm package` 会额外写出 `artifacts/web-build/BUILD_INFO.json`：产出提交号、分支、工作树是否干净，以及三棵子树的确定性摘要和 ZIP 的 SHA-256。部署前用它核对「发布物就是待部署提交」：

```powershell
node scripts/package-web.mjs --check <待部署 SHA>   # 或设置 RELEASE_SHA
```

校验会同时比对提交号与磁盘内容摘要，任一不符即失败退出。工作区有未提交改动时打包默认拒绝，确需打实验包用 `ALLOW_DIRTY_RELEASE=1`，此时 `BUILD_INFO.json` 记录 `dirty: true`，不得作为发布物。

## 部署

将 `web/dist/` 内容放到现有站点 `/web/`。参考 `web/deploy/nginx.conf` 合并到原 HTTPS server；保留官网及分享路由，API 与附件使用同源代理，SSE 关闭缓冲。新增收藏和个人 AI 分析需要同时发布本仓库 Go 修改；仅更新静态页面不会让线上旧服务具备新接口。

发布后请确认 `/web/assistant/assistant.json` 真的以 JSON 返回（例如 `curl -I https://<站点>/web/assistant/assistant.json` 看 `content-type`）。`web/deploy/nginx.conf` 的 `try_files` 会把缺失文件伪装成 200 + `index.html`，此时页面只会提示“本站暂无可用的教务助手安装包”，不会显示下载按钮。

## 验收边界

已运行的自动化包括共享数据校验、解析与提醒计算、SSE 分帧、课表编辑及冲突、主要路由和移动导航，以及真实 Chromium 扩展加载和握手。Go 测试覆盖收藏、Origin 校验与个人 AI 授权/用量等边界。`web/e2e/assistant-install.spec.ts` 覆盖未装助手时的下载引导与安装步骤、装好后不刷新自动复检（并断言此间不发起学校查询）、以及安装包缺失或通道不符时的降级；`web/src/assistant-package.test.ts` 和 `browser-extension/src/inject.test.ts` 覆盖包清单校验与补注入的站点计划。

尚未完成真实账号的发布—审核—通知回读，以及本科、研究生、二课、体测四种学校来源的登录查询验收。Chrome/Edge 的重启、升级、多账号和系统通知还需实机验收。18 个页面的固定数据视觉对照也尚未全量完成，不能用路由冒烟代替。

教务助手引导交付的是解包（开发者模式）安装：真实 Edge 上“下载—解压—加载已解压扩展—页面免刷新复检”的完整链路、浏览器周期性提示或暂时停用非商店扩展的表现、以及更换解压目录导致扩展身份变化后本机资料需要重新读取，都只能人工验收。长期方案是发布到 Edge Add-ons 或 Chrome Web Store，目前尚未提交审核。

校园地图已复用 App 资源；食堂贡献列表、实拍、审核原因及评价编辑保留关联资料已接入；管理端已增加用户、版块、公告、版本、日志和 AI 指标入口。这些接口接入仍需真实账号验收，不能视为发布—审核—回读全链路已通过。

学业页已展示分模块学分要求、课程明细和本地缺口检查，切换栏目保留本次查询结果并标注来源及时间；毕业检查仅覆盖已返回的学分模块，不替代学校最终结论。

完整方案中仍需补齐的业务包括校园电话/办事指南、食堂治理细项、部分竞赛推荐与偏好、更完整的成绩详情及毕业条件覆盖等。当前已有页面及 API 接入不等于这些子流程全部完成。

学校凭据请只输入官网或助手页面。真实学校来源不可达、身份不具备对应能力或服务器拒绝时保留错误与旧数据，不以模拟响应确认完成。
