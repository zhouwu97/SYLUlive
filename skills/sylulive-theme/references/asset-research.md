# 素材侦察

目标：动手生成之前，拿到这个角色**全部**可用素材的原图，逐张看过，并整理成一份清单。后续每次生成都从这份清单里取参考图。

## 1. 找全来源

| 来源 | 做法 |
| --- | --- |
| 图集网站（如 GitHub Pages 画廊） | 用浏览器或 `curl` 读取页面，收集所有 `<img>`、`srcset` 和「原图」链接；页面有分区、分页或「加载更多」时，要逐个展开。优先取「原图」链接，不取 480 宽的缩略档 |
| 页面背后的仓库 | 页脚或页头通常链接源码仓库。读 README、`ATTRIBUTION.md`/`LICENSE` 和资产目录，用 `gh api repos/<owner>/<repo>/git/trees/HEAD?recursive=1` 列出全部图片路径，再从 `raw.githubusercontent.com` 下载 |
| 上游资产库 | 画廊注明的「主要来源」也要打开，常常还有表情包、设定图、Prompt 和 LoRA 说明 |
| 百科条目 | 萌娘百科等条目的「设定」「性格」「梗」段落是阶段 2 的文字依据 |
| B 站、Pixiv | 搜角色名加「设定」「三视图」「表情包」「立绘」，看原作者主页的同系列作品。只记录链接和作者，确认能取得原图再下载 |
| 用户给的图 | 全部用上；手机截图要先裁出插画，去掉界面 |

把找到的每个来源记录在 `research/inventory.md` 开头：网址、作者或维护者、许可、图片数量。

## 2. 下载

- 下载到 `refs/raw/<分类>/`，保留原文件名，前面加两位序号，方便和总览图对应。
- 数量很多时（例如社区二创有 200 张），全部下载缩略档（宽 960）用于浏览；被选为锚点或可能入包的图，再下载原图。
- 下载用 `curl -L --fail -o <path> <url>`，逐个执行或少量并发。失败的条目记录在清单里，不要静默跳过。

## 3. 逐张看完

在 `client/` 下用工具脚本为每个分类生成带编号的总览图（每张最多 48 格）：

```powershell
flutter test --no-pub --dart-define="TOOL=contact" --dart-define="IN=<WORK>/refs/raw/community" --dart-define="OUT=<WORK>/refs/contact-community.png" ../skills/sylulive-theme/scripts/asset_tools_test.dart
```

打开每张总览图，逐格看完。把值得放大看的编号记下来，然后打开原图细看。

## 4. 写清单

`research/inventory.md` 用一张表记录全部图片：

```text
| 编号 | 文件 | 分类 | 尺寸 | 作者／出处 | 看到了什么 | 用途 |
| 07 | refs/raw/sheets/01-chibi-sheet.png | 设定图 | 2048×1536 | TreapGoGo | Q 版三视图+细节拆解，鳍耳、呆毛、围裙小鲸鱼都清楚 | 身份锚点 A |
```

分类取值：设定图、代表立绘、表情包、Q 版、换装、场景、壁纸、其他角色同框、低质或不相关。

「用途」一列只能写下面这些：

- **身份锚点**：1–2 张。脸、发型、服装最清楚的设定图，每次生成都要带上。
- **表情库**：3–6 张。覆盖开心、得意、生气或傲娇、委屈、困倦、吃东西等表情。
- **动作参考**：能表达性格的姿势，供页头和贴纸构图参考。
- **可直接入包**：尺寸和比例达到画质门槛的原画，注明适合哪个槽位。
- **配色**：用来取色的那张图。
- **不用**：并注明原因（低清、画风偏离、非本角色形态等）。

清单末尾写三段结论：

1. 这个角色最有辨识度的 5 个视觉元素；
2. 社区里反复出现的梗和动作，这是「性格」最好的证据；
3. 缺什么：例如没有背面、没有坐姿、没有深色场景。这些就是阶段 4 需要新画的部分。
