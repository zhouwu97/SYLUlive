# 正式版更新与 Beta 下载通道契约

## 范围与决策

Android 提供 `stable` 正式版更新通道和独立的 `beta` 测试版下载通道。Beta 只是可选下载，不是当前应用的更新任务。本变更涉及公开接口及发布控制，按 R3 执行；部署与正式放行仍使用现有发布入口。

## 用户行为

- 正式版普通更新默认按用户现有 WLAN／后台下载偏好静默准备包体；排队、下载、校验、暂停及静默失败均不自动弹窗。用户关闭自动下载时保留发现提示和手动下载入口；外部市场交付继续提示跳转。
- 下载并校验完成后显示安装确认。此前关闭“发现更新”或查看下载进度不影响完成提醒；应用在后台时等恢复前台再提示。选择稍后安装后，本次运行同一正式版包不重复提醒，手动检查仍可安装；新版本重新判断。安装始终由用户点击触发。
- 自动提醒和手动检查共用正式版弹窗，显示版本、包体大小、本次更新说明以及真实下载状态。下载完成提供“稍后安装／立即安装”；强制更新提示不可通过返回或遮罩关闭。开始下载、打开安装程序或外部市场失败时保留弹窗，显示错误并允许重试。旧版本弹窗在目标发布变化时关闭，按新结果重新判断提醒。
- 从手动检查开始到结果窗口关闭，共用一次展示占用；连点、顶部提示和自动回调不叠加窗口。已打开的进度窗口直接显示下载完成或失败；只有实际展示过结果才记录延后，检查页提前离开不吞掉全局安装提醒。同一版本的强制策略改变时关闭旧窗口；检查失败保留最后一次成功确认的策略。
- 默认仅接收正式版。“设置 → 通知与后台 → 应用更新 → 接收 Beta 测试版通知”保存本机订阅偏好，不绑定账号。
- 开启后立即检查正式版更新并另查 Beta 下载信息。Beta 弹窗展示测试版标识、版本、包体大小、功能说明，以及“Beta 版提供更丰富的功能，但仍处于测试阶段，不建议小白用户下载，推荐继续使用正式版。”
- 主按钮“下载 Beta 版”打开包体下载链接；外部交付使用 `action_url`。下载由浏览器处理，不排队应用内下载、不校验本机下载进度、不触发安装器。打开链接成功只表示已打开链接；失败保留弹窗和重试入口。用户可选“暂不下载”或关闭。
- 关闭弹窗后，本次运行不重复提示同一通道、同一构建号。不同通道的相同构建号分别判断提醒。
- 关闭订阅清除 Beta 下载信息并关闭对应弹窗，旧请求的结果不能恢复 Beta 提示。正式版更新策略、包体下载和安装状态独立保留。
- 正式版强制更新和下载完成的安装确认优先于 Beta；普通正式包静默准备期间可独立展示 Beta 下载信息。手动检查优先正式版更新；正式版无更新时可展示 Beta 下载入口。查询失败分别显示错误，不将 Beta 查询失败解释为正式版更新失败。
- 检查由启动、前台恢复和现有前台定时检查触发，不增加系统推送。偏好与 Beta 提示状态不绑定账号。

## 服务端选择

1. `stable` 只查询本平台正式通道已发布版本。
2. `beta` 只返回本平台测试通道最高构建号的已发布记录，不与当前正式版构建号比较。相同或更低构建号的 Beta 仍可下载；没有已发布 Beta 时返回无可用下载，不回退正式版。
3. 为复用既有响应结构，已发布 Beta 使用 `update_available=true`、`update_type=optional` 表示存在下载入口；客户端将其存入独立的 `betaInfo`，不参与正式版更新判定或策略缓存。
4. 创建 Beta 时最低支持构建号规范化为 1，后续禁止提高；Beta 不能改变正式通道业务请求的最低支持策略。客户端始终另查 `stable`，业务 API 继续携带 `stable` 版本头；Beta 查询失败不覆盖正式版检查结果。
5. 更新接口返回 `channel` 表示目标通道；旧客户端可忽略，缺少该字段的旧响应由新客户端按 `stable` 解析。

## 发布、存储与撤回

- 只有超级管理员可上传、发布和下架；沿用原有权限、签名校验、草稿及审计流程。
- App 和 Web 发布表单提供通道选择。已有记录的通道不可修改；转正式版需要在正式通道创建并发布记录。
- APK 按 `android/<channel>/<version_code>/` 分目录保存，正式与测试记录不共用包体路径。既有正式版路径继续可读，不迁移历史文件或数据库。
- 包体去重按平台和通道执行，同一个已验收 APK 可分别在 Beta 和正式通道创建记录。
- Beta 下载入口不承诺与正式版共存或覆盖安装；安装兼容性由分发包的包名、签名和构建号决定。客户端不执行 Beta 安装。
- Beta 允许下架最后一个已发布版本；正式通道继续保留至少一个可用版本。已下载或已安装的包不因下架被远程删除。

## 验证与回退

定向检查覆盖发布／下架、通道隔离、正式最低支持策略、用户订阅、浏览器下载、关闭、错误重试及晚到响应。Flutter 查看浅色、深色、大字号真实渲染；App／Go 使用本机隔离 HTTP 链路验收，不请求生产。

先部署服务端，再发布包含订阅入口的客户端。需要停止测试分发时下架 Beta 记录；回退旧应用代码时保留已有记录和文件，旧版仍仅查询 `stable`。旧服务端不接受 `beta`，回退服务端前停止 Beta 分发，并记录新版客户端检查失败的兼容范围。正式发布仍需签名包和 Android 真机升级验收，具体步骤见[发布手册](../ops/app-release.md)。
