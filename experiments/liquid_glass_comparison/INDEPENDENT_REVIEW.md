## 阻断问题

### D1 · P2 · Web 系统减少动态未生效

**位置：** `lib/main.dart:128`、`:261`、`:388`、`:397`；相关状态处理为 `:138` 和 `:413`。现有测试 `test/comparison_test.dart:57` 只覆盖手动 chip。

**复现与实际：**

1. 在实际运行页面，通过当前标签页的 DevTools 媒体仿真把 `prefers-reduced-motion` 设为 `reduce`。
2. 读取公开浏览器状态 `matchMedia('(prefers-reduced-motion: reduce)').matches`，结果为 `true`。
3. 页面“播放慢拖与快甩”“保持按压”仍为可用，动效幅度仍可用。点击“保持按压”后，两侧镜片仍由静态选中态膨胀到按压态；工具截图及 AX 的“松开观察”状态与该 `true` 值同时成立。
4. 手动点击“减少动态”能立即清除膨胀并禁用播放／保持按压；此时方向键仍能即时切换选中项。因此手动路径正常，系统偏好接入缺失。

**原因：** 宿主只合并 `_reduced` 与 `MediaQuery.disableAnimationsOf(context)`。本次 Flutter 3.41.8 Web 实际运行中，浏览器媒体偏好没有传入该值。代码引用 MediaQuery 不能作为 Web 系统偏好已工作的证据。另外 `didChangeDependencies` 只赋值 `reduced`，没有统一停止已开始的 `_playback`、清理持有指针并 snap 回选中态；`_playFrame` 也不检查减少动态，不能把补上偏好监听视为完成了动态切换处理。

**影响：** 已请求减少动态的用户仍会看到装饰性膨胀和演示运动；这违反仓库 UI 动效验收要求。该缺陷在实验宿主中修复，不改写固定原版快照。

**修复标准：**

- 初始进入与运行中切换系统 Web 媒体偏好均生效；与手动开关、MediaQuery 合并为同一个有效状态。
- 生效时停止自动轨迹、清理 held／pointer 状态、停止弹簧并恢复静态选中反馈；恢复系统偏好后不自动重启旧演示或旧按压。
- 键盘和普通导航选择继续即时可用；只在当前宿主维护所需监听，并在 dispose 清理。
- 在已有 `comparison_test.dart` 补初始与活动中切换的行为回归；真实 Web 复测 `matchMedia=true → 按压／播放无形变 → 方向键可选中`。以浏览器偏好实测作为最终证据，不能只重复点击手动 chip。
- 同步更新验证记录，保留本次失败和修复后结果。

### A1 · P2 · 完整候选的轮廓与导航可读性不足以放行业务 App

**位置：** `shaders/refined_glass.frag:94`、`:97`、`:135`、`:154`、`:155`；导航前景参与重采样位于 `:116`、`:145`。对照宿主的原版按压模糊／染色位于 `lib/comparison_renderer.dart:142`、`:191`。

**证据与原因：** 浅色网格、浅色文字和彩色矩阵中，右侧按压镜片的暗圈和强高光消失后，边界显著弱于原版，颜色接近背景的区域只剩很细的折线或凹痕。彩色底上的蓝色选中图标也未获得稳定的背景分离。文字场景中，背景字形继续穿入导航并与标签相撞；候选降低遮蔽后保留了更多这些干扰。深色文字场景同样存在叠字。原版也有该问题，候选没有解决它。

这不是透明 alpha 错误，也不能根据“更通透”判定更适合导航。业务导航必须在真实背景上读得清，实验的文字和颜色底图恰好暴露了当前组合的限制。现有中灰测试衡量透射偏差，不衡量选中轮廓、文字辨识或对比度；本评审没有从 JPEG 伪造 WCAG 数值。

**修复／App 采用标准：** 保留稳定的选中区域辨识和可读前景，再评估去暗圈与方向反射的幅度。使用业务 App 自己的固定清透／磨砂语义、主题导航色和真实滚动内容，对浅色、深色、彩色、密集文字，以及静止、按住、快速反向、释放状态检查。浅色低纹理底和繁忙背景均须通过，不以颜色或高光减弱本身作为质量指标。主题包静态颜色门禁继续遵守 `docs/design/theme-pack-contract.md:396` 的导航前景 3.0 阈值，并另检查动态合成结果。

本项不要求为了发布研究 demo 隐藏负面对照结果；它阻断完整候选直接用于 App。

### A2 · P2 · demo 接口和材质语义不能直接覆盖 App

**位置：** demo `shaders/refined_glass.frag:7`、`:61`、`:65`、`:113` 和 `lib/comparison_renderer.dart:142`、`:191`；业务 `client/lib/widgets/liquid_glass/liquid_glass_renderer.dart:291`、`:344`、`:355`，业务 shader `client/shaders/liquid_glass.frag:29`、`:30`。

**原因：** demo 是横向五项、64 DIP 高的研究宿主，着色直接用黑／白；正式 App 支持纵向侧栏、主题 `navBackground`、导航图片及原色图标、字体／大字号、角标、关闭档与 fallback。业务 shader 在旧 uniform 之后还有 `uVertical` 与 `uNavBackground`；直接替换文件会丢失这些语义。demo 磨砂在按压后从 6 降到约 1.2，染色同步降低；业务代码明确固定材质，不随按压自动转清透。

**修复／采用标准：** 只把选定的光学计算移植到业务 shader 对应函数，保留业务 uniform、纵向坐标、主题背景色、图标／字体图集和原有交互／fallback。继续使用现有导航测试覆盖横纵向、35% 幅度、提交／取消、第二指针、重新抓取、键盘、语义和设置持久化，再在实际目标 App 上验证 GPU 渲染。不能把 demo 的原版磨砂表现当作业务材质验收结果。

本项是迁移门禁，不是要求本次修改业务代码；`COMPARISON.md` 已正确承认该边界。

## 公平性与完整视觉比较

默认“只改光学”的公平性成立：`main.dart:502` 同一 `LensPose` 传给两侧，共享背景枚举、明暗、pointer、尺寸及 blur/tint 输入。`comparison_renderer.dart:176` 的 scale、lens center/height 在两侧相同；`:184` 只有同时满足候选且打开“光学＋形变”时才改 width。数值梯度距离校正会改变抗锯齿和光学带宽，但不改变场的零等值轮廓；不能把这些光学变化误写成另一套几何参数。

两侧都由同一实验宿主绘制，左侧不是上游完整页面的逐像素复刻。48 DIP 绘制余量、场景裁切、固定示例图集和未启用 highContrast／textScale 的宿主行为均是共同条件。完整原版入口确实实例化未改动的 `reference.NavigationDemo`，独立实测打开及返回正常。

| 项目 | 审查结论与边界 |
| --- | --- |
| 透明输出 | 候选 `:132` 在外部返回全零，`:160` 输出 `vec4(clamp(c) * mask, mask)`，符合预乘 alpha。没有看到新增矩形黑底。现有像素测试只检查一个外部像素和 48 个完全不透明像素，不能称为半透明边缘完整验证。App 迁移须在非整数 DPR 和另一底色上看边界合成。 |

| 折射方向 | `:140` 使用同一变形场得到的法线，不再把径向量额外加入折射方向。该局部改动值得试接；仍须用实际图案检查强弯曲／端点，不能由中灰图证明位移正确。 |

| 坐标 | 捕获 rect 在 painter 坐标中取得，再 `shift(-48,-48)` 与 `canvas.translate(48,48)` 对齐。两侧使用同一 rect/size，场景背景与 overlay 分离，没有捕获玻璃自身。实际网格、非对称文字与窄屏未见整体翻转或坐标错位。 |

## 非阻断取舍与测试证据限度

- **低强度是运动形变幅度，不是材质开关。** `main.dart:250` 保留 press，仅缩放 stretch/bend/vertical/energy。35% 的真实按压仍激活；0% 仍保留按压放大和光学响应，与 README 的定义一致。不可称为节省 65% GPU 工作，也不可把它当减少动态。
- **可选几何收缩继续留在实验。** 7.5% 的沿轨道膨胀有独立开关，不计入默认光学优劣；目前没有证据证明它优于业务 App 的现有尺寸／触控契约。
- **命名带倾向性。** `main.dart:368`、`:619` 的“改进范围／改进方案”会提前暗示胜负。改成“候选范围／候选方案”能使实验呈现更中性；这不阻断研究代码本身。
- **图集文字与无障碍是实验简化。** demo 仅提供一个 adjustable 语义入口，固定 11 号图集文字；App 需要继续保留五个入口、selected、角标、大字号与主题字体。不要复制该实验语义树到业务端。
- **测试断言范围有限。** 三项测试分别覆盖共享输入／取消／手动减少动态、窄屏和原版路由、单一中灰像素属性。35% 断言只检查 press 保留，没有在动态轨迹下比较 stretch/bend 的缩放；alpha 没检查部分覆盖边缘；中灰没有图案，无法证明折射方向、位移或色散。测试数量和文件数没有违反根测试约束。
- **失败记录有保留，但诊断日志命名陈旧。** `first-repair-tests.log` 为白底差值断言失败；`optics-repair.log` 同样失败；`optics-gray-diagnostic.log` 仍显示旧白底测试名和失败目标。最终源码已使用中灰相对偏差断言，不能把这些旧日志当作最终通过日志。`VALIDATION.md` 的最终 analyze／3 tests／build 成功是原作者记录，本次没有复跑或独立认证为成功。
- **没有像素指标证明候选全面优于原版。** 中灰回归用例有实际行为意义，说明指定采样区更接近源色；它不是玻璃质量总分，也不是浅底对比、色散品质或文字可读性的替代。

## 性能声明

文档目前没有捏造“更快”或手机帧率结论，这一点合格。候选清透路径确实跳过原版的零 sigma blur saveLayer / Picture.toImageSync，属于代码层面减少一次离屏图生成。

候选同时在 `reflectSurface` 中读取环境纹理，且 `dock()` 在镜片内被重复调用七次。从源码直接展开，镜片内原版约 24 次纹理读取、候选约 33 次；这是编译优化前的代码计数，实际指令、合并情况、GPU 时间没有测量。两侧还各自 capture 同一类场景。少一次离屏不能推出整体更快，幅度较低也不能推出功耗降低。

本轮没有 profile trace、frame timing 分位数、手机实机、持续内存、功耗或跨后端测量。实验分支可以继续保留这一明确限制；App 采用环境反射的完整组合前，需要在目标手机以相同场景、尺寸、材质和轨迹比较 UI／raster 帧耗与稳定性。源代码可审查不等于该性能门禁已通过。
