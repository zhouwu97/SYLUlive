# SYLUlive 主题制作

字段、槽位和资源规格以 `docs/design/theme-pack-contract.md`（第 2、6 节）和客户端解析器为准。只改主题包内容，不改共享 UI、默认主题和字体资源；清单省略 `font`。

## 先认清什么是「主题味」

坏主题的典型做法是一张风景图加一个人物，其余组件全部沿用默认。好主题的做法来自 B 站二次元手机主题和装扮套装，比如阿罗娜主题：UP 主把每个图标逐张重绘，开机、设置页头、通知图标、通话界面、安装界面都能看到角色或她的光环母题。归纳成四条：

1. **角色是主体，风景是舞台。** 页头画的是角色在做符合性格的事。人物占画面至少 35%，背景只交代地点。
2. **角色渗透到小组件。** 底栏图标、空态、角饰、区块记号、卡片底纹都用同一个角色的 Q 版或她的母题，不是只有一张大图。
3. **一个母题贯穿全套。** 从角色身上挑 1–2 个最有辨识度的元素（例如光环、鲸尾、饭团）。它们反复出现在纹理、记号、图标的选中态里。
4. **出自同一画师，逐张重绘。** 所有素材画风、线宽、光线一致。通用图标改色、不同来源的图混用，都会让「主题味」消失。

自检方法：遮住主题名，只看九个页面的截图，能不能认出这是谁的主题？

## 工作目录与自动模式

用户给出素材或角色后，按下面六个阶段**自动连续执行**，不需要在阶段之间等用户确认。每个阶段的产物写进工作目录，下一阶段只读这些文件：

```text
<WORK>/                      放在仓库外，或已被忽略提交的 artifacts/themes/<名称>/
  refs/raw/                  阶段 1：下载的原图（保留原文件名）
  refs/contact-*.png         阶段 1：带编号的缩略总览
  research/inventory.md      阶段 1：素材清单
  concept/character.md       阶段 2：角色设定
  concept/theme.md           阶段 2：主题母题与配色
  concept/slots.md           阶段 3：组件矩阵和每个槽位的提示词
  gen/                       阶段 4：生成原图（不入包）
  pack/                      阶段 5：manifest.json 和入包资源
  qa/                        阶段 6：实拍截图与 review.md
```

只有这些情况才停下来问用户：找不到角色的正面清晰参考、角色身份有歧义、生图接口不可用、虚拟机不可用。中途中断后，读取工作目录里已有的文件续做，不要重新开始。

预算：总生图次数不超过 60 次，单个槽位重做不超过 3 次。超过时改用原画裁切或简化该组件，并在报告里写明原因。

## 阶段 1：素材侦察（不许跳过）

按 [素材侦察](references/asset-research.md) 执行。要点：

- **把来源翻完。** 图集网站要抓取全部分区和分页，GitHub 仓库要读 README、署名文件和资产目录，B 站和 Pixiv 要看作者的同系列作品。只看首屏几张就开始生成，是做出「不像」的主要原因。
- **全部下载原图**，不用缩略图。用 `scripts/asset_tools_test.dart` 的 `contact` 模式把所有图做成带编号的总览，然后**逐张看完**。
- **在 `inventory.md` 里给每张图分类**：设定图（三视图、细节拆解）、官方或代表立绘、表情包、Q 版、换装、场景、壁纸。记录尺寸、作者和出处。
- **选定锚点**：
  - 1–2 张设定图作为身份锚点，后续每一次生成都要带上；
  - 3–6 张表情或 Q 版作为表情库；
  - 能直接入包的高清原画，标注可用的槽位。

## 阶段 2：角色设定与主题母题

写 `concept/character.md`（格式见 [主题方向](references/theme-direction.md)）：

- **标志物清单**：发型发色、呆毛、耳朵或兽耳、瞳色、服装结构与配饰、尾巴、道具。逐项写清楚形状和颜色，这些最容易被模型省掉。
- **性格与梗**：从设定页、百科、社区二创里归纳 3–5 条，例如傲娇、聪明但懒、爱吃白饭。每条至少对应一个可以画出来的动作或表情。
- **禁区**：不能画错的地方（发色渐变方向、耳朵形状等），以及不符合人设的画法。

写 `concept/theme.md`：一句话主题概念、母题（1–2 个）、辅助纹样、配色。配色从设定图上取色，`seedColor` 取角色主色，不能另选一个颜色。

## 阶段 3：组件矩阵

在 `concept/slots.md` 里为每个组件写一行：槽位｜画面内容｜体现的性格或梗｜参考图编号｜规格｜提示词。必须覆盖下表全部组件。表中写的画面内容只是方向，要换成角色自己的性格和梗。

| 组件 | 清单字段 | 画面要求 |
| --- | --- | --- |
| 首页页头（明、暗） | `decorations.home.background` | 角色主场景：腰部以上，人物在右侧 50–60%，做一件最能代表她的事。左侧 40% 低细节，留给 Tab 和搜索框 |
| 校园页头 | `decorations.campus.background` | 校园生活中的角色：上课、抱书、打哈欠等。胸部以上，头顶留空 |
| 我的页头 | `decorations.me.background` | 和用户互动的角色：招手、递东西、叉腰等，也可以换另一种形态 |
| 壁纸 global / secondary / schedule（明、暗） | `wallpapers` | 浅色或深色渐变加母题纹样，一角放一个小 Q 版，中间 70% 保持干净。课表壁纸最素 |
| 纹理 | `backdrop.pattern.tile` | 母题小图形的透明平铺块（例如小鲸鱼、水泡、饭粒） |
| 区块记号 | `sectionMark`（icon） | 母题剪影，单色透明 |
| Q 版贴纸 4–6 个 | `ornaments`、`cardArt`、`decorations.*.stickers` | 同一个 Q 版的不同动作，分别对应性格：探头、趴卡片边、捧道具、睡觉、生气 |
| 空态、错误插画 | `illustrations.empty/error` | Q 版表情：空态用无聊或偷懒，错误用委屈或慌张，带一句梗的动作 |
| 底栏图标 5 对 | `bottomNav.icons` | 语义不变（首页＝家、集市＝商店、课表＝日历、校园＝建筑、我＝人物），用角色画风统一重绘。选中态加母题或 Q 版小头像 |
| 服务图标（可选，成套才给） | `serviceIcons` | 13 个入口同一线宽、同一母题点缀；做不成整套就不给 |
| 首页顶栏图标 | `serviceIcons.menu/messages/search` | 菜单、消息、搜索三个小图标，和底栏同一画风，加母题点缀；26dp 以下仍要一眼认出含义，在页头插画上要看得清（必要时加浅色描边） |
| 发帖按钮角饰 | `ornaments.fab` | Q 版趴在首页 52×52 圆形发帖按钮的上沿或从侧面探头，用负 `dy` 探出按钮；不能盖住笔形图标 |

角饰位置要提前规划：`campusHeader` 写「从卡片右上探头」，`campusNotice` 写「趴在右下角」，`campusServices` 写「坐在宫格上沿」，`postCard` 写「小母题」，`fab` 写「趴在发帖按钮上」。避开「更多」按钮和数字。壁纸和 `cardArt` 里的小人不要落在底栏、发帖按钮和标题的位置。

## 阶段 4：生成素材

按 [素材生成](references/asset-production.md) 执行。核心规则：

1. **原画优先**：素材库里有尺寸和比例达标的高清原画，就直接用原画，或者只做扩图。真画师的作品比生成的更像。
2. **每次生成都带身份锚点**：设定图加对应表情图一起作为参考，提示词逐项写出标志物清单，并注明「忠实于参考比好看更重要」。
3. **先定画风再批量**：先生成一张 Q 版贴纸表（3×2 宫格、透明背景，同一张图里画全部动作），核对通过后用 `slice` 模式切开。同一张图生成的贴纸画风天然一致，单张分开生成做不到这一点。底栏图标同样用一张 5×2 宫格生成。
4. **页头逐张生成**：用 21:9 画布，每张都带锚点图和贴纸表作为画风参考。
5. **生成后立刻核对**：把成图和锚点图并排看，按标志物清单逐项打勾，缺一项就重做。

生图工具：在 Codex 里优先使用内置图像生成工具；不可用时，用 `imagegen-sunburst` skill 的脚本（`generate`/`edit`，`edit` 可以重复传 `--ref`，贴纸加 `--background transparent`）。

## 画质门槛（逐张检查，不过就重做）

1. **尺寸**：页头长边 ≥1800、宽高比 2.3–2.9；壁纸 ≥1080×2340；贴纸、插画长边 ≥512；图标画布 192–256。不能把低清图放大凑尺寸。
2. **头部完整**：按页头实际比例（cover 裁切后约 2.6:1）看，头顶、发饰、耳朵都在画面内，并留有余量。
3. **主体位置**：人物的脸不落在左侧标题区，不被状态栏或搜索框盖住。
4. **同一套**：画风、光线、饱和度一致；不出现截图和插画混用，也不出现与主色冲突的大块高饱和色。
5. **角色**：标志物清单逐项打勾，人数和互动都要对。缺一项就重做，不靠「整体像」放行。
6. **贴纸与图标**：透明边缘干净，没有白边或黑边；缩到 48px 仍能认出是谁；图标缩到 24dp 仍能认出原语义。
7. **页头图不要自带渐隐或留白遮罩**：沉浸页头的顶部和底部渐变由 App 绘制。

## 阶段 5：清单与打包

在 `pack/` 里写 `manifest.json`，新作品使用新的 UUID。参考 `artifacts/themes/mingfeng-complete/src/`（明风 · 晴蓝 V2）的结构：

- `layout.home/campus/me`：有装饰就**显式**写 `immersive`，`imageHeight` 140–160。`focalX` 取人物脸所在的横向比例（约 0.6–0.75），`focalY` 约 0.4。
- 明暗两套都要给：`seedColor`（角色主色）、`wallpapers`、`backdrop`（渐变、光斑、母题纹理）、`decorations`（三个页头加贴纸）、`componentOpacity` 0.85–0.9、`frostedGlass` `{enabled: true, strength: 0.2}`、`cardStyle` `{fill: tint, borderWidth: 0.75, shadow: soft}`、`identityHarmony` 0.6–0.7、`sectionMark`、`cardArt`（Q 版贴纸，opacity 约 0.12–0.16）、`ornaments`、`illustrations`。
- `bottomNav` 只写 `iconTint` 和 `icons`，**不写 `style`**：底栏样式是用户的设备偏好。彩色图标用 `original`，剪影图标用 `template`。
- `description` 写主题风格，并按素材许可注明角色原作者和素材来源。`license` 要和素材许可相容，素材要求非商用时选 `CC-BY-NC-4.0` 或 `personal-use`。
- 两张 1080×2340 预览图在阶段 6 用实拍截图通过 `fit` 模式生成，然后重新打包。

在 `client/` 下打包。脚本会补全配色 token，检查对比度、底栏双态图标，并检查本 skill 的硬性规则（页头必须 immersive、页头和壁纸尺寸、不写 `bottomNav.style`、不写 `font`），一次列出全部问题：

```powershell
flutter test --no-pub --dart-define="THEME_SOURCE=<WORK>/pack" --dart-define="THEME_OUTPUT=<WORK>/<名称>-v1.sltheme" ../skills/sylulive-theme/scripts/build_theme_test.dart
```

## 阶段 6：主题味评审与虚拟机验收

先跑组件检查，再在虚拟机上实拍。步骤见 [组件与虚拟机验收](references/component-qa.md)。至少要拍：首页顶部、首页滚动后的信息流、集市、课表、校园、我、一个二级页、空态页、深色模式首页。

然后在 `qa/review.md` 里按下表打分，每项 0–2 分。**总分 ≥10 且没有 0 分**才算通过；不通过就回到对应阶段重做，然后重新打包和拍摄。

| 项 | 2 分 | 0 分 |
| --- | --- | --- |
| 认人 | 遮住主题名能认出角色 | 认不出，或像另一个角色 |
| 渗透 | 9 个页面中至少 7 个能看到角色或母题 | 只有页头有角色 |
| 一致 | 所有素材像同一画师所画 | 明显混用截图、不同画风或通用图标 |
| 性格 | 至少 4 个组件画出了性格动作或表情 | 全是站桩立绘 |
| 主次 | 页头以人物为主，风景只交代地点 | 风景图加一个小人 |
| 可读 | 标题、正文、课表最小字清楚，装饰不挡按钮 | 文字压在脸上，或底纹抢字 |

交付时给出：主题包路径、九张实拍截图、`review.md` 评分、素材说明（哪些用了原画、哪些是参考原画生成的、参考图来源和作者）。

## 改造已有主题包

适用于「素材已有、规则不合格」的包，例如缺 `layout`、带 `bottomNav.style`、页头低清：

1. 只改用户自己的包，或者作者授权的包。
2. 解包到 `<WORK>/pack/`，跑一遍打包脚本，它会列出全部硬性问题。
3. 字段问题直接改清单；页头低清、比例不对、自带渐隐、截图画质的图，用原图作为参考按阶段 4 重绘；壁纸不够尺寸就重绘。
4. 保留原包的配色、图标和 `cardStyle`，除非用户要求改；缺少的组件按阶段 3 补齐。
5. `version` 加 1，`id` 不变，重新打包后走阶段 6。

## 投稿前自检

| 检查 | 对应拒绝原因 |
| --- | --- |
| 打包脚本没有报错，对比度全部通过 | `contrast` |
| 所有图片没有文字、水印、二维码 | `wallpaper_text` |
| 简介里注明了角色原作者和素材来源 | `copyright` |
| 页头在手机整宽下清晰，人物头部完整，主题味评分通过 | `quality` |
| 底栏五个图标语义可辨，两态不同 | `icon_semantics` |
| 名称不以「官方」「沈理」开头，简介里没有联系方式 | `metadata`、`impersonation` |

角色身份有疑问时（多个形态、合照、用户说「不像」），先按 [角色核对流程](references/character-art.md) 确定每个角色的参考图。
