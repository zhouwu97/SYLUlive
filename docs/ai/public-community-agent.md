# AstrBot 公开社区 Agent 专项方案

状态：0.5.0 逐账号运行扩展，生产新增权限默认关闭。风险 R3（自主任务、账号、上传及检索留存），发布须维护者明确放行。配置与留存的权威入口是 [插件 README](../../astrbot_plugin_sylulive/README.md) 和 [隐私数据台账](../privacy-data-inventory.md)。执行框架保持 AstrBot。

## 逐账号运行专项设计

App/Web 继续作为本人控制入口，Go 保存 bot、权限、规则版本及运行元数据；常驻 AstrBot 的任务管理器为已登记且明确授权的每个账号建立独立公开 Agent。创建者兼容旧凭据槽与公开发言账本；普通账号按安全凭据槽及服务端 bot ID 隔离库。部署者另行开启多账号任务开关，用户创建并启用机器人且授予公开阅读后才进入调度；评论、发帖权限继续分别控制。

本机索引仅记录不透明凭据槽和安装 ID，用于重启恢复；身份来自服务端当前 binding，不接受模型或网页指定发言账号。每轮调用使用新上下文与公开工具面，模型并发上限2；没有私人库、群历史或他人账号工具。执行前持久化下次时间，暂停或授权／规则代次改变取消旧任务，未知写入结果继续保留原账本。

Go 在原 owner → binding → source → bot 锁顺序下保存心跳并检查最终发布，单个 bot 采用两分钟执行占用、会话 ID 与递增序号。新会话只能在旧占用过期／正常释放或换绑后接管；新协议机器人拒绝缺执行会话的旧插件发布。规则版本在资料／权限／启停保存时递增，旧版本发言拒绝。心跳不授予任何写内容权限，公开只读 scope 可报告自己的非正文运行状态。

状态由当前 bot 开关、有效 binding、权限和心跳共同推导；过期显示离线，规则更新显示等待同步，成功发言以实际 bot 作者的服务端发布记录为准。两端独立刷新运行区，失败降为未知并保留表单草稿；切号和晚到响应按原会话代次隔离。

验收包括两账号同时阅读／独立发言、暂停 A 后 B 继续、撤权与改规则时的在途取消、并发接管、重启间隔恢复、旧授权不扩权、只读 scope 心跳、未知写入不重发、跨账号状态隔离及真实渲染。发布顺序、回滚和数据留存分别维护在运维入口与隐私台账。

## 账号、记忆与界面决策

一个创建者管理一个托管机器人，`managed_bots.owner_id` 主键与 `user_id` 唯一键共同约束数量。创建/启用需近期本人认证与现行资格；暂停只需本人会话，即使教务资格消失仍可止损。机器人为普通角色的特殊 `bot` 状态，无有效登录凭据、不继承创建者登录态。发布仍锁创建者、授权与源帖，再锁机器人检查额度、禁言和状态；评论及通知同事务，保留 AI 标识，不获取经验奖励。

三类上下文分开：创建者当前私聊以加密本机库记录，检索只注入已鉴权本人私聊；群仅短时内存；公开原文及向量使用单独公共库。公开 Agent 对象不持有私聊库，评论工具只出现在后台新上下文，群聊和本人私聊都没有自动发布工具。未配置嵌入/重排模型时显式使用 lexical，不谎称完成语义向量 RAG。

App 与 Web 以同一个 `/api/connected-apps/bot` 返回机器人、服务开关和专用授权状态。名称和启停请求不接受 owner/actor 参数。页面对 loading、empty、error、retry、saving、缺资格、旧服务404、切号和窄屏分别处理；不会根据本地按钮开关伪造后台正在运行，也不提供从网页读取本机私聊库的接口。

维护时必须保留：独立评论 scope 默认不选；旧令牌不扩权；帖子内容不能改变访问范围；不跟随任意URL；模型不得指定发布账号；只有本轮读到的帖子和有效内置表情可参与；超时占用发言账本且不盲重试。发言账本不随公开记忆清空。公开版块列表在进模型前过滤，详情再次复核。自定义人格中不能放私人事实或凭据。

0.4.4 将实时阅读展示与长期记忆投影分开，正文、公开作者昵称、统计、线程关系和图片引用完整进入本轮工具结果，长期库仍保存必要文字。后台新增评论分页与实际多模态读图；评论需先读正文与至少一页讨论，未读完明确 partial。来源变化或暂停使本轮待执行动作失效。

自主新帖采用独立 `community:bot_post`，依赖公开读取／动作／提案授权，不由自动评论继承。先查询服务能力；当前机器人模式仍需有效的机器人阅读授权，不因旧接口或关闭写入开关回退匿名读取。只从本轮已读来源构造版本，图片由部署者审核的公开素材清单选 ID，插件核对哈希，按独立 bot 身份上传。服务端复用原上传校验与文件归属，在发布事务内绑定并公开图片；日限1帖，评论／发帖每轮合计最多一次尝试。普通人工确认路径拒绝这些 bot 配图载荷，避免未展示图片被批准。已绑定用户的个人查询接口不参与此链路。

每个机器人另有 `post_enabled` 与 `image_enabled`，两项缺省关闭；旧 `reply_enabled` 和 `sticker_enabled` 不授予新能力。App/Web 共用策略与服务端状态，分别展示发帖和配图选择。后端对发帖内容及全部来源板块重新校验范围、禁链接和屏蔽词，对图片校验 bot 自有或明确上传授权；没有配图权限仍可在其他条件满足时发纯文字。

此范围不把 QQ 的 search_meme/send_meme 变成社区附件上传：前者只向当前聊天发送兼容插件的本轮候选，后者只能使用明确批准的公开素材。没有素材或关闭相关权限时允许只读或纯文字，不能从私人聊天自动采图。人格继续完全由 AstrBot 配置。

## 参考与取舍

人格由 AstrBot 人格与会话配置管理。前台解析当前会话所选人格，后台无私聊会话，使用 AstrBot 默认人格 prompt；插件只附加访问边界。0.4.3 删除旧版随包“大肥鱼”正文、注入和插件人格配置项，不把人格状态放入权限管理页。原生人格中的设定会进入模型，应只配置愿意公开的内容。

阅读调度另参考 B站 [dsh-bili-scroll 演示](https://www.bilibili.com/video/BV1d8pU6xEZX/) 对应 [源码](https://github.com/c1overzz/dsh-bili-scroll) 和小黑盒插件 [dsh-xiaoheihe](https://github.com/fbbDirge/dsh-xiaoheihe)，它们不是本次人格来源。未运行第三方项目或复制其运行时代码/素材。

采用专用工具面、身份与经历分离、调度与生成隔离。人格是稳定表达底色，事实记忆来自实际公开阅读；不把模型感想存成亲身经历，不宣称实现自动心理成长。用户提供的 [小黑盒原帖](https://www.xiaoheihe.cn/app/bbs/link/195743574) 对应 [Ornn8 评测](https://github.com/Ornn8/memory-system-benchmark)：其 Qwen 对照为原文块嵌入召回加重排，正式卷未公开，结论限低频单人配置。本实现复用 AstrBot 的 embedding/reranker Provider，保留原文与本机版本隔离向量；BM25 只作为显式选择的离线基线，不把纯关键词实现当作该评测方案。没有复用或宣称复现上游分数。

## 调用链与边界

部署者设置与 App/Web 保存的机器人权限 → 互斥定时器/本人单次命令 → 固定 `/bot/policy` 核对 → 只返回公开字段的同源认证列表 → 服务端版块允许表与本机更严的帖子拒绝表 → AstrBot 原生 Agent 新上下文 → 仅本轮候选 ID 的阅读工具 → 详情可见性与机器人权限复核 → 本机公开检索库。聊天检索只召回线索，再逐条复核当前公开来源。无机器人、暂停、旧服务或权限校验失败不回退匿名读取；人类匿名公开接口不改变。

网络路径、工具集合、额度、超时和留存由代码控制。正文不是指令。后台不提供私人账号资料、聊天、文件、命令、任意网页、子代理或跨会话发送工具；独立评论工具须新授权。普通账号管理只留确定的本人命令。公开请求不继承私人历史、全局 KB、媒体或注册工具集合。其他插件后续注入可破坏隔离，目标部署应使用独立公开实例或受审查插件。

服务端根据机器人白名单限制列表、详情、评论和回复上下文，本机范围仍可进一步收紧，禁止项不进入模型。规则在读前与返回前复核，写入事务再次检查；这不等于撤回已交给模型的公开文字。来源变更不是实时推送；召回时复核，不收回已经外发的内容。

## 状态、验证和回滚

覆盖 disabled、idle、loading、busy、cooldown、scope_required、empty、completed、error、paused、cancelled。空白名单、缺模型、网络失败和超时不降级到私人客户端或无工具限制 Agent；失败同样受间隔限制。配置/代次改变后旧结果不得入库；最终回答也需检查本轮代次。

分阶段验证：先离线验证允许/拒绝、数据投影、Cookie/Token 隔离、TTL/容量、来源变化和失败不回放；再用固定真实 SDK 和合成 Provider 验证分发、上下文、工具及原生 Agent 调用链；最后由维护者在目标环境验收真实模型选择工具、QQ 接收、empty/error/retry、恶意正文套话、暂停/重载和检索复核。合成测试不能替代最后一阶段或证明人格体验。

发布另记不可变构建物、CI/安全证据、责任人与明确放行。回滚先关闭公开 Agent/定时开关，恢复旧 ZIP；不迁移服务端和凭据，新检索库可停机后独立移除。QQ/Provider/备份副本由部署者管理。
