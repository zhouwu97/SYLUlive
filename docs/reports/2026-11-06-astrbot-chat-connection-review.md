# AstrBot 聊天与连接页隔离交付检查

- 基准：`origin/zhou`，`e19b33daad997e5301d86dfe8d4faedf2a0ed4d6`。
- 范围：本次聊天的当前附件、引用、本人近期对话和连接引导修复。用户已明确授权检查、测试后推送此范围。
- 风险：R2，涉及私聊上下文隔离和本人权限确认；不改服务端鉴权、数据库、生产配置或原授权。

## 问题与修复

隔离钩子曾清空本轮媒体与原生 conversation，导致当前图片无法进入模型、原生私聊无法保存新轮次。连续消息插件又可能注入旧话题预判。本次保留当前请求的附件和引用，按真实合并窗口重建用户发言，并仅为归属核对成功的创建者本人恢复有界近期对话；群与后台继续隔离。旧检索／思考不循环回放，最终回复校验完成后才写插件记忆，可选记忆故障不阻断普通聊天。

连接页直接打开可修改 origin 的 AstrBot 插件权限视图，并说明原生后台登录。旧连接显示缺失 scope，明确重新取得连接码、手选权限和替换授权的步骤；失败保留原连接。自动参与和个人查询／签到均不默认选中。满足基础 scope 加评论或发帖 scope 后才显示启用步骤。较早的查询或确认响应不能覆盖编辑连接码后的页面状态。

## 兼容与交付边界

基准服务端尚未包含本机混合版本的新机器人管理后端和自动评论／发帖 scope。此分支只修聊天与连接引导：不会凭空增加服务端能力。旧服务请求不含对应 scope 时只能批准其支持的权限；不兼容时显示版本核对和重新申请入口。启用指引供具备对应 App／服务能力的部署使用，不代表本分支单独具备完整机器人管理链路。

这次是源码推送，不构成生产放行或部署。未进行真实 QQ 对话／模型质量验收、线上授权、生产写入和自动社区发布。原主工作区及其他任务的未提交文件保留。回退恢复上一固定插件 ZIP 与 Web 构建，不删原生存档、不清凭据、不重写旧授权。
