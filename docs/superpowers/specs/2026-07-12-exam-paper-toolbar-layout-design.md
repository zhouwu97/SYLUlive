# 试卷库筛选栏与学年数据设计

## 目标

在 Android 手机端将试卷库的四个筛选项压缩为单行展示。学年下拉仅展示数据库中实际存在已发布试卷的学年，按年份倒序排列；下拉面板可纵向滚动，并同时容纳“全部学年”和 3 个学年选项。

## 范围

调整已发布试卷列表接口响应、Flutter 列表模型、试卷库页面和筛选工具栏。不改试卷查询参数、搜索防抖、分页、投稿和管理端接口。

## 接口与数据流

- `GET /api/exam-papers` 在现有分页响应中新增 `academic_years: string[]`。
- 服务端从全部 `published` 状态试卷中查询不同的 `academic_year`，按字符串降序返回。该查询独立于当前请求的关键词、学年、学期和类型筛选条件。
- 客户端在 `ExamPaperPage` 中解析 `academic_years`；每次加载第一页成功后，试卷库页面以该列表更新工具栏。
- 服务端未返回该字段或列表为空时，客户端显示“全部学年”，不再根据当前日期虚构学年。

## 筛选栏布局

- 搜索框保持现有尺寸和位置。
- 四个筛选控件始终使用 `Row`，不再在窄屏换行为两行。
- 下拉触发器高度为 28px，缩小文字、内边距、箭头和控件间距。
- 四项按 4:4:4:3 的弹性比例分配可用宽度，保证“全部学年”“全部学期”“全部类型”和“最新”在常用 Android 手机宽度下完整可见。
- 下拉菜单的最大高度为“全部学年”加 3 个学年项；超过范围后纵向滚动选择。

## 行为与兼容性

- 学年菜单始终包含“全部学年”。
- `academic_years` 少于 3 项时，显示实际可用学年，不产生空白项。
- 下拉选中值始终来自服务器返回的列表或空值，保持和查询条件一致。
- 试卷库没有已发布试卷时，学年菜单仅显示“全部学年”。

## 验收与测试

- Go 处理器测试验证只返回已发布试卷的去重学年，且按倒序排列，并确认请求筛选条件不会改变该集合。
- Flutter 模型和服务测试验证 `academic_years` 解析与接口传递。
- 工具栏组件测试验证 320px 宽度下四项同一行，学年菜单只展示服务端提供的年份，菜单可视高度为“全部学年”加 3 项。
- 仅使用 Android Studio 模拟器安装运行，打开试卷库并验证单行布局、学年排序和下拉滚动；不使用 Web、浏览器或其他验证方式。
