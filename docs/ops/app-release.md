# Android 发布

本文只描述 Android 发布物的专项执行要求。每次发布先执行根目录 [发布前回归清单](../../RELEASE_CHECKLIST.md)，再按本文完成构建物、设备和渠道验证。

## 1. 构建前

- 明确版本号、目标 API、发布渠道、服务端契约和兼容范围。
- 固定不可变源代码提交，确认客户端与服务端的实际版本组合。
- 确认 CI 相关 jobs、客户端测试和必要的服务端验证均有可追溯结果。
- 确认正式 API、推送和签名配置来自受控环境；私钥不进入仓库、聊天或构建 artifact。
- 使用 client/scripts/build_release.ps1 或当前仓库批准的正式构建入口，不把临时测试包当正式发布物。
- 正式发布构建设置 RELEASE_DECISION=passed，并提供对应的 CI 运行号和 security.yml 运行号；涉及 Go、Python 或依赖文件时同时要求依赖审计证据。脚本会把 workflow_conclusion、evidence_status、Gitleaks 和依赖审计结果写入 release-manifest.json。

## 2. 构建物检查

- 记录 APK／AAB 文件名、版本、源提交、构建时间和 SHA-256。
- 使用 apksigner 验证签名证书指纹与批准记录一致。
- 确认包名、版本号、目标 API、渠道配置和 assetlinks 与发布目标一致。
- 确认构建物未包含调试地址、示例 API、占位推送配置或测试凭据。

## 3. 设备验证

至少在一台目标 Android 设备完成：

- 安装、启动和首次配置；
- 登录、登出、会话恢复和错误提示；
- 本次改动涉及的关键业务链路；
- 权限允许、拒绝和重新授权；
- 网络失败、超时、重试和恢复；
- 覆盖安装、版本升级和旧数据兼容；
- 通知、后台恢复和应用重新启动。

验证使用专用测试账号和隔离数据，记录设备、系统、包版本、步骤、结果和脱敏证据。

## 4. 渠道和发布后

- 官网下载地址、GitHub Release、版本更新入口和 assetlinks 指向同一构建物。
- 发布记录包含版本、提交、签名指纹、校验值、验证范围、已知问题和回滚包。
- 发布后按根目录清单完成服务端健康检查、关键业务冒烟和观察窗口。
- 发现阻断问题时停止继续分发，按 docs/ops/rollback.md 和 DEPLOY.md 执行回滚。

签名验证只证明构建物身份，不能替代自动测试、真实设备验证、业务验收或发布批准。
