# 组件与虚拟机验收

## 1. 页面 × 检查项

每一项都要记录：实际页面、组件与状态、清单字段或共享组件、明暗实拍文件、结果。结果只能是以下四种之一：

- 已看到主题效果
- 沿用固定语义
- 当前账号或设备未触发
- 客户端没有接入

导入成功、写了字段、截了整页，都不能单独证明组件有变化。

| 实际页面 | 检查点 |
| --- | --- |
| 首页顶部 | 沉浸页头铺到状态栏，人物头部完整；标题、Tab 选中与未选中、搜索框可读 |
| 首页信息流（页头滚出后） | 互动回复条、版块标签、帖子表面与描边、正文与次要文字、更多按钮、评论与浏览数、发布按钮；`cardArt` 和角饰不压数字和更多按钮。头像、帖子附件属于用户内容，不受主题影响 |
| 主壳底栏 | 五个入口逐个点，看常态和选中图标、标签、底栏底色与内容末行。**底栏样式和液态玻璃参数在应用主题前后必须一致** |
| 集市 | 搜索、筛选 chip、商品卡、排序与筛选面板、发布按钮；价格和交易状态保持原有语义 |
| 课表 | 周次、今天标记、时间轴、网格、课程色板、最小课程文字、课程详情；分别记录有课、空课表、未绑定三种可达状态 |
| 校园、工具箱 | 沉浸页头、学期卡、通知、区块记号、服务宫格、工具箱列表；对照六个校园入口和七个工具箱入口；打开一个入口再返回，确认装饰不挡点击 |
| 我、个人主页、设置 | 沉浸页头、资料卡、真实头像和封面、列表组、图标、分隔线、次要文字、箭头、开关；打开一个含开关的设置子页 |
| AI 助手与共享状态 | 会话标题、气泡、输入框、发送按钮的可用和禁用态；空态和错误显示主题插画；加载、离线、权限说明和重试保持原有语义 |
| 桌面小部件与启动图标 | 课表、考试小部件是否跟随 App 明暗字色与课程色；App 内预览和 Android 桌面实拍分开记录 |

## 2. 执行步骤

| 步骤 | 命令或操作 | 记录 |
| --- | --- | --- |
| 1. 组件构建检查 | 在 `client/` 下运行：`flutter test --no-pub --dart-define="THEME_PACKAGE=<包路径>" ../skills/sylulive-theme/scripts/check_components_test.dart` | 九页 × 两种亮度 × 五种状态是否有构建或布局异常 |
| 2. 锁定设备 | `adb devices -l`，`adb -s <SERIAL> emu avd name` | 设备、App 版本、字体比例、明暗模式、起始页 |
| 3. 记录原状态 | 截一张首页和底栏；在底栏设置里记下样式和液态参数 | 测试结束后恢复用 |
| 4. 导入 | `adb -s <SERIAL> push <包> "/sdcard/Download/沈理校园/主题/"`，在 App「本机主题」里下拉刷新后点开 | 主题名、版本、参与的分组 |
| 5. 先试用后应用 | 先试用，走一遍第 1 节；再应用并重启 App | 两次的截图 |
| 6. 实拍 | `adb -s <SERIAL> exec-out screencap -p > <WORK>/qa/<页面>-<明暗>.png`（Windows 要用二进制方式写文件）。截图前等导航和图片加载完成 | 至少九张：首页顶部、首页信息流、集市、课表、校园、我、二级页、空态页、深色首页 |
| 7. 大字号与暗色 | 系统字体 1.5 倍下看首页和校园；切换深色再拍一遍首页 | 有没有溢出、被截断，对比是否足够 |
| 8. 角饰位置 | 直接检查校园周次、通知日期、帖子更多按钮、服务宫格边缘 | 没有稳定留白的位置，移除该处角饰 |
| 9. 预览图 | 用 `asset_tools_test.dart` 的 `fit` 把首页亮色和暗色实拍裁成 1080×2340，作为 `preview/light.jpg`、`preview/dark.jpg`，然后重新打包 | — |
| 10. 恢复 | 结束试用，或恢复上一个外观；确认底栏回到第 3 步记录的状态 | — |

每次替换了素材或修改了清单，都要重新打包、导入，并重拍受影响的组件。截图避开学号、私信和真实课表详情。打包脚本的输出（可用分组、图标数、各模式资源槽位）和设备验收结果分开记录。
