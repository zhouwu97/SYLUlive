# AstrBot 多用户授权与权限后台

状态：0.2.0实施方案／候选实现；本地检查不能代替CI、真实QQ、学校资料和生产验收。风险R3；不扩展社区自动发布。

## 产品与边界

每位QQ用户使用自己的校园授权。帖子、评论、食堂、地图与资讯继续匿名读取；绑定与撤权不影响公开查询。聊天模型、人格和记忆由AstrBot管理，不新建Go聊天Agent。

用户在机器人私聊发`/sylu-connect`（`/绑定校园`），收到本次请求的官网链接和设备代码；本人登录官网核对安装名称和代码，按需同意成绩、二课、签到。三个个人权限默认不勾选，旧授权不增权。群中请求绑定只提示转本人私聊，不在群发链接或代码。链接是标准设备授权请求，不是含App JWT的登录捷径。

| 请求 | 行为 |
| --- | --- |
| `/sylu-grades`、`/我的成绩`、私聊“查我的成绩” | 读取本人已同步学期成绩，每页20门，保留下一页、来源、范围、时间、过期／部分状态 |
| `/sylu-erke`、`/我的二课`、私聊“查我的二课” | 读取本人同步的二课摘要，不冒充完整活动明细或实时学校查询 |
| `/签到`、`/sylu-checkin` | 发起人独立授权签到，与App共用同日事实与奖励 |
| `/sylu-status`、`/sylu-disconnect` | 查询／撤销自己的连接；甲的撤权不清除乙的凭证 |
| 群内个人查询 | 提示本人私聊，不读取成绩／二课，不将私人结果装入群模型 |
| 任意获准公开会话查看帖子 | 沿匿名接口，不携带任何绑定凭证 |

官网批准后，下次本人查询会对本人的待授权请求尝试一次标准轮询；也可单独查状态。不会为每次绑定创建长期聊天任务或无限轮询器。学校未登录、资料未同步、授权未完成或scope未批准时明确拒绝，不拿部署者或他人的数据兜底。

## 凭证与主体隔离

新用户凭据槽按服务origin、平台实例、机器人QQ、发送者QQ隔离，分别维护安装UUID、access／refresh、待授权状态、刷新锁和授权代次。磁盘只保存安装UUID，token仍使用系统凭据库；无安全凭据库时仅内存保存并提示重启后重连。原部署者保留旧槽兼容已有连接。每进程最多缓存500个新用户客户端，超过时明确拒绝。

只从真实消息事件提取主体，不接受模型参数的QQ号、目标用户ID、角色或学校密码。服务器仍以OAuth凭证绑定的校园owner作为唯一业务主体；一校园账号和一安装UUID各最多一个有效授权。换QQ或替换绑定需要本人在官网明确同意。自部署进程和Bearer Token不能证明每个请求真实来自某QQ；安装名称中的QQ是自报核对信息，不宣称独立QQ归属证明。

非部署者私聊同样隔离部署者全局知识库和跨会话工具。成绩与二课只经确定命令返回，未注册给模型。第三方插件、QQ和机器人系统运维者可能保存或接触私聊及结果；业务管理员角色不会自动得到他人成绩接口，但不能承诺操作系统管理员无法接触其机器内的数据。

## 数据来源与实际同步入口

现有Web教务资料默认只在本机。本方案在“已授权助手”增加显式同步面板，复用现有教务助手连接流程；先读取本机、预览、另行勾选同意，再上传最小结构。

- 成绩只投影当前学期的课程名称、成绩、学分、GPA、课程性质及学期；不上传学校学号、课程内部ID、密码、Cookie或HTML。上传的是用户同步资料，不标为实时学校来源。当前只保留最近一次上传的学期，不宣称覆盖全部学期；App既有教务云快照仍可提供其他已同步范围。
- 浏览器二课只上传毕业总量与分类缺口，不编造缺失的学年与活动；也支持App既有最小二课快照。所有快照保留同步时间和部分／过期状态。
- 上传和OAuth授权分开：上传不授权机器人，绑定不自动上传或登录学校。现有“永不云存储／二课上传”隐私选项仍拒绝相应操作。
- 5天后标记过期，副本保留到本人删除／覆盖，不宣称定时物理删除。页面可删除成绩上传副本和二课云摘要；删除成绩上传副本不删除App原有教务云快照。撤销助手可以阻断插件后续读取，已送达QQ或外部插件的副本不能逆向撤回。
- 成绩上传记录包含服务端加入的教务绑定ID／版本，读取时核对当前身份；用户不能上传这些内部归属字段。已有服务器教务快照沿用当前凭据代次校验。

二课快照原哈希依赖JSON对象字节顺序，PostgreSQL jsonb重排后可能误报损坏。改为规范化JSON计算哈希；已知旧结构仅在严格解码、重新归一化后与旧哈希匹配才兼容，不接受未知字段或篡改，不批量修改真实数据来制造通过。

## 后台权限可视化

入口`/web/admin?tab=integrations`，复用站点管理员／超级管理员认证，不复用QQ中的AstrBot管理员角色。

- 按状态分页查看绑定昵称、安装名称、scope、状态和创建时间；安装名中的QQ仅用于核对。
- 查看最近50条审计元数据，包含事件、操作者、原因与时间，不含成绩、二课、草稿正文、凭证或学校账号。
- 只能缩减当前已批准的scope或撤销授权；不能代用户新增权限。操作必须有原因、确认和预期授权代次；并发旧页面不能覆盖新决定。
- 缩减递增代次，使旧access／refresh失效、作废待发草稿；恢复／新增须用户本人重新同意。此处管理当前授权，不是持续禁止用户重新申请的名单策略；长期禁用沿现有账号治理。
- 管理员没有指定用户读取成绩或二课的接口；App管理员JWT不能用作集成个人数据令牌。

数据库事务沿用用户→绑定锁顺序。个人读取和无正文审计同事务，审计失败不返回私人数据；撤权后的旧代次拒绝。管理员调整也按此顺序，不建立平行的权限数据库或任务队列。

## 接口与开关

新增scope：`academic:grades:read`、`academic:erke:read`；签到沿`checkin:write`。默认不批准，用户可仅同意其中部分。

| 接口 | 主体与内容 |
| --- | --- |
| `GET /api/integrations/v1/me/grades`、`me/erke` | 集成token本人，无目标用户参数；成绩只接受offset／limit |
| `POST/DELETE /api/connected-apps/personal-sync/grades` | App登录本人，严格最小结构、显式上传同意／删除，不接受owner字段 |
| `PUT/DELETE /api/personal-snapshots/erke` | 复用既有App本人最小摘要上传／删除 |
| `GET /api/admin/integrations`、`:id/audits` | 站点管理员，仅元数据 |
| `POST /api/admin/integrations/:id/restrict` | 站点管理员，仅减权／撤销，预期epoch与原因 |

本机新增`allow_multi_user=false`、`allow_personal_queries=false`。上线显式启用，`allow_checkin`仍须既有开关及本人scope；`public_read_all_sessions`沿部署者选择，社区提案和发布开关不随个人查询开启。

服务端另有`INTEGRATION_PERSONAL_DATA_ENABLED=false`，关闭时拒绝批准新个人scope、本人查询和新成绩上传，仍保留删除上传副本、减权与撤销。后台和授权页读取实际服务状态，读取失败时显示未确认并禁止新读取／上传。该开关要求`INTEGRATIONS_ENABLED=true`且`SCHOOL_AUTHORITY_RETIRED=false`；已有退役部署不能直接开启，须重新评审，不能静默关闭退役开关来恢复旧学校能力。此约束也保证复用的二课最小快照路由与本机身份核对可用，插件开关本身不能放行服务端接口。

## 发布与验收

1. 本地验证两个独立合成用户的链接、凭证、数据、分页、签到及撤权隔离，群和第三方主体反向拒绝；覆盖授权页默认不勾选、同步未确认不上传、权限减少、旧代次、删除／过期／损坏及审计失败。
2. 通过真实AstrBot SDK、Go服务／HTTP、Web检查、浏览器桌面与移动端真实渲染。PostgreSQL锁、迁移与jsonb兼容必须有独立证据；SQLite不能代替行锁验证。
3. 获准后推送不可变候选并验证CI／安全门禁。明确生产放行后按运维入口备份，先Go和Web，再插件，最后打开新本机开关；不能代用户批准scope或用改库补身份。
4. 获得具体测试授权后，用真实QQ和学校账号验收；未同步不能冒充实时查询，不额外向群发测试消息。
5. 回滚先关新本机开关并撤销新个人范围授权，再恢复旧插件／Web／Go。兼容审计新列和快照类型可保留，不回灌整库。保留原模型、人格、接收设置、群语音偏好和部署者旧绑定。
