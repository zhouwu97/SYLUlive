# 从主题字段到屏幕上的组件

按用户要覆盖的页面核对下表。每项记录实际页面、组件与状态、清单字段或共享组件、明暗实拍文件和结果。一个页面可关联多项。结果分为已看到主题效果、沿用固定语义、当前账号或设备未触发、客户端没有接入。查当前页面和共享组件确认消费字段；导入成功、写了字段、截了整页都不能单独证明组件有变化。

| 实际页面 | 制作与检查 |
| --- | --- |
| 首页顶部与滚动后的信息流 | 标题、Tab 选中与未选中、搜索输入、互动回复条、版块标签、帖子表面与描边、正文与次要文字、更多、评论与浏览、发布按钮。两张截图分别拍到主视觉和页头离屏后的帖子。用 token、卡片填充、淡底图或小角饰贯穿列表。避开更多按钮和数字；头像、帖子附件属于用户内容。 |
| 主壳与集市 | 轮流点击五个底栏入口，看选中和非选中图形、标签、底栏底色与内容末行。集市检查搜索、筛选 chip、商品卡、排序与筛选面板、发布按钮。价格和交易状态保留其含义。 |
| 课表 | 检查周次、今天标记、时间轴、网格、课程色板、最小课程文字与课程详情。分别记录有课、空课表、未绑定的可达状态。只见绑定引导时，课程格仍待实拍。 |
| 校园、工具箱 | 校园紧凑页头、通知、区块标题、服务宫格与工具箱列表。对照契约列出的六个校园与七个工具箱入口，区别已显示、需滚动、当前权限下隐藏。打开一个入口再返回，确认装饰不挡点击。 |
| 我、个人主页、设置 | 资料卡、真实头像和封面、列表组、图标、分隔、次要文字、箭头和开关。打开含开关的设置子页，在不改账号资料的情况下检查设置项、弹层和关闭返回。 |
| AI 助手与共享状态 | 检查会话标题、气泡、输入框、发送按钮的可用和禁用态。使用已有对话或本机样例。空态和错误可接主题插画，加载、离线、权限说明和重试保留原语义。工坊样例与真实请求的结果分别记录。 |
| 桌面小部件与启动图标 | 桌面课表、考试小部件独立于 App 页签。检查宿主是否已添加、是否选择跟随 App、明暗字色与课程色。试用不写设备偏好，涉及持久应用、切换系统启动图标或修改现有桌面布局时依用户范围执行。App 内预览、平台通道测试和 Android 桌面实拍分列。 |

**虚拟机执行顺序**

在 `client/` 下先用实际交付包运行工坊样例，覆盖九页、两种亮度和正常／加载／空／失败／权限五种状态，并构建课表与考试桌面小部件预览。这个检查报告组件构建和布局错误；继续以下设备步骤验收实拍、触控和系统宿主行为。

```powershell
flutter test --no-pub --dart-define="THEME_PACKAGE=D:/art/campus-v1.sltheme" ../skills/sylulive-theme/scripts/check_components_test.dart
```

1. 用 `adb devices -l` 与 `adb -s SERIAL emu avd name` 锁定用户指定的虚拟机。记录 App 版本、字体比例、明暗模式、起始页及已有外观。以 `adb -s SERIAL exec-out screencap -p` 取得真实屏幕；Windows 用二进制流写 PNG。
2. 从 Android 文件管理器或 App 导入最终文件，确认主题名、版本和参与分组。用同一台设备、相同页面和字号比较；在信息流滚动、打开筛选弹层、查看二级页并返回。按表检查可达组件，截图前等待导航和内容加载完成，验收加载时另存瞬间截图。
3. 在亮暗两种模式核对活跃控件、课程小字与图标对比，选代表页面实看 1.5 倍字号。先记录原设置，测试后恢复。异步快速切页后核对旧页面背景、用户和图片不会覆盖新页面。失败、重试与权限场景使用本机可控数据；缺少前置条件时写明并标出替代证据。
4. 在校园周次、通知日期、帖子更多和服务宫格边缘直接检查角饰与文字的位置。如果槽位没有一块稳定的留白，移除该处角饰，沿用卡片材质或入口图标。实际出现「应用无响应」时保留页名和复现步骤，恢复交互后再验该路径。
5. 校验退出试用能恢复，再按用户要求确定交付时的设备状态。替换了素材或修正了清单，就重新打包并导入，重拍受影响的组件。同屏展示能验证的效果，截图避开学号、私信和真实课表详情，报告给出组件对应的截图或具体未验证原因。打包脚本输出的是解码后清单中的可用分组、两态图标数和各模式的资源槽位，和设备验收结果分别记录。
