# 沈理校园 Web 与教务助手

React + TypeScript + Vite，复用 Go API；Web 当前视觉实现入口为 [tokens.css](tokens.css)、`src/commons.css` 与共享组件，具体设计按本次任务要求执行，验证流程见 [开发与交付规范](../DEVELOPMENT_STANDARD.md)。桌面现有实现沿用 v3.2 亮蓝品牌与三栏结构，通过组件外框、内部细分隔线和任务分组建立层次，首页与社区使用独立描边帖子卡片，公共帖子沿用服务端置顶数据。600px 以内的手机 Web 对照实际 Android App（601–860px 为窄桌面布局，侧栏收为图标），由 `src/mobile-app.css` 与手机组件实现暖白／青绿配色、五项底栏及各主入口。历史结构参考保留在 `web/reference/prototype-v3.html`。当前产物用于开发联调，发布状态以实际验收记录为准。

## 运行

正文 Emoji 使用同源打包的 [Noto Color Emoji v2.051](https://github.com/googlefonts/noto-emoji/releases/tag/v2.051) 彩色字体，按 Unicode 字素簇呈现，保留复制内容与组合表情；字体加载失败时退回系统彩色字体。字体只作用于 Emoji，中文、数字、标点沿用当前主题。浏览器资源为 `src/assets/fonts/noto-color-emoji-v2.051.woff2`，由上游 `fonts/Noto-COLRv1.ttf` 转为 WOFF2，保留 COLRv1 彩色字形；来源、校验值和复现步骤见该目录 README。OFL-1.1 许可随站点分发于 `public/licenses/NotoColorEmoji-OFL.txt`。移除 `inline-emoji.css` 的字体声明与对应字体资源即可退回系统字形，不影响已发布文字。

在仓库根目录执行：

```powershell
pnpm install
pnpm dev
```

访问 `http://127.0.0.1:5173/web/`。开发代理默认指向 `http://127.0.0.1:8080` 的本地 Go，包含 `/api`、资源和公开协议路径。本地 Go 未启动时页面保留网络失败与重试入口。需要其他受控联调环境时，显式设置 `$env:SYLULIVE_API_ORIGIN='https://你的联调域名'` 后启动；该值只接受不带账号、路径、查询参数的 HTTP(S) origin。显式指向生产会读取或写入真实业务，自动化测试继续固定使用 loopback 夹具，不把生产密钥复制到前端。

浏览本地页面期间保持 `pnpm dev` 运行；测试临时启动的开发服务会在测试结束时退出，不能代替日常开发进程。网络连接失败时，社区、集市和其他读取页显示中文说明与重试入口；重试保留当前搜索和筛选，不将故障当作空数据。

Playwright 启动前会读取开发服务的只读探针 `/web/__test-environment`，只有该进程确认 API 指向 loopback 才能继续；自动启动的服务固定指向本机 8080，复用连接生产的开发进程会被拒绝。探针仅在 Vite 开发服务存在，不导出上游地址或凭据；本地 Go 与测试数据库仍须使用可丢弃测试环境。代理集成测试使用独立依赖缓存，避免破坏正在运行的 Vite 页面。

需要在本地最新 Web 上连接线上服务器时，在仓库根目录的独立终端运行：

```powershell
pnpm dev:online
```

此时仍访问 `http://127.0.0.1:5173/web/`，账号登录及业务请求会通过代理连接真实服务器；表单保存、回复和治理操作会写入真实数据。`dev:online` 显式选择线上联调模式，已设置的 `SYLULIVE_API_ORIGIN` 仍优先用于自定义环境。普通 `pnpm dev` 继续连接本机 `8080`，需要先启动本地 Go；本地后端未启动时会返回 502。切换模式前先停止占用 `5173` 的旧开发进程。不要把 Playwright 自动启动的临时服务当作此联调进程；完整自动化继续使用隔离服务与夹具，避免与正在使用的 `5173` 联调进程共用。

## 手机 App 扫码同步

课表／成绩页面的「手机 App 扫码同步」显示当前网页账号、五分钟倒计时，可放大二维码或在「无法扫码？」复制同步链接交给App。复制和放大保留原会话，手机仍需核对并确认；不增加学校核验。网络暂时失败保留二维码并重试，过期、关闭、换码或切换账号会停止旧请求并作废会话。网页只接收在当前有效会话内成功解密的资料，解析／解密失败也立即清除中转密文。资料只在当前页面会话内，刷新后需重新同步。

## 登录与本机账号记录

登录面板提供账号选择、密码显隐、注册和找回密码。按表单选择在当前浏览器保留最近 5 个成功登录账号，邮箱大小写和首尾空格统一去重；密码须额外勾选「记住密码」，默认不保存。重新打开时可回填最近账号，历史账号中可逐条移除或清空。取消记住密码会移除该记录的保存密码，退出登录保留此前已选择保存的记录。

服务端返回登录冷却时，面板提供公开隐私页中的开发者联系方式，未登录也可查看并自行申诉；链接不传账号、密码或验证码。普通错误密码不显示冷却申诉提示。策略与恢复边界见[登录安全运维](../docs/ops/auth-security.md#普通登录密码容错)，浏览器验收入口为 `e2e/login-cooldown.spec.ts`。

记录位于本站 origin 的 IndexedDB `sylulive-login`。密码以 AES-GCM 密文与不可导出 CryptoKey 保存，不写入 localStorage／sessionStorage；不保存会话 Token，不同步到服务器。这是浏览器本机保存，不是操作系统凭据库，仍受同源脚本安全边界约束。清理可使用面板操作，或清除站点数据并刷新。本站密码与教务助手保存的学校密码分开管理。

存储不可用、配额不足或密码无法解密时可继续手动登录，不降级保存明文。修改本站密码或通过邮箱重置成功后清理能匹配到的旧保存密码，账号历史保留；清理失败会明确提示。历史记录移除优先于在途写回。验收入口为 `e2e/login-history.spec.ts` 与 `src/login-history.test.ts`，所有认证写入测试使用合成账号和本地接口夹具。

## AstrBot 授权、机器人与草稿确认

个人主页提供统一的「QQ 助手与社区机器人」入口。管理页内的「绑定我的 QQ」用于本人签到、成绩和二课，「管理社区机器人」用于设置、运行和社区授权。默认链接与旧连接码链接定位到本人绑定，`?purpose=bot` 定位到社区机器人。切换分类保留 URL 连接码，并清除尚未提交的授权表单。详细入口和授权规则见 [AstrBot 接入指南](../docs/ai/astrbot-connection-guide.md)。

顶部先核对当前账号的连接状态；读取失败显示状态未确认，不当作未绑定。携带连接码时优先展示新请求表单；否则展示有效连接和当前用途的权限。编辑只修改当前用途的权限，另一用途已批准的权限保留；完整权限可展开核对。当前两种用途仍复用同一执行端授权，替换或断开会撤销该连接全部权限，页面必须明确告知。历史默认折叠。断开响应不确定时只读核对一次，不自动重试写入，分别显示已断开、仍有效或结果未确认。

「社区机器人 → 接入教程 → 部署者工具与后台」提供「打开 AstrBot 插件管理」，在新标签页进入 AstrBot 4.29.3 的 `/#/plugin-view/astrbot_plugin_sylulive/permissions`，默认本机 `http://127.0.0.1:6185`，可填写其他后台 origin（仅当前页面使用）。只传固定页面路径，不传校园连接码、登录凭据或个人资料；登录继续由 AstrBot 负责。社区机器人入口中，已有连接缺少自动参与权限时可直接「补充机器人授权」，无需重新绑定；启用不会增加 scope，未核实所需授权时不显示「去启用」操作。插件管理仅配置消息入口，不替代校园账号本人授权。

站内完整教程可从「接入教程」或 `/web/connected-apps?guide=astrbot` 打开，未登录也可阅读；分别说明使用已部署机器人与部署者安装、模型、平台、开关、授权、启用和诊断步骤。教程源码文档为 [AstrBot 接入指南](../docs/ai/astrbot-connection-guide.md)。连接码是 AstrBot `/sylu-connect` 生成的短期一次性核对码；已有有效授权无需重复输入，后台是否实际运行以机器人启用状态和执行端心跳为准。

连接权限分为公开浏览、机器人自动参与和可选的本人查询／签到。可以点击「选择自动评论和发帖所需权限」补齐公开读取、草稿和两个独立发言权限，再核对并提交；不会连带选择成绩、二课或签到。写权限仍默认不选，快捷选择不会直接发送授权。当前服务使用有效登录直接核对和管理；兼容旧服务要求密码验证时，取消会中止在途验证并保留业务草稿，再次操作可重新验证。更换连接码后旧请求不能恢复旧确认内容；到期请求说明重新获取代码的入口。

机器人后台运行区通过本人 `/api/connected-apps/bot/runtime` 每30秒独立核验，显示离线／暂停／缺授权／运行／失败、最近浏览和服务端成功发言；失败保留表单草稿并将状态降为未知。后台任务属于常驻 AstrBot，不以网页开关推断正在执行；多账号运行与新版接口依赖见插件及运维入口。

机器人管理表单可新建暂停账号、编辑名字和本人上传的公开头像、保存公共阅读／自动文字评论／内置表情／自动发帖／公开配图权限、板块白名单、屏蔽词、禁链接及更严限频。创建与启用分开，保存后由服务端执行；独立连接scope及平台总开关仍须满足。发帖和配图默认关闭，旧评论选择不扩大权限；文字评论与发帖分别展示服务开关和授权结果。App 提供同等权限设置与原生设备授权入口，两端共用数据。社区作者旁显示服务端确认的创建者公开归属；无接口或旧服务不显示虚假成功。契约见 [API](../server/API.md) 与 [插件说明](../astrbot_plugin_sylulive/README.md#社区机器人账号管理)。

「社区机器人」提供一人一个独立 AI 机器人的创建、命名、启用和暂停。页面分别显示服务端自动评论开关与专用授权，启用账号不代表 AstrBot 后台运行。自动评论 scope 默认不选，须本人明确选择；不改旧授权。记忆只在本机 AstrBot 保存，群不进长期库，公共后台无法读取私聊记忆。

本人绑定不要求学校核验或预先连接教务。缺少学校资料只影响成绩／二课查询，可从 `/web/connected-apps?purpose=personal&view=data` 在网页准备并同步，不需要重绑 QQ，也不影响签到。本人绑定成功后回原 QQ 聊天用 `/sylu-status` 核对领取；`/sylu-checkin` 签到，`/sylu-checkin-status` 查状态，成绩和二课还需同步并授权对应摘要。绑定不会开启每日自动签到。`/web/connected-apps/actions/:id` 显示不可变草稿并由本人确认。提案、机器人自主评论和自主发帖权限默认不选，草稿仍须本人逐条确认；只有独立获准的机器人可自动参与。当前服务的核对、批准、机器人管理和本人确认发布均使用有效登录，不额外要求再次输入密码；旧服务返回 `recent_authentication_required` 时仍保留兼容验证，验证后必须重新核对，不自动重放创建、授权或发布。帖子来源或授权变化时，页面禁止发布并要求重读。

详见 [插件安装与本地配置](../astrbot_plugin_sylulive/README.md)。本地开发务必设置前述 `SYLULIVE_API_ORIGIN`，插件与 `INTEGRATION_PUBLIC_ORIGIN` 均指向本地网页 origin 5173。未启用后端新集成时，这些页面不会伪装成功。该入口不改变现有 Web/Flutter 校园 AI。

页面可预览并确认同步当前学期最小成绩和二课摘要，成功后仍需另行授权本人查询 scope。个人服务开关关闭、查询失败或旧服务时不可新增私有授权；删除只清对应同步副本，失败/退役不能报告已删除。切换账号或类型会取消旧预览确认，重复提交受控。App 原生授权同样将成绩、二课和发帖默认关闭，并根据当前服务端状态限制选择。反复验收入口见[完整测试清单](../docs/ai/astrbot-full-chain-test-checklist.md)，其中的跨运行时命令串联实际 Web、Go 与原生 AstrBot SDK，使用合成数据和确定性测试模型。

## 扩展安装与本机查询

```powershell
pnpm --filter @sylulive/extension dev
```

Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，目录为 `browser-extension/dist-dev`。生产域名使用 `browser-extension/dist`；生产包不注入 localhost。

维护者也可照常手工装载上面的目录；普通用户不必再自己找目录。页面检测不到教务助手时，连接弹窗与工具箱“教务连接诊断”会给出本站同源的安装包下载入口、SHA-256 校验值和自助安装步骤；用户在扩展管理页装载后，扩展会主动向已打开的站点标签页补注入握手脚本，页面自动复检并提示可以继续，不需要刷新。复检只确认通道建立，读取学校资料仍由用户点“连接并读取资料”触发。

该引导依赖 `web/public/assistant/`：本地 5173 用 `pnpm assistant:dev` 产出开发通道包，`pnpm build` 自动产出生产通道包。两个通道的授权域名不同，页面会拒绝在错误环境安装错误通道的包。0.1.1 起，扩展 worker 启动、重新启用和浏览器启动时会按 manifest 已允许的站点补回握手脚本；安装、更新与启动同时发生会合并执行，不新增学校域名权限，也不主动读取学校资料。真实 Chromium 的停用→启用→原页面免刷新握手见 `e2e/extension-reenable.spec.ts`。

在网站登录后，进入课表或成绩的“连接教务助手”。点击“连接并读取资料”后，新助手在缺少权限或学校会话过期时自动打开登录助手。首次需在扩展页授权学校域名，并输入学号、教务密码；二课分别输入 WebVPN 统一认证密码和二课系统密码。勾选“授权在此浏览器保存凭据”后，仅在学校身份核对成功时保存。后续会话过期再连接时，自动填写、经学校原按钮登录，成功后自动返回原网页并继续拉取本次选择的资料。只打开页面或完成安装握手不会自动读取资料。

验证码、滑块、学校拒绝登录和未知页面保留学校页人工处理，每次尝试的每一步最多自动提交一次；密码有误时可在助手页点击“修改登录信息并重试”，在同一任务中修正后重新登录，原网页继续等待。等待最长五分钟，可在网页或助手页取消；关闭发起页面、切换账号或重新连接后旧任务不能回填。研究生保留手动学校登录后自动返回；体测沿用独立 HTTP 风险确认和原有手动返回流程。

网页在开始读取前核对本站会话，access Cookie 过期时通过既有同源刷新接口恢复；等待学校登录途中会话过期也继续原任务。账号发生变化则停止。身份绑定请求携带 `X-Expected-App-User`，由服务端核对预期本站账号。助手只向网页回报固定进度阶段；每 1.5 秒发送的扩展内部心跳仅确认绑定助手页存活，不访问学校或本站网络，也不新增 `tabs` 权限。每次注入凭据前和完成登录时均核对任务及本站账号。

正方页面会重写原生数组方法，学校页注入脚本使用 NodeList 遍历，避免依赖页面改写后的 `Array.some` / `Array.find`。注入异常时改为提示手动登录，该阶段不反复填写；测试同时覆盖原生数组方法被学校脚本替换的环境。

凭据只在扩展 IndexedDB 以 AES-GCM 密文和不可导出的浏览器密钥保存，按站点、本站账号和学校系统隔离，关闭再打开浏览器后仍可使用；这不是操作系统安全凭据库。助手页可清除已保存凭据，损坏密文也可清除恢复；网页“断开并清除当前资料”同时清除当前系统凭据，卸载扩展也会清除。退出本站会取消本人任务并清除连接、资料缓存及提醒，保留曾明确保存的凭据，供同一本站账号再次登录后使用。取消、学校网络故障和资料读取失败不覆盖旧凭据或旧资料。密码、原始响应和学校会话不交给网站；本科与研究生使用账号配置接口登记学校类型和学号，登记用于试卷库等校内功能准入。

二课身份取自已登录系统的顶部栏 `top.aspx`，要求存在退出入口和唯一账号；成绩页不包含学号，不能用于身份识别。读取前后仍分别核对当前账号，顶部栏为空、登录过期或账号有歧义时保留原资料并要求重连，不读取完整个人档案来推测身份。更新已解压扩展的构建目录后，需要在浏览器扩展管理页重新加载，再回到网页重试读取。

个人资料默认保留在页面会话中。勾选“在此电脑保存”后，扩展 IndexedDB 才保存查询得到的结构化资料。课程提醒另行确认通知权限及本机保存，依赖浏览器运行；修改课表后需重新同步提醒。独立课程窗口不提供系统置顶。

## 认证链路的错误码与授权状态

扩展的回包 `error.code` 是可判定的分类，页面按分类给下一步动作，不再只丢一句文本：

| code | 含义 | 页面动作 |
| --- | --- | --- |
| `extension_unavailable` | 握手超时，本机没有助手 | 展示下载与自助安装步骤，自动复检 |
| `authorization_required` | 助手未获准访问该学校域名 | 提示打开助手页授权；次按钮变成“打开助手完成授权”，授权完成后免刷新自动恢复 |
| `school_login_required` | 学校登录过期或会话被踢 | 提示打开学校登录页后重试 |
| `site_login_required` | 站点账号已失效 | 先由同源网页尝试恢复会话；无法恢复时退回未连接，要求重新登录沈理校园 |
| `connection_stale` / `identity_changed` | 连接代次被接管或本机教务身份换了人 | 清空连接、退回第 2 步并提示重新连接 |
| `unsupported_query` / `invalid_argument` / `failed` | 该系统不提供该资料、参数无效、其他异常 | 原样展示消息 |

兼容性：`BridgeResponse.error.code` 仍是 `string`，`hello` 的 `connections`、`authorized`、`automaticLogin` 都是可选字段。旧扩展回的未知错误码按 `failed` 处理，读不到 `authorized` 时不为授权继续轮询。新助手 `connect` 可返回 `flowId`，网页仅对有此字段的任务使用新增 `loginStatus` 轮询；旧助手没有 `flowId` 时保留手动返回重试。旧页面仍可使用原来的连接命令。任务状态不包含凭据；扩展内部助手消息只接受绑定标签页的扩展页面，并再次核对本站账号和学校身份。

请求计数（本科、学校和本站会话均有效）：一次“连接并读取资料”= 网页本站会话预检 → `hello`（本地）→ `session`（站点 `account` + 学校身份页）→ 读取账号配置 → `query`（前置 `account`、前置身份核对、抓资料、后置身份核对、后置 `account`），完成登记后刷新本人资料；配置缺失时还要写入该配置，其中 3 次请求本科身份页。`hello` 会报告扩展已保有的连接代次和本机授权位（只读 `chrome.storage.session` 与 `chrome.permissions.contains`，不发任何网络请求），所以重开弹窗再点“查询并更新资料”需 6 次。过期会话另有刷新和登录等待请求；等待期间 `loginStatus` 每秒核对本站账号，助手每十秒及各注入/完成边界另行核对。`query` 内部的前后置核对一次都没有减少，账号被切换仍能在写入前检出。

课表拉取：默认学年学期由 `defaultAcademicTerm()` 按月份推导（正方以秋季起算学年，春季学期归属上一学年，直接取日历年份会在 2–8 月拉到上一学期）；JSON 接口返回登录页时按“重新登录”提示，返回坏数据时提示原资料已保留。学校对某学期返回空列表且本机已有非空课表或成绩时，页面拒绝替换，弹窗保持打开并说明原因，扩展侧仍照常记录快照。

明确未做的优化：身份结果的同代次 TTL 复用、成绩分页并发抓取、用课表响应自带的学号代替独立身份复核。

## 食堂详情与怀旧存档

用户侧食堂页面、组件、数据处理和局部样式放在 `src/canteen/`。路由入口见 `src/main.tsx`，独立后台页见 `src/admin-canteen.tsx`。数据规则测试沿用 `src/canteen-data.test.ts`，浏览器流程在 `e2e/`，构建与站点前缀见 `package.json` 和 `vite.config.ts`。

店铺详情由 `src/canteen/canteen-detail.tsx` 与限定范围的 `src/canteen/canteen-detail.css` 维护，沿用食堂主页的封面、评分和配色。详情优先展示接口返回的店铺封面、平均分、人数、就餐评价数和五项分数；缺失评分不编造默认值。评价使用共享图片预览组件，限定缩略图尺寸并支持失败重试、大图预览和原图入口，菜品保留独立加载、空态与失败恢复。分页请求在离页时取消，换店后不能回填旧评价。渲染和恢复验收入口为 `e2e/canteen-detail-ui.spec.ts`。

食堂页「怀旧食堂」单独展示下架存档，保留历史评分但不显示名次。超级管理员可在怀旧详情「维护怀旧食堂」修改名称和位置，保存失败保留表单。接口、只读权限和旧端兼容见 [食堂下架与怀旧存档](../server/API.md#食堂下架与怀旧存档)；定向验收入口为 `e2e/canteen.spec.ts`。详情页「管理店铺」为管理员提供营业店铺下架、永久删除入口；怀旧店铺的管理与恢复营业只向超级管理员开放，最终由服务端复核权限。下架需填写原因，删除需输入店铺名称，失败保留确认内容。操作成功后刷新相关列表，删除后返回店铺列表。

AI 页面布局由 `src/ai.css` 维护：历史列表独立滚动，长标题最多显示两行，回答与输入区分别占用明确空间；手机通过「历史会话」展开列表。布局改动保留原有会话读取、生成、停止与会话隔离逻辑，回归入口为 `e2e/ai-experience.spec.ts` 和上述渲染用例。

## 构建、测试与打包

```powershell
pnpm check
pnpm test
pnpm build
pnpm --filter @sylulive/extension dev
pnpm exec playwright install chromium
pnpm test:e2e
pnpm package
cd server
go test ./internal/handlers ./internal/middleware ./internal/ai
```

`artifacts/web-build/` 包含静态网站、生产扩展、开发扩展及 Windows 下生成的 ZIP。包为联调候选包，不表示学校链路或商店审核通过。扩展发布前还需按实际商店补齐展示素材与隐私披露。

`pnpm package` 会额外写出 `artifacts/web-build/BUILD_INFO.json`：产出提交号、分支、工作树是否干净，以及三棵子树的确定性摘要和 ZIP 的 SHA-256。部署前用它核对「发布物就是待部署提交」：

```powershell
node scripts/package-web.mjs --check <待部署 SHA>   # 或设置 RELEASE_SHA
```

校验会同时比对提交号与磁盘内容摘要，任一不符即失败退出。工作区有未提交改动时打包默认拒绝，确需打实验包用 `ALLOW_DIRTY_RELEASE=1`，此时 `BUILD_INFO.json` 记录 `dirty: true`，不得作为发布物。

## 部署

生产发布在仓库根目录执行一条命令（需已配置服务器 SSH 公钥，且 Web 相关目录无未提交改动）：

~~~bash
scripts/deploy-web.sh            # 构建当前 HEAD 并发布
scripts/deploy-web.sh status     # 查看线上版本与可回滚版本
scripts/deploy-web.sh rollback   # 切回上一版本
~~~

脚本在本机执行 check、单测和构建，把 `web/dist` 打成只含 `web/` 的包上传；服务器端 [deploy/deploy-web](../deploy/deploy-web) 解压到 `/var/www/sylulive/releases/<SHA>/`，保留上一版带哈希的 JS/CSS（已打开的页面不白屏），原子切换 `/var/www/sylulive/web` 链接。随后只做最小冒烟：公网 `/web/` 首页即本次版本，且其引用的 JS/CSS 可取到；失败自动切回并删除失败版本。保留最近 5 个版本。不触碰 Nginx、官网首页和后端进程。浏览器 E2E 不在脚本内，按发布风险另行执行。

首次部署新站点时，将 `web/dist/` 内容放到现有站点 `/web/`。参考 `web/deploy/nginx.conf` 合并到原 HTTPS server；保留官网及分享路由，API 与附件使用同源代理，SSE 关闭缓冲。新增收藏和个人 AI 分析需要同时发布本仓库 Go 修改；仅更新静态页面不会让线上旧服务具备新接口。

发布后请确认 `/web/assistant/assistant.json` 真的以 JSON 返回（例如 `curl -I https://<站点>/web/assistant/assistant.json` 看 `content-type`）。`web/deploy/nginx.conf` 的 `try_files` 会把缺失文件伪装成 200 + `index.html`，此时页面只会提示“本站暂无可用的教务助手安装包”，不会显示下载按钮。

## 验收边界

图文发帖在首页、社区、手机与集市入口进入独立单页 `/web/compose`（集市 `?board=2`），旧帖编辑使用 `/web/post/:id/edit`。顶部直接确认分区或发布类型；标题、正文与图片按单列填写，集市交易字段位于内容下方。正文自动增高，提供编辑/预览、分区状态、按需添加图片及粘贴/排序；操作栏紧接内容，长文时保持可达，返回保留来源筛选和阅读位置。桌面评论原地展开，楼中楼在对应评论下回复，表情和图片从工具栏按需打开；收起保留本页草稿，Ctrl/Cmd+Enter 发布，手机保留输入弹框。草稿仅保留在当前标签页内存，站内返回后重进可继续，刷新/切号清除；编辑新增图片会与保留原图共同提交。上传失败保留选择和成功编号；发布结果不确定，或发送后通过浏览器后退离开时，重开先核对“我的发布”，不会自动重放。功能边界见[发帖与草稿契约](../docs/design/post-composer-contract.md)，验收入口为 `web/e2e/post-composer.spec.ts`、`web/e2e/comment-composer.spec.ts` 和 `web/src/media-upload.test.ts`。

`web/e2e/experience-audit.spec.ts` 以用户操作检查快捷搜索的焦点、方向键与回车、六个列表的搜索历史回填、手机资讯搜索保留列表视图、结构化校历与旧图片返回的兼容，以及地图失败后的恢复。校历沿用服务端返回的学期、教学周、事件和调课规则，不以只有学年标题表示已展示完整内容。

`web/e2e/ai-experience.spec.ts` 检查历史会话的迟到响应隔离、新建会话清理来源、创建等待与已创建运行的停止恢复、重复提交及账号切换。创建结果尚未返回时只能停止本页等待，页面会明确要求从历史核对服务端结果，不报告运行已取消。这些写入与事件流使用本地合成夹具，不代表真实学校或真实模型端到端验收。

已运行的自动化包括共享数据校验、解析与提醒计算、SSE 分帧、课表编辑及冲突、主要路由和移动导航，以及真实 Chromium 扩展加载和握手。Go 测试覆盖收藏、Origin 校验与个人 AI 授权/用量等边界。`web/e2e/assistant-install.spec.ts` 覆盖未装助手时的下载引导与安装步骤、装好后不刷新自动复检（并断言此间不发起学校查询）、以及安装包缺失或通道不符时的降级；`web/src/assistant-package.test.ts` 和 `browser-extension/src/inject.test.ts` 覆盖包清单校验与补注入的站点计划。

尚未完成真实账号的发布—审核—通知回读，以及本科、研究生、二课、体测四种学校来源的登录查询验收。Chrome/Edge 的重启、升级、多账号和系统通知还需实机验收。18 个页面的固定数据视觉对照也尚未全量完成，不能用路由冒烟代替。

教务助手引导交付的是解包（开发者模式）安装：真实 Edge 上“下载—解压—加载已解压扩展—页面免刷新复检”的完整链路、浏览器周期性提示或暂时停用非商店扩展的表现、以及更换解压目录导致扩展身份变化后本机资料需要重新读取，都只能人工验收。长期方案是发布到 Edge Add-ons 或 Chrome Web Store，目前尚未提交审核。

校园地图已复用 App 资源；食堂贡献列表、实拍、审核原因及评价编辑保留关联资料已接入；管理端已增加用户、版块、公告、版本、日志和 AI 指标入口。这些接口接入仍需真实账号验收，不能视为发布—审核—回读全链路已通过。

学业页已展示分模块学分要求、课程明细和本地缺口检查，切换栏目保留本次查询结果并标注来源及时间；毕业检查仅覆盖已返回的学分模块，不替代学校最终结论。

完整方案中仍需补齐的业务包括校园电话/办事指南、食堂治理细项、部分竞赛推荐与偏好、更完整的成绩详情及毕业条件覆盖等。当前已有页面及 API 接入不等于这些子流程全部完成。
