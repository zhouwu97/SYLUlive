# 试卷库界面优化设计

## 1. 背景与目标

当前试卷库已具备检索、筛选、投稿、个人投稿管理、管理员审核、预览和下载能力，但四个页面的信息密度与状态反馈不一致：筛选区占用首屏较多，空状态缺少下一步动作，投稿流程缺少阶段感，个人投稿与审核列表的处理效率偏低。

本次采用已确认的 **A 方案：紧凑工具栏**。目标是在不重构服务端领域模型的前提下，提高以下核心任务的完成效率：

1. 用户输入课程名并快速定位试卷。
2. 用户选择 PDF、确认合规信息并完成投稿。
3. 用户理解投稿状态并处理可操作事项。
4. 管理员快速识别待办并进入审核。

非目标：课程分类体系、推荐算法、收藏、评分、OCR、自动隐私识别。这些能力需要新增数据或服务，不纳入本轮。

## 2. 设计原则

- **内容优先**：首屏优先展示试卷结果，不设置欢迎语或营销区。
- **紧凑但可触达**：搜索框高 44 px，筛选控件高 36 px，主要按钮高 48 px，触控区域不小于 44×44 px。
- **状态可行动**：空状态、失败状态和审核状态都提供明确的下一步操作。
- **能力真实**：只展示现有接口能够准确支持的数据；分页数据不得用前端局部结果冒充全量统计。
- **沿用现有系统**：继续使用 Flutter Material 3、NotoSansCJKsc、`AppTheme`、`GlassContainer` 和 `ExamPaperCard`，不建立第二套主题。

## 3. 统一视觉规范

### 3.1 色彩与形状

- 页面背景沿用暖白；内容面保持白色或主题 `surface`。
- 主色 `#6366F1` 仅用于选中态、主按钮、关键进度和链接。
- 状态色：待审核使用琥珀色，已通过使用绿色，已下架使用灰色，危险操作使用红色。
- 工具控件圆角 8–12 px，内容卡片圆角 12–16 px；不继续扩大到 20–24 px。
- 边框替代重阴影；页面区块不包装成悬浮大卡片，不嵌套卡片。

### 3.2 字体与间距

- AppBar 标题 17 px / 600。
- 试卷标题 16 px / 700，最多两行。
- 正文 14 px；辅助信息与标签 12 px。
- 页面水平边距 16 px，卡片内边距 14–16 px，列表间距 8–10 px。
- 不使用随视口缩放字号，不使用负字距。

## 4. 页面设计

### 4.1 试卷库

顶部由搜索框、横向筛选行和结果摘要组成。搜索提示改为“搜索课程名或关键词”。筛选依次为学年、学期、类型和排序，保持当前接口字段不变；每次变更仍触发刷新，搜索继续使用 420 ms 防抖。

结果摘要展示接口返回的 `total`，格式为“共 N 份试卷”；存在筛选时展示“筛选 N”和“清除”。为此页面状态需保留最近一次 `ExamPaperPage.total`，不能使用当前已加载列表长度代替总数。

`ExamPaperCard` 调整为三层：

1. 首行突出课程名，右侧只在投稿管理和审核场景显示状态。
2. 第二行展示学年、学期、考试类型三个弱标签。
3. 末行展示投稿者、下载量和日期。

公共试卷库中的条目均为已发布内容，因此不重复显示“已通过”。整卡进入详情，右下角保留紧凑“投稿”扩展按钮。

### 4.2 投稿试卷

页面按“填写信息 → 选择文件 → 隐私确认 → 提交”的顺序组织。顶部步骤指示仅反映本地完成度，不引入多页向导，避免增加跳转成本。

课程名、学年、学期、考试类型沿用现有字段。标题预览保留，但作为紧凑只读区域，不再使用独立大标题。选择文件后显示文件名、大小以及格式/大小校验结果。

提交按钮固定在底部安全区上方，并根据条件提供明确状态：

- 缺少课程名、PDF 或隐私确认时禁用。
- 上传中显示百分比并禁用返回前的重复提交。
- 上传失败保留表单、文件和勾选状态，页面内提示错误并允许重试。
- 管理员直接发布与普通用户待审核的结果文案保持区别。

### 4.3 我的投稿

P0 先优化卡片状态表达：待审核显示“管理员审核中”，已通过显示“已收录至试卷库”，已下架显示 `unpublishReason`。待审核提供“预览”和“撤回”；已通过进入详情；已下架提供“重新投稿”入口时应预填元数据，但仍要求重新选择本地 PDF。

“全部 / 待审核 / 已通过 / 已下架”分段筛选列为 P1。当前 `mySubmissions` 是分页接口且没有 `status` 参数，不能仅筛选已加载页面。服务端增加状态过滤和各状态计数后再启用该控件。

### 4.4 审核管理

保留“待审核 / 已发布”双 Tab。P0 改进空状态、错误状态、卡片层级和下拉菜单文案；管理员仍通过编辑页完成元数据确认，避免在列表中误触发布。

P1 在服务端支持查询条件后增加课程名/投稿人搜索与排序。快捷“通过”仅在审核规则允许使用原始元数据直接发布、且具备二次确认时启用；“退回”必须填写理由。否则列表只提供“预览”和“审核”，不伪造一键操作能力。

## 5. 状态与错误处理

- **首次加载**：使用 3 个固定高度骨架卡片，避免加载完成后的布局跳动。
- **下拉刷新**：保留当前内容，使用刷新指示，不整屏清空。
- **加载更多失败**：保留已加载数据，通过 Snackbar 提供“重试”。
- **刷新失败且已有数据**：列表顶部展示内联错误条；只有无缓存数据时才使用整屏错误状态。
- **无搜索结果**：展示当前关键词/筛选摘要，提供“清除筛选”和“投稿这门课试卷”。
- **库为空**：提供“投稿第一份试卷”。
- **个人投稿为空**：提供“去投稿”，并说明普通投稿需管理员审核。
- **审核为空**：待审核显示“当前没有待处理投稿”；已发布为空时允许重置筛选。
- **危险操作**：撤回、退回、下架均二次确认；完成后原地更新或移除卡片。

## 6. 组件边界

建议在 `client/lib/widgets/exam_papers/` 下建立领域组件，避免四个页面重复状态样式：

- `exam_paper_toolbar.dart`：搜索、筛选、结果摘要、清除操作。
- `exam_paper_list_card.dart`：通过 `variant` 区分公开库、我的投稿、管理员审核，基础信息布局保持一致。
- `exam_paper_status_badge.dart`：统一状态颜色与文案。
- `exam_paper_empty_state.dart`：统一空状态图标、标题、说明和主次操作。
- `exam_paper_list_skeleton.dart`：固定尺寸列表骨架。
- `exam_paper_upload_step_header.dart`：根据表单状态计算完成步骤，仅负责展示。

页面继续拥有数据请求、分页、导航和提交逻辑；组件不直接依赖 `ExamPaperService`，通过值与回调通信，便于 Widget 测试。

## 7. 实施优先级

### P0：纯前端可完成

1. 收紧试卷库工具栏与卡片密度，展示真实 `total` 和筛选计数。
2. 补齐列表骨架、保留内容的错误提示、可行动空状态。
3. 重排投稿表单，增加本地步骤状态、文件校验反馈和底部固定提交按钮。
4. 强化我的投稿卡片状态、原因和操作。
5. 统一审核页的状态、空态和操作文案。
6. 抽取试卷领域组件并补充 Widget 测试。

### P1：需要接口配合

1. `my-submissions` 支持 `status` 参数并返回各状态计数。
2. 管理列表支持关键词、投稿人、排序参数。
3. 评估审核快捷通过接口或复用当前审核接口时的元数据确认规则。

### P2：数据验证后再决定

根据搜索无结果率、筛选使用率、投稿完成率和平均审核时长，评估搜索建议、最近搜索和课程别名，不预先建设课程分类体系。

## 8. 测试与验收

### 8.1 Widget 测试

- 搜索防抖、筛选刷新和乱序请求保护继续通过。
- `total` 与筛选计数正确，清除后恢复默认条件。
- 有旧数据时刷新失败不会清空列表。
- 空状态主按钮能进入投稿页并按条件预填课程名。
- 投稿按钮仅在课程名、有效 PDF、隐私确认均完成时启用。
- 上传失败后表单与文件状态保留，上传中不会重复提交。
- 待审核投稿允许预览和撤回；已下架正确展示原因。
- 暗色模式、320/360/412 px 宽度下无溢出、遮挡和横向抖动。

### 8.2 验收指标

- 390×844 逻辑像素下，试卷库首屏至少完整展示 2 张试卷卡片。
- 搜索到筛选结果的主要控件均在首屏，无需滚动。
- 所有可点击控件触控区域不小于 44×44 px。
- 筛选、刷新、加载更多和上传操作均有加载、成功、失败三态。
- 公开列表不显示冗余“已通过”；个人与管理列表状态颜色和文案一致。
- 固定底部按钮不遮挡最后一项内容，列表底部预留安全区。
