# ADR 005：声明式主题包与免费主题商城

- 状态：accepted
- 日期：2026-11-16
- 决策依据：维护者参考 SukiSU-Nova 主题商店后确认了以下事项：
  - 所有登录用户都可投稿主题，审核通过即上架，商城展示作者名；
  - 主题可携带图标；
  - 首批官方主题先通过商城下载提供；
  - 鸿蒙端暂停更新，不做适配；
  - 首批主题化页面覆盖首页、集市、课表、校园、我、个人主页、AI 助手、工具箱和设置；
  - 2026-11-16 补充：桌面启动图标、桌面小部件配色和自定义字体也纳入主题范围。
  - 2026-11-17 补充：先维护一套 UI 组件风格，在这套风格内提供完整主题能力，并增加页头布局、卡片样式、图片效果和贴纸编辑；新增能力从 P1 开始实现，不扩大 P0 的颜色迁移范围。
- 实施入口：[主题商城实施计划](../theme-store-plan.md)、[格式契约](../theme-pack-contract.md)、[制作与审核细则](../theme-creation-guide.md)
- 风险等级：本机主题包与工坊为 R2；商城投稿、审核、公开资源与新接口为 R3。本 ADR 不授权推送、部署或生产迁移。

## 背景

SukiSU-Nova（`c60f21b`）的主题是应用外观设置的快照：一份可空字段的 `theme.json` 加上按固定条目名存放的图片，作者在 App 内调好外观后一键导出，旧客户端遇到新格式整包拒绝。本项目沿用"主题 = 外观数据"的思路，去掉其无安全价值的内置密钥加密。

本项目的配色目前写死在 `AppColors` 常量和约 1267 处颜色字面量中，主题化的前提是把目标页面迁移到语义 Token。

## 决策

### 1. 主题是声明式外观数据

主题包只包含白名单内的外观值、内置布局模板的选择与参数、图片资源和字体文件，不含脚本、任意组件树、着色器或外部 URL。客户端忽略未知字段。

主题包含：

- `light`／`dark` 两套配色：种子色、语义 Token 覆盖值、课表课程色板；
- 圆角档位（紧凑／标准／圆润）；
- 壁纸：全局竖屏／横屏壁纸，以及首页、课表、我三个页面的独立壁纸，附带填充、模糊和遮罩；
- 组件透明度、毛玻璃强度、底栏样式；
- 同一套组件风格内首页、校园、我三个页头的标准／紧凑／沉浸模板、图片区尺寸和对齐；
- 卡片描边宽度和阴影档位（卡片圆角统一由 `shape` 档位控制）；页头背景图与可移动、缩放、旋转的装饰贴纸；
- 壁纸和页头背景图的亮度、对比度与饱和度（渲染时使用颜色矩阵：Flutter 用 `ColorFilter.matrix`，网页用 CSS `filter`）；
- 底栏五个页签的自定义图标（常态与选中态）；
- 自定义字体：常规体，可选粗体，只替换正文字体；
- 桌面启动图标：
  - 可以切换到随安装包内置的备选图标，Android 和 iOS 都支持；
  - 也可以在 Android 上用主题自带的图片添加一个桌面快捷方式。系统只允许切换到预先打包的图标，下载来的图片不能替换 App 本身的图标，所以采用"多加一个快捷方式"的方式；
- 桌面小部件配色：小部件选择"跟随 App 主题"时，由当前 Token 映射得到（Android 课表与考试小部件、iOS 课表小部件）；
- 名称、简介、标签、许可和预览图。

主题不包含：

- 字号与文字缩放；
- 启动页、预测返回等行为偏好；
- 界面文案替换；
- 状态语义色（成功、警告、危险、信息），以保证状态含义一致；
- 账号、学校和任何个人数据。

切换桌面启动图标和添加桌面快捷方式，都会改动系统桌面。所以在导入页里，这一组默认不勾选；用户勾选后，由系统弹窗再确认一次。

### 2. 语义 Token 与受控的组件参数定义主题能力

新增 `ThemeExtension` 语义调色板，`AppThemeTokens` 改为从当前主题读取。首批迁移页面：首页、集市、课表、校园、我、个人主页、AI 助手、工具箱、设置，以及它们使用的共享组件（底栏、帖子卡片、集市卡片、首页服务抽屉、设置组件、校园组件）。未迁移页面保持默认配色。Token 名称是包格式契约，只增不改。

只维护现有的一套组件、导航和交互语义。布局模板复用这些组件，不增加 Miuix／Material 等 UI 风格分支。主题可调整参数及装饰槽位以格式契约第 2.7–2.9 节为准；装饰不能遮挡真实内容、拦截触摸或替换他人的个人封面。

“完整”指九个首批页面及其共享弹层、输入区、加载、空态、失败和权限状态均能跟随适用的主题参数，并且同一份配置贯穿工坊、导出、导入、全局试用、应用、重启恢复、回退、投稿审核和商城下载。范围外页面及原生系统界面的边界在实施计划验收矩阵中明示。

### 3. 包格式

- 文件后缀为 `.sltheme`，内容为明文 ZIP：`manifest.json` 加图片。manifest 写入明暗两套的完整 Token 值，因此服务端和 Web 端不需要实现配色推导。
- 完整性：商城目录记录规范包的 SHA-256，客户端下载后核对一次。包内条目逐个校验 ZIP 格式自带的 CRC32；项目固定的 `archive` 4.2.0 解码器不会自动做这一步，需要显式调用。manifest 不记录逐个资源的哈希。
- `formatVersion` 超出客户端支持范围时整包拒绝；`minAppVersion` 不满足时提示升级。
- Dart 与 Go 按同一份[格式契约](../theme-pack-contract.md)实现，使用同一组错误码。

### 4. 本机导入、试用和回退

- 系统文件打开、App 内导入和商城下载走同一条校验与安装路径。导入不上传任何内容。
- 应用前展示明暗预览，可以按组勾选：配色、壁纸、材质与卡片、底栏与图标、圆角、布局、页头装饰、字体、桌面小部件、桌面启动图标。其中桌面启动图标默认不勾选。
- **当前外观保存为一份完整配置**，记录每个分组最终生效的值：
  - 应用主题时，把勾选分组的值合并进这份配置；
  - 用户手动修改时，直接改写对应分组；
  - 主题 ID 和版本只用来标记来源和提示更新，不用来在启动时重新拼装外观。
- 只保留"上一个外观"一份记录，可以一键恢复，也可以恢复默认。
- 主题安装目录按版本区分。被当前外观或上一个外观引用的版本和图片会保留，不再被引用时才清理。
- 试用是一个全局会话：试用期间顶部常驻"试用中"横条，可以在任意页面之间切换。点"结束"或重启 App 后，回到试用前的外观。商城用户试用和审核员试用使用同一套机制。
- 主题文件存放在应用私有目录，属于设备级偏好。

### 5. 投稿与上架

- 所有登录且账号状态正常的用户都可投稿，不需要申请创作者权限。投稿频率由配额限制。
- 每个作品及每次更新单独审核，审核通过即上架；未投稿或未通过的主题仍可作为文件在本机之间分享和导入。
- 商城展示作者昵称，并链接到作者个人主页。
- 投稿记录不可变，`family_id` + `version` 管理版本。
- 每个作品同一时间最多只有一个上架版本；新版本通过前，继续提供旧版。
- 某个版本审核通过时，比它旧的待审版本自动标记为"已被新版本取代"。
- 审核、撤回、下架都先锁住作品的根记录。
- 管理员不能审核自己的投稿。
- 下载地址固定到具体版本：同一个版本的大小、哈希和文件永远不变。
- 服务端解包校验，所有图片重新编码并去除元数据，然后重新打包生成规范包。客户端下载的是服务端规范包，并用目录中的 SHA-256 核对一次。
- 全部免费。不上架成人内容。举报复用现有举报流程。下架停止后续下载，不远程删除已安装副本。

### 6. 官方主题

首批官方主题由维护者账号通过商城投稿上架，标记为官方来源，先走下载；后续再选择性内置到客户端。

内置默认外观在 Token 化时保持像素不变。它的亮色 `textSecondary` 在白色卡片上的对比度是 4.29、亮色 `tagText` 在 `tagBackground` 上的对比度是 4.47，达不到商城要求的 4.5，因此不受商城对比度检查约束。官方主题"沈理青"把亮色 `textSecondary` 改为 `#6E757C`、亮色 `tagText` 改为 `#107A70`，作为有意的视觉变化单独验收。

### 7. 平台范围

Android、iOS、桌面端和宽度 600px 以下的移动网页支持应用主题；Web 端把 Token 映射为 `web/tokens.css` 的 CSS 变量。鸿蒙端暂停更新，不提供主题入口。

## 未采纳的方案

- **加密主题包**：内置密钥无安全价值，还妨碍审核和排错。
- **界面文案替换**：登录、教务和安全中心等入口有被伪造文案误导的风险。
- **双套 UI 风格、代码或任意布局级主题**：本期只维护一套 UI；允许白名单内的模板和参数，不开放执行代码或替换任意组件树。
- **投稿前申请创作者权限**：主题风险集中在图片内容，逐件审核已能覆盖，申请环节只会增加门槛。
- **成人内容开关、付费主题**：与校园场景和免费原则不符。

## 回退

主题叠加在内置默认外观之上，关闭主题功能开关或"恢复默认外观"即可回到现有视觉。商城侧通过下架停止后续下载，已安装副本保留在本机。
