# 沈理校园 AI 助手 v4.1 P0 实施说明

本分支按 v4.1 最终冻结补丁完成 P0 基础设施，并完成 P1 运行时、P2 RAG 的首个可部署闭环。AI 启用后向所有已登录用户开放；课表 Skill 的确定性核心已实现，但由于当前校历仍可能是 v1，生产开关保持关闭。

## 安全边界

- `AI_ENABLED=false` 是默认总开关。
- AI 接口统一要求登录，不再按用户白名单或管理员角色区分访问权限。
- `AI_API_KEY` 仅从 Go 服务进程环境变量读取，不进入客户端、请求体、日志或健康响应。
- 体测密码从旧版明文偏好存储一次性迁移到 Secure Storage；安全写入成功后才删除旧值。
- `python-edu-service` 保持零改动。凭证加密与内部认证继续由 `services/security.py` 提供。

## 数据库准备

在独立 PostgreSQL 测试库先执行：

```bash
psql "$DSN" -f server/sql/20260719_ai_runtime_rag.sql
psql "$DSN" -f server/sql/20260719_ai_privacy_quota.sql
```

首个迁移安装 `vector`、`pg_trgm` 扩展并创建知识文档、1536 维向量分块、管理审计、运行时、配额和计量表；第二个迁移解除配额账本到 Run 的外键，确保删除会话不能重置滚动限额。设置 `PGVECTOR_TEST_DSN` 后运行 `go test ./internal/models -run TestPGVectorMigrationIntegration` 可执行独立集成验证；未设置时测试会明确跳过。生产启动前会只读核验表、扩展、索引和配额约束，不再用 AutoMigrate 改写这些对象。

默认向量模型版本为 `paraphrase-multilingual-minilm-l12-v2-384-v1`。FastEmbed 的真实 384 维结果通过 LangChain `Embeddings` 返回，模型名、版本与维度写入注册表和影子向量表；禁止补零、截断或静默混用。历史 `padded-1536` 数据只按原版本标识保留用于回滚，不得登记为新的真实维度模型。

## 校历与课表

- `schema_version=1` 继续兼容读取和展示，但课表映射固定返回 `data_unavailable`。
- `schema_version=2` 的每个学期必须显式提供唯一的 `edu_semester_code`，允许值只有 `3` 或 `12`。
- 日期、教学周和相对日期统一使用随 Go 程序携带的 IANA `Asia/Shanghai` 时区数据。
- Go 侧只读现有 Python 课表缓存接口，不修改数据库、登录、Cookie、Session 刷新或课表抓取流程。
- P0 健康响应会报告 AI 开关、课表 Skill 状态和时区；课表 Skill 保持关闭，待 P3 发布并核验 v2 当前校历后再启用。

## 知识库管理

统一前缀为 `/api/admin/ai/knowledge`。管理员可导入、列表、读取、检查和请求重建索引；发布、撤销、替代动作在 Handler 内再次要求 `super_admin`。

所有管理审计的用户 ID 与角色来自认证 Context。无请求体的动作拒绝任何请求体；替代动作只接受 `replacement_document_id`。CLI 通过环境变量 `SHENLIYUAN_ADMIN_JWT` 携带短期管理员 JWT，例如：

```bash
shenliyuan-ai-kb publish --document-id 18
```

## 部署配置

参考根目录 `.env.example` 设置 AI 配置。启用的最小配置为：

```dotenv
AI_ENABLED=true
AI_PROVIDER=openai-compatible
AI_API_KEY=<server-secret>
AI_BASE_URL=<openai-compatible-gateway>
AI_CHAT_MODEL=gpt-5.4
```

正式部署前还需由运维注入真实密钥，并在 P3 发布至少一份无待确认项的当前 v2 校历。当前生产已完成数据库备份、两步迁移、RAG systemd 服务和 Go 服务部署；访问范围由 `AI_ENABLED` 总开关统一控制。
