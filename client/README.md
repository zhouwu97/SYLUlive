# 沈理校园客户端

这是 SYLUlive 的 Flutter 客户端，负责校园 App 的界面、账号交互、社区功能，以及逐步迁移到设备侧的个人教务访问。

## 客户端边界

- App 账号、社区、竞赛、通知和反馈通过 Go 服务端访问。
- 个人教务访问优先由客户端直接连接学校系统，并通过设备安全存储保存本地会话和缓存。
- 学校密码、Cookie、个人教务 HTML 和原始会话不得写入服务端日志、远程 AI、MCP 或普通业务接口。
- 迁移期旧 `/api/edu/*` 能力可能返回 `410`；客户端应遵循能力探测结果，不应反复调用已退役接口。
- 手机已连接教务而服务端账号配置缺失时，完整查询确认缺失后自动通过 `/api/academic-account-configs` 补登记学号与教务类型，包括曾同步成功后记录缺失的情况。已有云端解绑、不同学号、版本冲突或账号切换时不自动覆盖；登记不授予可信学生身份权限。

## 扫码同步到网页

在课表设置进入「扫码同步到网页」，支持相机、相册和粘贴网页同步链接。手机先核对与网页相同的本站账号，再读取本机已有资料，由本人选择后发送；不要求重新登录学校系统。拒绝相机权限仍保留相册和链接入口，恢复前台时恢复扫描。上传网络失败或服务繁忙保留选择，重试复用同一份密文；已接收的内容不能替换。切换本站会话（含同一账号重新登录）、改变学校来源或离页阻止旧流程发送。

显式本机跨端联调：先构建 Web并在127.0.0.1启动preview，再设置 `QR_CHAIN_WEB` 和 `QR_CHAIN_FLUTTER`（Flutter可执行文件路径），从server运行 `go test ./internal/handlers -run '^TestAcademicTransferWebAppChain$' -count=1 -v`。该链路使用真实网页密钥、Flutter加密和HTTP、Go内存中转与网页解密导入，账号为隔离合成夹具，不请求学校、生产服务或真实手机相机；相机识别与权限的最终硬件验收另行记录。

## 课表与考试存档

- 课表菜单进入「课表设置 → 课表显示」可调整课程块字号（80–150%）、文字颜色和课程块颜色，设置保存在本机。默认字号为 100%，继续沿用当前屏幕宽度适配；默认颜色跟随当前主题并按课程配色。应用主题配色后，颜色选项同步为跟随主题，后续手动改色会写入当前外观；重新应用主题重置颜色，恢复上一个外观可撤回。自选课程块颜色统一用于本周课程，非本周灰底和冲突橙色提示保留；恢复默认值会同时重置字号、颜色、透明度和每节课高度。
- “调整课程安排”先选择原周次，再选择目标起始周、星期和节次；整段提前或延后时保持单双周和离散周次的间隔，目标周次不能超出本学期。
- 调课确认页同时展示原安排和新安排。目标位置已有同一课程且时间完全相同的教务原安排时，可勾选合并；不同课程、部分节次重叠和已有本地调整继续提示冲突。恢复原安排会撤销这条调课及其合并效果，不修改教务原始快照。
- 课程详情的“删除课程”只删除本机所选周次的这次上课安排，支持单周和范围；删除已调课安排时保留其他周次的调整，合并显示的原安排一并删除并分别保留恢复记录。课表菜单“已删除课程”可恢复教务原安排。源安排未变时，重启和重新拉取保留本地删除；学校安排变化后暂停删除并要求重新确认，载入存档沿用原有规则替换行为。周次范围可早于当前周，结束周提前时自动收拢开始周；继续调整保留原有离散周次。
- 本机课表刷新传递学校真实学期 ID；本科兼容学期码保留 `3/12`，研究生使用学校返回的 ID。
- 桌面小组件的手动换色与主题包同步按操作顺序保存并刷新，后选的配色生效，未完成的旧同步不会覆盖新选择。刷新失败时选项按已保存设置回显；手动同步的写入和刷新失败会明确报错，保留重试入口。
- 用户点击课表“保存当前课表为新存档”时，同时保存 App 内存档和公共 JSON 副本；已有 App 内存档可点击导出补写公共副本。
- Android 10 及以上通过 MediaStore 保存到 `Download/沈理校园/课表存档/` 或 `Download/沈理校园/考试存档/`；Android 9 及以下由系统文件选择器选择保存位置。
- iPhone 和 iPad 通过系统「文件」选择器选择位置。取消后可从课表存档或考试页重新导出。
- 公共文件导出失败会明确提示重试，已保存的 App 内课表仍保留。公共副本由用户在文件管理器删除，卸载、退出账号或删除 App 内存档不会自动清理它。
- 考试日程页面维护本地考试安排，支持手动添加和 JSON 导入/导出；该页当前不提供从学校获取考试安排的入口。

## 互动消息

- 在“我的 → 收到的赞”查看点赞者、点赞时间与原帖；评论点赞可定位到对应评论。列表包含历史有效点赞，支持刷新、分页和失败重试。
- 回复提醒使用首页未读入口与系统通知。成功定位目标回复后只消费该回复的通知；已读状态同步到 Android，清理对应系统提醒并拦截延迟推送。
- 新回复通知使用独立高优先级渠道；关闭系统权限或单独关闭该渠道时不会绕过用户设置。

## 反馈工单

- 登录受限弹窗的「向开发者申诉」无需登录，展示 `AppContacts` 中已有公开联系方式与本次提交账号，支持复制申诉信息；用户自行联系开发者人工核查，复制失败可长按选择文字。普通密码错误仍可立即重试。冷却策略与恢复边界见[登录安全运维](../docs/ops/auth-security.md#普通登录密码容错)。
- “我的 → 服务与支持 → 创建工单”可直接反馈 Bug，默认选择问题反馈，也可切换为功能建议或其他类型；支持补充复现信息、截图及可选设备诊断信息。
- “我的工单”可查看处理进度、管理员回复并补充信息，入口保留未读回复角标。未登录时点击这两个入口会先进入登录页。
- 工单更新集中在“我的工单”与管理员的“工单管理”，不进入通用通知列表或通用通知红点。管理员入口按本人未读工单会话数显示角标，工单卡片显示该会话未读消息数；待处理数量继续在摘要中展示。成功读取工单详情后消费本账号在该会话中已经读到的通知，保留其他工单、其他管理员与读取期间的新消息；返回后刷新入口角标。

## 我的页面与平板导航

“我的”沿用信息流的分栏边界：扣除首页侧栏后，可用宽度达到 840 时左栏保留 380 宽的个人中心，二级页面及其后续跳转在右栏打开，返回逐层退出。左侧切换功能会替换右侧导航栈，并遵守详情页的离开限制。窗口收窄后保留已打开的详情、输入与滚动状态；从窄屏新进入二级页面仍使用整页导航。账号、会话或角色变化会清空右侧旧页面。

分栏中的二级页、帖子详情与个人主页通过 `SharedPageBackground` 共用外壳的整张壁纸，不重新绘制局部壁纸；个人主页原有的用户封面继续显示，帖子和商品卡片的左右边缘与上方标签栏对齐。独立打开的页面继续使用原有背景和留白。

集市与个人主页复用 `AdaptiveDetailLayout`：集市在剩余宽度达到 840 时保留左侧商品列表，商品、作者主页及后续帖子在右侧逐层打开。单独打开的宽屏个人主页在查看内容时分栏；已在信息流或个人中心详情栏内的主页沿用当前区域，避免再打开整屏或第三栏。收窄后保留详情、回复草稿和列表位置，返回先回到来源主页，再退出详情。会话或角色变化会清空旧详情，集市搜索的晚到结果也不能回填新会话。

## 表情包

表情功能入口为输入面板的“表情管理 → 添加”：可多选相册图片、导入图片 ZIP / `.sylupack`，预览改名后安装到当前账号的本机目录。本机导入无需网络；新投稿、创作者与社区目录需要配套 Go 服务端。资源与兼容边界见 [Emoji 资源契约](../docs/design/emoji-resource-contract.md)。

制作外部文件时，普通图片 ZIP 以文件名作为逐张对应文字；需要明确文字和资源关系时，使用根目录 `manifest.json` 的 `assets[].path` / `name`。缩略图由系统生成，不要额外打包。完整字段、目录示例和限制见 [ZIP 与 sylupack 制作格式](../docs/design/emoji-resource-contract.md#8-zip-与-sylupack-制作格式)。

新版提供免费“表情商城”和“创作中心”直达入口。普通用户可自由导入自用并整理仅本机个人标签；公开投稿需先申请创作者权限，每包/每次更新单独审核。创作页支持账号隔离的自动保存草稿、逐张文字、公开标签、封面/面板图标选择和上架效果预览，失败或取消上传保留草稿。网格使用系统生成的静态缩略图，点击才展示完整图片/动图。管理员在“表情创作者审核”开通、驳回和暂停权限，自己的申请及作品均需其他管理员处理。流程与迁移边界见 [实施方案](../docs/design/emoji-creator-store-plan.md)。

帖子、评论及图片查看器会自动播放 GIF 原图；选择面板使用静态预览。官方「明风 OvO」匹配原始动图内容哈希时使用对应的内置预览，其他内容继续使用本机派生图。自动播放原图可能比静态图消耗更多流量。

管理页支持按包名、个人标签和逐张对应文字查找；输入面板中的已安装包支持按对应文字筛选，切号清空筛选状态。商城“返回使用”会回到面板并选中安装包。本机包异步加载后的标签切换直接定位目标页，避免旧滚动边界让分页动画停在“最近使用”。

Windows 可从仓库根运行 `./scripts/verify-emoji-chain.ps1`，联调真实 Flutter 页面和 Go API。脚本只启动随机 loopback TLS 端口、临时 SQLite 与上传目录，注入隔离 API 地址；覆盖导入、申请、审核、商城、安装返回、筛选、评论上传和下架保留，结束回收临时服务。需要本机 Go、Flutter 和已安装依赖；运行时串行执行 Flutter 检查，避免共享原生 DLL 构建目录冲突。该显式联调在普通 `flutter test` 中跳过，不替代 PostgreSQL、代理和手机验收。

## 体测登录与保存密码

- 工具箱体测入口读取本机安全存储；已有密码时自动查询，无密码或读取失败时保留手动输入。密码按原字符传递，仅在学校请求中进行一次 MD5 转换。
- 查询页与设备刷新共用登录解析，区分学校明确拒绝凭据、验证码要求、网络异常和其他服务失败；失败不删除已保存密码。成功登录后的本机保存失败单独提示，不阻断本次查询。
- “重试”清除旧错误并重新登录，“返回修改密码”回到输入页；账号、学号或本站会话变化后旧请求不能继续回填页面或发起密码保存。

## 二课成绩更新

- 二课页打开时先显示当前账号的加密成绩缓存，再用已保存凭据后台更新；下拉、顶部“更新”和菜单“更新二课数据”复用同一流程，刷新期间保留已有成绩。
- 首次验证可选择“在本机安全保存密码”，成功认证后通过 `DeviceCredentialStore` 写入系统安全存储，与校园 Agent、个人数据中心的更新入口复用。取消保存只在当前页面会话保留密码。Web 的安全存储不持久化密码。
- 学校返回的通用登录错误、HTTP 401、网络超时和页面解析失败不能单独证明密码错误。二课模糊错误先核实受保护页面，再最多恢复登录一次；只有 CAS 明确拒绝账号或密码才要求修改凭据。
- 毕业要求、学年要求和活动记录独立获取，部分失败保留原有对应数据；学年活动与全部活动分别缓存。已有学年缓存支持离线查看。
- 部分刷新保留原快照时间并持久标记不完整；保险箱和个人 AI 将其作为需同步数据。混合新旧值的摘要暂不上传，完整刷新后恢复既有授权上传流程，不改变服务端 v2 契约。
- 二课页面、个人数据中心及设备任务的更新与摘要上传绑定 App 账号、教务来源和会话代次；上传/删除在请求发送前复核发起会话。同一账号重新登录也会取消旧流程。个人数据中心更新与清除互斥，切号后需重新打开。
- “修改登录密码”和“清除已保存密码”在二课页菜单；“清除本地缓存”仅清成绩，个人数据中心清除本机个人数据会同时清理保存的二课密码。历史 SharedPreferences 明文密码不迁移，只清理。

## 我的 AI 机器人

连接区显示由服务端核验的后台运行状态、最近浏览、下次计划及 bot 作者的真实成功发言；约30秒独立刷新，失败降为尚未核验并保留资料／权限草稿，切号与晚到响应不能回填。执行端离线或无本人授权不显示正在运行；旧服务未提供协议时明确不可核验。创建者、普通账号的任务都由常驻 AstrBot 承载，App 不需要驻留，开关及授权方式见插件说明。

该页沿用设置页背景入口、共享卡片材质和现有青绿品牌。毛玻璃与卡片透明度由外观设置统一控制；关闭毛玻璃停止模糊并保留手动不透明度，简洁背景恢复实色卡片。维护时复用 `AppCard` / `AppCardSurface`，内部信息行、输入与状态不要再叠一层模糊或不透明底面。状态图标和文字必须同时保留，无障碍与真实渲染验证按开发与交付规范执行。

设置 → 我的 AI 机器人提供新建（默认暂停）、名字与公开头像编辑、社区权限及言论规则、启用／暂停和原生 AstrBot 连接授权。资料和主要操作前置，社区参与与发言规则分组查看，记忆隐私以摘要及可展开详情呈现。仅成功读取并确认没有机器人时展示新建；加载、无法读取和旧服务单独显示状态，不伪造创建结果。

社区权限采用公开浏览总开关、评论／表情独立能力选择及板块多选清单；发言节奏支持每日额度分段选择、间隔快捷选择和自定义。预设只修改草稿，保存前显示待保存。失效板块提供明确移除，处理前不能保存／启用，紧急暂停仍可使用；组内控件只用平面选中态，不叠加毛玻璃。

复用 `/api/connected-apps/bot`，两端共用服务端规则；请求绑定当前账号会话代次，切号清空旧状态。账号启用、服务端开放、专用评论授权分别显示，不声称后台已运行。头像复用相册、方形裁剪及现有上传，保存失败保留草稿。记忆与模型仍在本机 AstrBot 管理，App不读取私聊库；群仅短时上下文，创建者私聊与公开阅读分开保存。接口与规则见 [服务端 API](../server/API.md) 和 [插件说明](../astrbot_plugin_sylulive/README.md#社区机器人账号管理)。

## 食堂管理与商家投稿

管理员从「食堂管理」集中进入商家资料、菜品、投稿审核和上下架操作。列表支持名称／位置搜索、区域及营业状态组合筛选，状态数量随当前搜索与区域变化；刷新失败保留原列表并提供重试。

每家商家只有一个「编辑商家」入口，在独立页面修改名称、位置及展示标签，并通过一次 PATCH 原子保存。展示标签支持自动汇总、手动最多 3 个或手动留空隐藏；已有评价、菜品和图片不变。管理页及写请求绑定当前账号会话，切号、重新登录或撤销权限后不能继续操作旧页面。下架商家仍仅超级管理员可维护。

「提交商家」使用独立页面，搜索无结果时保留搜索词作为名称。区域增加「其他」，表示食堂以外的校内独立店铺、校外餐饮等；选择后不要求填写食堂楼层。投稿仍需一张真实上传的门面图片，通过审核才公开。上传／提交期间拦截重复操作，提交失败保留输入及图片，离开未提交表单时提醒。

管理页使用普通分隔列表，上下架收进商家菜单。编辑和投稿共用名称输入与位置点选组件：名称支持清空、字数与错误提示，区域和楼层直接点选，大字号下自动换行；编辑页可再次点击已选位置取消设置。商家预览集中显示封面、状态、位置、评分、菜品与实拍数量，以及随草稿变化的展示标签；自动标签附真实提及次数，手动标签按选择顺序展示，选项中的数字表示顺序。手机上预览位于表单上方，宽屏并排显示。底部保存区保留修改状态，键盘打开后仍可操作；投稿仍在右上角提交。完整接口与兼容边界见 [服务端商家管理](../server/API.md#商家管理与区域)。定向验证：`flutter test test/screens/canteen_management_screen_test.dart`，真实渲染截图写入忽略提交的 `build/canteen-management-components-qa/`。

## 食堂怀旧存档

食堂首页与排行页的「怀旧」进入独立下架食堂存档；怀旧详情保留历史评价和图片，不参与排名。超级管理员可从「维护资料」进入原有运营页面，普通管理员对下架资料只读。接口、权限及旧端兼容规则以 [食堂下架与怀旧存档](../server/API.md#食堂下架与怀旧存档) 为准。

## 应用更新

Android 正式版普通更新默认静默准备安装包，沿用用户的“仅 WLAN 自动下载”和“允许后台继续下载”设置，下载及校验完成后再询问是否安装。应用在后台时恢复前台再提示；选择稍后安装后，本次运行同包不重复打扰，手动检查仍可安装。关闭自动下载后保留手动入口；强制更新和外部应用市场分发仍直接提示。

自动提醒与手动检查共用正式版弹窗，支持深色、大字号、长说明滚动和毛玻璃；下载、安装入口及应用市场跳转失败会保留重试入口。强制更新显示下载状态，顶部提示条可重新打开详情。

Android 始终单独检查正式版更新；在“设置 → 通知与后台 → 应用更新”开启“接收 Beta 测试版通知”后，另查测试版下载信息。Beta 弹窗展示版本、功能说明及“功能更丰富，但不建议小白用户下载”的提示，由用户选择打开浏览器下载或关闭。Beta 不进入应用内更新、下载任务或安装器。关闭订阅不会影响正式版策略和下载进度。超级管理员在“应用版本”上传时选择 `stable` 或 `beta`。接口、优先级和下架边界见[应用更新通道契约](../docs/design/app-update-channels.md)。

## 开发环境

- Flutter 3.x
- Dart（版本约束以 `pubspec.yaml` 为准）
- Android Studio 或 VS Code
- Android SDK；iOS 构建需要 macOS 与 Xcode

### iOS 本地验证

在装有 CocoaPods 的 macOS 上，从 `client/` 执行以下命令。模拟器构建完成后，通过 `ios/Runner.xcworkspace` 打开 Runner scheme，选择 iPhone 或 iPad 模拟器进行测试。

```bash
flutter pub get
flutter build ios --simulator --debug
```

真机签名使用维护者的 Apple Developer Team。Runner 和 CourseScheduleWidget 目标需要启用同一个 `group.com.sylu.sylulive` App Group，Runner 同时需要 Push Notifications 和 Associated Domains。APNs 在 Debug 和 Profile 使用开发环境，在 Release 使用生产环境。Universal Links 依赖域名提供与签名应用匹配的 `/.well-known/apple-app-site-association`。

iOS 课表小组件的实际快照读取共享课表，示例课程只用于组件图库预览。全量课表按本地日期和教学周生成当前及后续七天的时间线；退出账号或清空数据会同时移除共享存储中的旧课程和考试。未同步、无课、数据损坏与 App Group 不可用分别显示对应状态。原生数据与日期回归测试位于 `ios/RunnerTests/RunnerTests.swift`，在 Xcode 的 Runner scheme 中执行 Test。

iOS 客户端从 `/api/app/update` 查询 `ios/stable` 版本。管理端创建 iOS 版本时填写 App Store 或 TestFlight 链接，服务端若配置了 `APP_RELEASE_MARKET_HOST_ALLOWLIST`，需包含对应 Apple 域名。App 检出新版后打开商店。

### iOS 真机测试包

GitHub Actions 的 [Build iOS IPA](../.github/workflows/ios.yml) 在 macOS runner 上构建未签名的 arm64 IPA，包含课表与考试小组件。到对应运行的 Artifacts 下载 `sylulive-ios-unsigned`，解压后用 Windows 签名工具安装到测试设备。免费 Apple 账号的签名有效期为 7 天，远程推送和 Universal Links 需用支持对应能力的签名另行测试。小组件依赖主 App 和扩展共享同一 App Group。

自签或侧载时，签名工具必须保留小组件扩展，并为主 App 和扩展配置同一 App Group 的有效授权；仅保留 entitlement 文件中的声明不能代替签名授权。共享容器不可访问时，App 的小组件设置页会报告签名权限错误；需修正签名、重新安装，再执行“同步全部小组件”。在 iPhone 上验收真实课程显示、跨日换课、退出后旧数据清除和权限失败提示；Windows 上的逻辑测试不覆盖 WidgetKit 与签名运行环境。

## 运行

```bash
flutter pub get
flutter run
```

液态玻璃的 Android 视觉验收使用默认 GPU 渲染。Android Studio 的运行参数应与命令行保持一致，不额外开启 `--enable-software-rendering`；软件渲染截图不能代表 GPU 折射材质的实际效果。

Windows 模拟器验收液态玻璃时，AVD 的 Graphics 选择 Hardware（`hw.gpu.mode=host`）。出现 `adb: device offline` 时，先核对 Windows 应用程序事件中的 `qemu-system-x86_64.exe` 崩溃记录，区分模拟器进程退出与 App 崩溃；修改 Graphics 后冷启动，保留应用数据。

正式设置页的 `SettingsSwitch` 使用与液态玻璃 Demo 一致的绿色／灰色胶囊轨道和白色滑块：轨道 56×30、滑块 30×24 逻辑像素。轻点依次在原端鼓起、平滑滑向另一端、到位后收回；动画中再次按下继续原有滑行，确认横向拖动后才转为手动跟随，轻点抬手直接转向新目标，不重复等待鼓起。按住拖动使用保留速度的临界阻尼跟随，重新按住和反向保持连续；逐次截断越界位移，手指拖出轨道后反向移动立即生效。横向拖动建立后，斜向回拖不再移交滚动，保存结果回传不打断当前手势。松手保留弹性回收，由原生 Switch 提交一次设置；开关独立重绘，动画不带动外层设置卡片逐帧重绘。背景仅采样独立的页面底面和卡片材质，不采样开关自身。高对比度、禁用态、无采样源和共享分栏背景保留原生开关；减少动画保留即时反馈。开发包从“设置 → 界面设置 → 底部导航栏 → Liquid Glass Reference QA”查看同一组件的本地样例，样例不保存设置。

外层导航底座始终保留清透折射和亮边，使用固定光源，按压与拖动不改变它的位置、尺寸和材质。内部选中胶囊静止时显示普通选中态，按住后才激活透镜，宽度增加 30%；胶囊以外的底座和其他入口保持不变。按下其他入口（含入口边缘）时，胶囊先在原端鼓起，再展开着自动移向该入口；持续按住则保持展开。短按抬手继续完成同一段行程，到位后收回；长按到位后抬手收回。滑行中再次按住胶囊保留当前目标与动量，轻微抖动不刹停；确认拖动时以此刻可见位置接管。胶囊的拉伸与弯曲使用 1.35 倍形变弹性，独立增加形变幅度并降低形变弹簧的刚度与阻尼，手动位置跟随与按压尺寸沿用原参数；开关不启用此增强。拖动只更新透镜的连续位置，松手提交一次切页；取消回到原入口。停手但仍按住时，拉伸与弯曲回稳，清透透镜继续显示。键盘、无障碍选页与减少动态效果不激活按压透镜。

Windows 本地联调可双击仓库根目录的 [一键配置本地环境.bat](../一键配置本地环境.bat)，选择本机桌面、Android Studio 模拟器或与真机同网的网卡。它会把 Go 服务地址写入本机专用的 `.env.local-api.json`。启动开发机的 Go 服务（默认 8080 端口）后，用 VS Code 打开 `client/` 并选择 `SYLUlive (Local/Configured)`，或在该目录运行 `flutter run --dart-define-from-file=.env.local-api.json`。真机需能访问所选地址的 8080 端口。

不要把真实学校账号、密码或 Cookie 写入提交内容、测试快照和日志。

## 常用检查

公开协议正文与 App 共用 `lib/legal/legal_documents.dart`，修改后从仓库根目录执行 `dart run client/tool/export_legal_documents.dart`，并同步服务端确认版本。CI 的 `--check` 会阻止公开页面与 App 正文漂移；服务端将导出 HTML 嵌入二进制。维护与回退见 [公开法律文档运维](../docs/ops/public-legal-documents.md)。

```bash
flutter analyze
flutter test
```

涉及界面、动效和无障碍的改动，先检查 `lib/theme/`、相关共享组件与已有测试，具体设计按本次任务要求执行。状态、异步竞态、无障碍和真实渲染验收统一见 [开发与交付规范](../DEVELOPMENT_STANDARD.md#42-flutter-与客户端)；[功能契约与决策记录](../docs/design/README.md) 中的数据和权限边界继续适用。

自定义背景下普通卡片、弹窗和预览使用 `ThemeProvider.effectiveComponentOpacity`。卡片不透明度滑块的 0–100% 线性映射为实际底色的 75–100%，偏好保存实际不透明度。历史 75% 对应新 0%，更低的历史值使用新最低档。文字和图标沿用主题前景色。课表独立透明度与显式透明容器继续使用自己的设置；关闭毛玻璃只停止模糊。未应用主题材质时，简洁背景恢复实色卡片；显式主题材质按当前明暗变体生效。

卡片效果预设同时填入不透明度档位和模糊强度。关闭使用 100%／0%，高性能使用 75%／35%，高画质使用 0%／100%，自定义从 50%／65% 开始。手动调整后按完整组合匹配预设，保存重试使用当前数值。

本机主题包从“我的 → 个性主题”或界面设置中的“主题”进入，也支持通过系统文件关联打开 `.sltheme` 文件；可按配色、圆角、壁纸、卡片材质和导航栏预览、全局试用或分组应用，支持导出当前混搭外观、恢复上一个外观和手动外观。实现范围、存储和验证入口见[本机主题包说明](lib/features/theme_pack/README.md)。

## 原教务绑定自动同步

教务绑定保留原入口；本机学校登录成功后检查服务器身份，缺失时先对账账号配置，再以临时学校会话让服务器向固定学校入口重新核验学号。恢复本机会话、刷新课表和网络重试沿用同一补交流程，不新增学生绑定／单独认证入口。学校密码不随补交上传，服务端不保存学校会话。接口部署前置条件与验收步骤见[绑定测试说明](docs/student-identity-test.md)。
