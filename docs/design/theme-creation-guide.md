# 主题制作与审核细则

本文面向三类读者：主题作者、商城审核员、官方主题的制作者。

- 格式、对比度规则与硬性校验规则以 [主题包格式契约](theme-pack-contract.md) 为准。
- 本文规定的是做出一套好主题的标准，以及审核时的判定依据。
- 第 1–5 节的内容要整理成作者可读的版本，放进主题工坊的"制作指南"页。

## 1. 制作流程（主题工坊）

1. **定主色**：选一个种子色，工坊会推导出全套 Token。先在亮色和暗色下各看一遍首页和课表，再决定要不要逐个微调 Token。
2. **调课表**：点"从种子色生成"，得到一套课程色板，然后在课表周视图里检查相邻课程能不能分得清。
3. **放壁纸**：先放全局壁纸，再设置首页、课表、我三页的独立壁纸；用焦点、亮度、对比度、饱和度、模糊和遮罩调整氛围。明暗两套独立保存；“复制亮色设置”只复制一次。
4. **调材质**：设置组件透明度、毛玻璃、圆角，以及卡片描边和阴影。壁纸越花，透明度就要越高（越接近 1.0）。这些选择使用同一套 UI 组件。
5. **换图标**（可选）：主题提供配色、图标与着色方式。底栏样式和液态效果由使用者在本机设置。五个底栏图标要么全换，要么只换"首页"一个；不要只换其中两三个，否则风格会不统一。
6. **选字体**（可选）：导入一个 TTF 或 OTF 字体，在样例页上检查正文、标题和数字的显示效果。
7. **桌面图标**（可选）：从内置备选图标中选一个和配色搭配的；也可以另外提供一张自定义图标，供 Android 用户添加为桌面快捷方式。
8. **看小部件**：在工坊的"小部件"预览中，检查课表和考试小部件在亮色、暗色下的效果。
9. **排页头**：首页、校园、我按明暗分别检查。当前模式有背景或贴纸时自动沉浸，可调整对齐和页头高度；无装饰时可选择标准或紧凑排版。真实资料与操作区始终保留，字体仍由用户字号设置控制。
10. **放装饰**（可选）：为三个页头选择背景，每个页头最多五张贴纸；在预览里拖动、缩放、旋转及调整层次，也能直接输入数值。单项、单页头和整组都能重置。装饰不覆盖作者的真实头像、封面和内容图片。
11. **检查**：工坊对比度面板全绿；九个首批页面的明暗、加载、空态、失败及权限状态均已预览；在 1.5 倍字号下检查页头和操作区。
12. **导出或投稿**：填写名称、简介、标签和许可，确认素材授权。先导出到另一台设备导入，核对布局、卡片、图片效果、贴纸层次和位置，再完成试用、应用、重启与恢复检查。

## 2. 配色细则

**硬性要求**：满足格式契约第 5 节的对比度阈值，商城投稿时会自动拒收不达标的主题。

以下各项由作者自查、审核员人工判断，工坊不做自动检测：

| 检查 | 规则 | 原因 |
| --- | --- | --- |
| 大面积背景的色度 | `background`、`surface`、`card` 在 HCT 空间的色度不超过 16 | 高饱和的大面积底色看久了容易累，也会让卡片层级糊成一片 |
| 亮色背景的亮度 | 亮色模式下 `background` 的 HCT 色调不低于 90 | 低于这个值，看起来像"灰掉的暗色"，而不是亮色 |
| 暗色背景的亮度 | 暗色模式下 `background` 的 HCT 色调不高于 12 | 同上，方向相反 |
| 主色与危险色 | `primary` 与 `#E54848` 的色相差至少 20°，或 `primary` 的色度不超过 20 | 避免普通按钮看起来像删除、警告操作 |
| 卡片层级 | `card` 与 `background` 的色调差，亮色至少为 2，暗色至少为 3；或者 `cardBorder` 与 `card` 的对比度至少为 1.3 | 卡片要能和背景分开 |
| 课程区分度 | 色板中相邻两个颜色的色相相差至少 25° | 相邻课程要能分清 |

推荐做法：

- 亮色背景用带一点主色倾向的暖白或冷白，不要用纯 `#FFFFFF` 作为页面底色。卡片可以用纯白。
- 暗色背景用色调 6–10 的深灰，并带轻微色相。纯黑 `#000000` 只用于明确定位为 OLED 的主题。
- 主色的色调：亮色模式 35–50，暗色模式 70–85。

## 3. 壁纸细则

| 项 | 要求 |
| --- | --- |
| 尺寸 | 竖屏推荐 1080×2340，横屏推荐 2340×1080。短边至少 720，长边至多 4096 |
| 文件 | 推荐 WebP，质量 80–85，单张控制在 1.5MB 以内。上限是 8MB |
| 安全区 | 竖屏顶部 12% 会被状态栏和顶栏遮挡，底部 14% 会被底栏遮挡。主体放在中间 74% 的区域内，并用 `focalX`／`focalY` 对准 |
| 文字区 | 壁纸本身不能带文字、水印、二维码或联系方式 |
| 首页 | 首页上有信息流卡片，画面花的图要加 `blur` 6–12，或者把组件透明度设到 0.9 以上 |
| 课表 | 课表上有网格和小字。推荐使用低对比、大色块的画面，`blur` 4–8，`scrim` 至少 0.2 |
| 我 | 顶部是头像和资料卡，画面主体要避开顶部 30% 的区域 |
| 明暗 | 暗色模式下的壁纸要单独提供更暗的版本；或者沿用同一张图，但 `scrim` 至少 0.35 |

### 3.1 页头背景与贴纸

具体图片尺寸、参数范围与裁切规则以格式契约第 2.7–2.9、6 节为准。

- 页头背景与贴纸只出现在首页、校园、我各自的页头，不占用真实资料、通知和按钮的位置；个人主页原封面继续显示。
- 先定页头高度，再摆贴纸；在最窄视口、宽屏分栏和明暗两种模式检查裁切。贴纸超出图片区的部分会被裁掉。
- PNG／WebP 贴纸保留透明边缘，导出后不能出现黑边或白底；贴纸层次由列表顺序决定。
- 图片效果只作用于壁纸和页头背景，在渲染时使用颜色矩阵（Flutter 用 `ColorFilter.matrix`，网页用 CSS `filter`），不改变贴纸、图标、商品图及用户内容。导出原图与效果参数，预览图则记录实际渲染后的效果，防止重复处理。
- 图片与装饰继续遵守本文的素材授权和内容规则；不能画出假的按钮、权限提示、通知或系统弹窗。

## 4. 图标细则

| 项 | 要求 |
| --- | --- |
| 画布 | 192×192 透明背景。图形主体放在中间 144×144 的区域内 |
| 语义 | 每个槽位的图标必须能被认出原来的含义：首页＝家或主页，集市＝商店或购物，课表＝日历或课程表，校园＝建筑或校园，我＝人物 |
| 两态 | 常态与选中态必须能看出区别：选中态填充加常态描边，或者两态的形状不同。两张图完全相同会被拒收 |
| template 模式 | 只用到图标的 alpha 通道。图标要做成单色剪影，线宽至少 12px（按 192 画布计算），这样缩到 24dp 时依然清楚 |
| original 模式 | 彩色图标在亮色和暗色两种 `navBackground` 上都要清楚可辨，要用明暗两套预览分别检查 |
| 文字 | 图标里不能有文字 |
| 风格 | 五个图标的线宽、圆角、视觉重量要一致 |

### 4.1 自定义桌面图标

| 项 | 要求 |
| --- | --- |
| 画布 | 推荐 1024×1024，不透明，背景铺满。主体放在中间 66% 的圆形区域内，因为不同启动器会把图标裁成圆形、圆角方形或水滴形 |
| 辨识 | 一眼能看出是"沈理校园"：保留主题主色，或者保留 App 原图标的主要形状 |
| 禁止 | 模仿其他 App 的图标（微信、QQ、支付宝、银行、系统设置等）；使用系统图标样式；带红点、角标、数字 |
| 文字 | 最多 2 个字，并且要在 48dp 大小时仍然清楚 |

## 5. 字体细则

| 项 | 要求 |
| --- | --- |
| 授权 | 只接受 OFL-1.1、Apache-2.0、CC0-1.0，或者作者本人拥有版权的字体。商用字体、"个人免费"的字体、从网站下载但授权不明的字体都不能投稿 |
| 覆盖 | GB2312 一级汉字（3755 个）至少覆盖 99%，服务端会自动检查。推荐用子集化工具保留 GB2312 全部 6763 个汉字，加上常用标点和 ASCII，这样文件可以从十几 MB 降到 3–6MB |
| 大小 | 单个文件不超过 24MB，推荐不超过 8MB；文件越大，用户的下载时间和启动加载时间越长 |
| 字重 | 至少提供常规体。标题较多的主题推荐再提供一个粗体，合成粗体在部分字体上会糊 |
| 可读性 | 正文以 14sp 显示时笔画清楚；数字、英文和中文的基线、高度要协调。过于花哨的手写体和书法体只适合大字，不适合当正文字体，审核时按 `quality` 拒绝 |
| 排版 | 字体的行高和字宽不能过大。在九个页面中，1.5 倍字号下不能出现文字溢出或被截断 |

## 6. 命名、描述与授权

**名称**：

- 不超过 20 个字符；
- 不能以"官方""沈理""沈阳理工"开头，这几个词留给 `official` 来源；
- 不能冒充其他作者；
- 不能带广告或联系方式。

**简介**：说明这套主题的风格和适用场景。不能出现链接、二维码、QQ 号、微信号或店铺信息。

**素材授权**：

- 投稿时必须勾选"我拥有全部素材的使用权"。
- 许可字段按实际情况选择：
  - 自己拍摄或绘制的作品：可以选任意许可；
  - 使用别人的作品：需要原作者授权，并在简介中注明来源；
  - 原创的同人作品：可以投稿；
- 校徽、校名标识只能出现在官方主题里。

## 7. 内容红线

出现以下任意一项，直接拒绝；情节严重的，交给账号处理流程：

- 色情、性暗示、血腥暴力；
- 政治、宗教、歧视、仇恨相关内容；
- 广告、引流、联系方式、二维码、链接；
- 能识别出身份的他人照片（本人拍摄并取得同意的除外），以及学号、手机号、证件等个人信息；
- 冒充官方，或者冒充 App 的系统界面（例如在壁纸里画一个假的弹窗或按钮）；
- 抄袭他人在商城里已上架的主题（同样的壁纸加上同样的配色）。

## 8. 审核规程

### 8.1 每个投稿必做的检查

1. 在管理端审核页点"试用此主题"，开启全局试用会话，顶部会常驻"试用中"横条。从底栏依次切换首页、集市、课表、校园、我五个页签；再从"我"进入个人主页、设置，从首页进入 AI 助手和工具箱；在系统设置里切换明暗模式，把这九个页面再看一遍。
2. 检查过程中重点确认文字可读、控件颜色（按钮、开关、滑块）与主题一致。
   - 检查完成后，点横条上的"结束"，回到原外观，再返回审核页做出判定。
   - 如果中途重启了 App，试用会自动结束，需要重新进入审核页。
3. 逐张查看壁纸、页头背景和贴纸原图：放大检查边角有没有水印、文字、二维码；核对贴纸透明边缘、层次及小屏裁切。分别试用首页、校园和我的明暗页头，有装饰时确认插画或贴纸从状态栏区域铺开。整宽下图像清晰、人物头部完整，模糊或主体被裁掉按 `quality` 拒绝。
4. 如果主题带底栏图标，核对五个槽位的语义和两态区别。
5. 如果主题带字体：
   - 核对 manifest 中声明的许可，与字体文件内 `name` 表的版权和许可字段是否一致（审核页会显示这两个字段）；
   - 在试用状态下，把字号调到 1.5 倍，检查九个页面有没有文字溢出。
   - 许可不符时按 `copyright` 拒绝，排版问题按 `quality` 拒绝。
6. 如果主题带自定义桌面图标，核对它是否满足 4.1 节，模仿其他 App 的按 `impersonation` 拒绝。
7. 查看审核页的小部件预览：亮色和暗色下文字都清楚。
8. 核对名称、简介、标签与实际内容是否一致。
9. 如果是新版本，对照"与上一版的差异"面板，检查改动是否合理。
10. 核对布局、卡片和图片效果参数，分别在窄屏、宽屏分栏、1.5 倍字号下检查；装饰不挡操作、不改变权限提示，用户内容图片保持原样。下载服务端规范包试用时，外观应与投稿预览一致；重编码不能丢掉透明贴纸或导致效果重复叠加。

### 8.2 判定

- 通过：所有检查都符合要求。
- 拒绝：必须从下表中选择原因，可以再附加补充说明。作者看到的是"原因 + 补充说明"。

| 原因代码 | 作者看到的原因 |
| --- | --- |
| `contrast` | 部分页面的文字看不清，请提高文字与背景的对比度 |
| `wallpaper_text` | 壁纸含文字、水印、二维码或联系方式 |
| `copyright` | 素材授权不清，或使用了未授权的作品 |
| `content` | 内容不符合社区规范 |
| `icon_semantics` | 底栏图标无法辨认原含义，或两态没有区别 |
| `quality` | 画面模糊、拉伸、主体被遮挡等质量问题 |
| `metadata` | 名称、简介或标签与内容不符，或含广告 |
| `impersonation` | 冒充官方或他人 |
| `duplicate` | 与已上架的主题重复 |

- 审核时效目标：投稿后 48 小时内处理。

### 8.3 下架

已上架的主题被举报并核实违规后，下架整个版本族。下架原因从 8.2 节的原因表中选择，作者在"我的投稿"里能看到下架原因。

## 9. 官方主题参考参数（暂不上架预制包）

当前商城不预置首批官方投稿，开放等待社区用户上传；以下参数仅作为后续人工设计官方主题时的参考规范。

官方主题如后续制作，用主题工坊制作并用维护者账号投稿，`source` 为 `official`。

每套官方主题必须满足以下全部要求：

- 工坊对比度面板全绿，第 2 节表格中的各项都满足；
- 明暗两套都完整提供；
- 九个首批页面在亮色和暗色下都截图，作为制作记录存档；
- 名称以外的文字（简介、标签）由维护者确认。
