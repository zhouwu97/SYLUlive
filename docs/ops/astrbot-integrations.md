# AstrBot 集成发布入口

## 机器人管理接口的兼容发布

App/Web 管理页共用 `/api/connected-apps/bot`，插件规则读取使用 `/api/integrations/v1/bot/policy`。这些接口不依赖自动评论开关；新增 `INTEGRATION_AUTO_REPLY_ENABLED` 默认关闭。迁移新增 `managed_bots` 及规则列，不代替本人新建账号或追加旧连接 scope。公开归属、头像及规则数据范围见 [隐私台账](../privacy-data-inventory.md)。

以现场运行 SHA 为基准集成，保留个人资料查询、快照上传、设备取消、重新验证和已有授权接口。按 [正式入口](../../DEPLOY.md) 完成不可变候选、备份、CI/安全核验及明确放行后再部署。部署后执行 `python scripts/verify-managed-bot-release.py --origin https://sylulive.online --sha <完整候选SHA>`：同时检查真实 SHA、`managed_bot_v1` 和两个受保护接口的 JSON 401，不能把首页或普通版本请求成功当作新接口已发布。

再由本人在当前 App 验收读取已有资料／明确空状态、新建暂停账号、名字和本人头像、规则保存与重新读取、暂停和撤权；旧接口应继续可用。管理资料正常并不表示 Agent 已自动运行，自动评论另需本人专用授权及独立开关。回退先关闭自动参与，保留新增兼容表和已发布记录，按原备份及回退手册恢复；不覆盖发布后生效的撤权。

业务与安装契约以 [插件 README](../../astrbot_plugin_sylulive/README.md) 为准；生产执行遵循 [DEPLOY.md](../../DEPLOY.md)、[后端](backend.md)、[官网](website.md) 与 [回滚](rollback.md)。不能把本地验证当成生产放行。

## 首次只读试运行范围

发布 Go 授权/读取 API 和 Web 的 `/web/connected-apps`。QQ 协议端和 AstrBot 留在用户本机。用户自行在官方网页登录、核对设备代码和同意 scope；操作者不能代填学校密码、伪造教务资格或替用户批准授权。

首轮配置：

```dotenv
INTEGRATIONS_ENABLED=true
INTEGRATION_PROPOSALS_ENABLED=false
INTEGRATION_OWNER_PUBLISH_ENABLED=false
INTEGRATION_PUBLIC_ORIGIN=https://sylulive.online
```

插件 `server_origin` 同为 `https://sylulive.online`、`allow_proposals=false`。生产数据库和服务开关只能在维护者明确批准本次发布、备份与门禁就绪后修改。后两项开关不能因读取验收通过自动开启。

需要按名单向指定群共享公开读取时，在插件中显式配置 `public_read_group_ids`，并使 AstrBot 接收设置允许对应群；也可显式启用`public_read_all_sessions`沿实际接收范围共享公开读取。开启`allow_multi_user`和`allow_group_binding`后允许群发起绑定、向原发起人私发链接；未开启时仍须本人私聊。0.2.1需先发布支持设备请求取消的Go后端，再安装插件；取消失败时保留本机状态重试。断开仍限本人私聊，草稿和动作查询仍限部署者私聊。群状态不能展示绑定昵称或授权链接。默认群列表为空，不通过放宽私人接口鉴权实现群功能。

0.1.6起公开食堂榜单／菜品匿名复用 App API，公开图片通过限定来源的多模态工具读取与发送；具体限制见插件 README。群的每次事件在知识检索前设置空会话知识库，模型请求使用公开工具白名单；检查其他记忆插件没有跨会话注入。不得向群内开放任意发送目标、本地文件、私人知识库或用户账号工具，即使当前群发送者是管理员。0.2.0成绩与二课权限仅供本人确定私聊命令，不新增私信、课表或学校登录 scope。

## 发布前

0.2.0服务端个人范围须单独设置`INTEGRATION_PERSONAL_DATA_ENABLED=true`。默认关闭，关开关后旧个人scope也不能读，不能批准新范围或上传新成绩，但保留本人删除和撤权。启动校验要求集成已开启且`SCHOOL_AUTHORITY_RETIRED=false`；退役部署不可直接开，必须另行评审，不得自动关闭退役开关。先在后台确认服务状态，再启用本机两个开关，不能仅改插件就宣称已开放。旧公开查询和签到独立保留。

启用前须在备份与数据库发布批准后执行`server/sql/20261101_integration_personal_snapshots.sql`。旧`20260725`迁移的类型约束仅接受二课，GORM AutoMigrate不会自动扩展它；新迁移事务性允许`integration_grades`，重复执行安全，锁等待超过5秒失败回滚，不改写资料。保留执行记录；应用回滚时保留兼容约束，不删用户资料来恢复旧约束。注销、撤回协议或教务身份换绑会清理本人的新成绩上传副本，普通撤销助手只阻断读取，不等于删除资料。

0.2.0是Go、Web与本机插件的R3联合变更，入口见[多用户授权与权限后台](../ai/astrbot-multi-user-authorization.md)。先检查新增审计列、jsonb兼容、两用户隔离、后台管理员反向鉴权和回滚，再按正式入口发布Go和Web，最后更新插件并显式开启`allow_multi_user`／`allow_personal_queries`。旧scope不增权，不能代用户批准个人范围；模型／人格／接收设置／群语音及社区发布开关保留。PostgreSQL、CI、真实QQ和生产验收各自记录，不能用本地合成测试替代。回滚先关新本机开关并撤销新个人范围授权，再恢复旧代码，不回灌整库或删审计。

0.1.13仅更新本机插件；不改后端、授权、模型、人格或其他插件配置。备份原安装目录，打包并核对逐文件摘要后按AstrBot原生重载入口加载。检查首次“今天吃什么”直接返回同店门面／实拍（无实拍时明确标注评价配图）及昵称评价、下一轮换一家、无图／网络失败／来源删除／投递不确定、同轮重复并发及否定发图。真实QQ群外发仍使用具体批准额度，截获发送的重放仅证明发送链路已执行，不能写为群成员已收到。回滚恢复上一插件包并原生重载，保留用户本机配置与凭证。

0.1.12可按部署者明确意愿打开`public_read_all_sessions`，让公开读取跟随AstrBot实际接收范围；默认关闭，旧配置保持名单模式。不要只关闭AstrBot白名单就宣称其他群已有校园工具权限。测试新增群／非本人私聊公开查询成功、本人账号和签到拒绝、跨平台拒绝、私有审核目标未扩大以及“只看不发”不触发实际发送；无需重绑校园账号或开启社区发布。安装前备份原插件和配置，保留模型、人格、其他插件及已有授权。

0.1.10 只需更新 AstrBot 插件，不新增后端路由／迁移／scope。确认 ZIP 包含 `public_canteen.py`；保持原模型、人格、绑定和群白名单。验收“今天吃什么→有图片吗？给我看看→这家评价怎么样”，核对当前店铺、真实评价和原生图片投递；覆盖不同成员、新建对话、过期、无图／无评价、来源删除和投递不确定。短期引用在重载后清空，应先重新推荐。测试外发群消息须使用已批准的具体测试额度；截住发送的本地重放不能记为真实 QQ 收到。回滚只恢复上一插件 ZIP，旧凭证和授权无需变更，社区写入开关保持关闭。

0.1.9 公开查询不再依赖部署者的绑定：先发布服务端匿名 `/api/integrations/v1/public/community/*` 再更新插件，否则新插件会明确读取失败，不回退到私人令牌。验证无凭证可读公开帖、隐藏／删除后不可读、不增加浏览量，`binding`／`me/checkin` 仍需令牌。资讯与校历复用现有匿名 App API；地图要求已发布 `/web/assets/campus-map.png`。不得通过关闭本人接口鉴权满足公开查询。

每日签到单独使用 `checkin:write`，官网默认不勾选，插件 `allow_checkin` 默认关闭。首次启用需本人重连并核对代码／权限，不能代替用户确认、修改旧授权scope或把原有只读授权恢复成写授权。对可丢弃库验证同日重复、与App混用、跨自然日、撤权／scope变更、审计失败整体回滚和并发；本地插件只给本人私聊提供确定签到命令，模型仅可查询状态。不开放补签或定时任务，不开启社区提案／发布开关。

1. 固定不可变候选 SHA，完整测试并按开发规范核验 CI/安全证据。新增 `astrbot-plugin` job 使用真实 AstrBot SDK；PostgreSQL job 显式运行 `TestIntegration` 并提供本机专用测试 DSN，不能让这些测试因缺环境静默跳过。
2. 保存当前二进制、运行环境、有效 Nginx 配置及源码工作树差异。现场已有未提交修改时停止直接部署，先确认其行为被候选保留；不得使用强制重置丢弃它。
3. 只读统计教务核验分布。插件只认可 `school_profile` 且版本为 `v1` / `undergraduate-preverify-v1`；统计是绑定记录数，不是保证可授权人数。用户状态、当前协议和近期登录仍在授权时复核。
4. 对生产数据库做一致性备份，记录恢复入口与校验值。新版本启动会增加集成凭证/动作/审计/限流表、内容来源列和刷新会话的认证时间列；关开关不等于没有迁移。
5. 检查部署入口的源目录、运行目录和 Go 版本。后端使用 `deploy/deploy-shenliyuan <SHA>`。现有官网根目录与客户端产物保持隔离；Web 只发布 `/web/` 子路径并保留已有首页、分享与 API 配置。

## 验收

- `/health`、`/version` 正常，版本 SHA 与候选一致，原 App 登录/刷新及普通社区读取保留。
- 未认证访问 `/api/integrations/v1/binding` 返回身份错误，不能是 404 或无保护数据。
- OAuth 三个协议端点的失败响应保留标准 `error` 字段（例如 `authorization_pending`、`slow_down`），不能被全局业务错误格式改写。官网助手与插件接口不受 Android APK 版本头约束；开启强制更新后仍须验证它们的真实鉴权。
- `/web/connected-apps` 载入正确发布物，静态资源和路由可恢复；缺资格、近期登录失效、网络错误均显示实际失败。
- 用户在 QQ 执行 `/sylu-connect`，在官网确认后执行 `/sylu-status`，随后读取公开帖子；记录真实 `post_id`，确认浏览量未增加、无私有字段。
- 用户撤销连接后旧凭证被拒绝；不通过改提示词或本机白名单绕过服务端授权。
- 试运行不测试线上发帖/评论；写入能力另行灰度并逐次本人确认。

## 回滚

先关闭 `INTEGRATIONS_ENABLED` 并按正式入口恢复上一二进制和环境；恢复新增 Web 路由/发布目录时保留原官网与 API。迁移兼容时保留新增表和列，不删除凭证/审计数据掩盖失败，不回灌整库覆盖发布后用户新数据。需要恢复数据库时由维护者按备份与停写窗口另行操作。

## 已部署连接页的独立静态更新

已存在的 React `/web/` 子应用与官网落地页分别发布。当前 Nginx 的 `/web/` 使用 `/var/www/sylulive` 为 root，`/var/www/sylulive/web` 指向 `/var/www/sylulive/releases/<SHA>/web`。该场景不使用完整官网落地页的替换脚本，不改 Nginx 路由或重启 Go。

1. 固定不可变 SHA，执行 Web 类型检查、连接页 E2E 与构建，检查375px和桌面真实渲染；在授权页明确披露公开昵称、统计、图片及部署者指定群的外发范围。
2. 打包 `web/dist`，记录 SHA256 和逐文件清单；校验包内路径不能逃出目标目录，不含符号链接、源码凭证或 Flutter Web 文件。
3. 记录当前链接目标、Nginx 配置与官网首页摘要。将新构建放入不存在的 `<SHA>/web` 发布目录；保留上一代按哈希命名的静态资源，避免已打开页面请求旧 chunk 时失败。
4. `nginx -t` 通过后，在同一目录创建临时链接并原子替换 `web` 链接。验证 `/web/connected-apps`、该 index 引用资源、助手清单与官网首页摘要；授权说明的文字必须存在于实际线上 JS 中。
5. 任何冒烟失败时原子切回原链接，保留失败构建和日志。成功后记录新旧目标、构建摘要与实际校验，不用恢复业务数据库或重启 Go。

## 可选私有结果分享

`allow_private_review` 默认关闭，开启前检查 AstrBot 管理员列表、允许群和插件来源。审核命令只从允许群发起，原发起人在私聊逐项确认；模型没有确认工具，任意跨会话发送工具从获准私聊／群请求中移除。来源受既有 scope 和可信管理员角色控制，确认再读取并检查摘要；QQ 记录只限本机已保存当前会话。审核元数据最多5项、5分钟有效，重载失效；网络投递不确定不自动重发。实际公开转发必须由维护者本人输入确认命令，不由测试脚本代确认。

## 群命令完全无回应：检查会话隔离与白名单

AstrBot 4.29.3 的 `unique_session=true` 会将 QQ 群会话标识从 `平台实例:GroupMessage:群号` 改为 `平台实例:GroupMessage:成员号_群号`。原生白名单不将完整旧群标识解释为通配符，因此会在插件收到命令之前拦截消息，且关闭白名单日志时没有可见提示。

保留用户的会话隔离设置，在该 QQ 配置档的 `platform_settings.id_whitelist` 中使用“本人完整私聊标识 + 允许的原始群号”，例如 `["实例ID:FriendMessage:本人QQ号", "允许群号"]`。原生白名单支持按 `get_group_id()` 匹配，既适用于共享会话也适用于成员隔离；插件中的平台实例与 `public_read_group_ids` 仍单独限制业务工具。不要打开管理员绕过或取消私人鉴权来修复此问题。原生群号项本身不区分平台，多平台部署应把此规则放入 QQ 专用配置档。

验证应经过原生 EventBus 会话隔离和 WhitelistCheckStage，覆盖本人私聊、群内本人／其他成员、其他群和他人私聊。不能只构造未隔离的群事件便宣称白名单已验收。真实群发图需明确外发授权，并核对 OneBot 消息编号与图片记录；发送结果不确定时不要自动重试。
