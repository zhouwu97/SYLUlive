# 商家详情页贡献入口设计

## 背景

商家详情页同时在菜品空态展示“上传菜品实拍”，在页面底部展示写评价输入框和“添加”按钮。两个入口虽然提交对象不同，但都以新增操作的强强调样式出现，造成页面存在多个重复新增入口的认知负担。

## 已确认的交互方案

收起状态下，详情页底部只显示一个全宽主按钮：`贡献内容`。

点击后打开底部操作面板，面板内提供两个明确按钮：

- `写商家评价`：复用现有评价创建/编辑流程及权限校验。
- `上传菜品实拍`：复用现有菜品实拍上传 Sheet，继续支持输入菜名和上传图片。

菜品空态和评价空态不再展示各自的新增 CTA。评价区仍保留筛选、排序、历史评价、投票和管理操作；菜品区仍保留查看全部和已有菜品详情入口。

## 组件与数据流

- `CanteenDetailScreen` 保留一个 `bottomNavigationBar`，改为全宽“贡献内容”按钮。
- 点击主按钮后，由详情页展示轻量 `showModalBottomSheet`，返回用户选择的贡献类型。
- 选择评价后调用 `_openPrimaryReviewEditor`，不复制登录、绑定教务、冷却和编辑判断。
- 选择菜品照片后调用 `_openDishPhotoUpload`，不复制上传、审核和刷新逻辑。
- 上传或评价成功后继续调用现有 `_reloadSilently`，刷新详情数据。
- 详情页向 `DishGallerySection` 传入 `onUpload: null`，使菜品空态只呈现说明，不出现第二个新增入口。
- `CanteenReviewSection` 的评价空态只呈现说明，不出现“写第一条评价”按钮；评价动作统一从底部贡献入口进入。

## 状态与可用性

- 商家正常且用户可贡献时，主按钮启用，操作面板中的两个入口可用。
- 商家下架时，主按钮禁用并显示“该商家已下架，暂不能贡献内容”；保留历史评价查看。
- 用户未登录或未绑定教务时，主按钮仍可打开操作面板；点击写评价时沿用已有提示，不提前复制权限逻辑到入口层。
- 菜品上传的登录/权限行为沿用现有上传 Sheet 和 Provider 流程。
- BottomSheet 使用现有 CanteenTheme surface、accent、radius 和 AppMotion；不新增全局颜色、圆角或动效系统。
- 主按钮、面板按钮均保证至少 44 logical px 的触控高度，并提供可读的文字语义。

## 验证范围

- Widget test：详情页显示唯一“贡献内容”主入口；菜品空态和评价空态不显示重复新增 CTA。
- Widget test：点击“贡献内容”显示“写商家评价”和“上传菜品实拍”两个选项。
- 保留并运行已有菜品空态、评价筛选失败回滚、评价发布刷新及相关餐饮页面测试。
- Flutter analyze 检查详情页、评价区和菜品区。
- 按 Design QA 检查 light、dark、large-text、菜品空态、评价空态、商家下架和操作面板状态。
