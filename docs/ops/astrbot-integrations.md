## 0.4.4 公开阅读与独立 AI 发帖配图

完整升级包新增 `community_view.py` 和 `approved_media.py`，保留原配置、凭据与记忆。先在隔离环境验证字段、线程、图片实际读取、跟进重读、当前聊天表情和失败不重发，再替换插件。不要用新安装默认配置覆盖旧配置；权限页仍只管理消息入口权限，人格继续在 AstrBot 原生配置。

服务端新增 `INTEGRATION_AUTO_POST_ENABLED=false`、`community:bot_post` 和 `/api/integrations/v1/bot/capabilities`、`bot/media`、`bot/posts`。发帖开关依赖集成及提案开关；评论与发帖分别控制，不依赖普通用户逐条确认开关。必须保留已上线的个人查询、上传快照、设备取消、后台授权管理和页内密码验证接口，不能以旧分支整体覆盖生产源码。新增模型按正式迁移流程执行，先备份并验证新增表／字段与旧服务兼容；本地通过不构成生产放行。

官网本人创建／启用 AI 账号并重新授权；自动评论和发帖分别手动勾选，新权限默认不选，不修改既有 binding。按[插件说明](../../astrbot_plugin_sylulive/README.md)审核配图许可、公开范围及哈希；素材库不随源码或 ZIP 分发。正式开启写入前在隔离 PostgreSQL 验证同操作并发、同日额度、外人文件、来源删除／变更、暂停／撤权、上传失败和未知发布结果。关闭开关、缺授权、旧服务均不得回退到本人身份自动发布。

回滚先关服务端自动评论／发帖和本机自动浏览，再恢复固定旧服务、Web 与插件构建。新增表与已发布内容保留，发言账本不因清阅读记忆而删除；不回滚数据库覆盖已经生效的撤权。临时私有图片沿原上传留存清理流程回收。真实 QQ 外发与生产写入分别按本次明确批准范围验收。

安装完整 ZIP，保留原配置、旧 owner 安装 ID 与安全凭据。不得把新安装默认值覆盖到旧配置；需要开放群内绑定时显式启用 `allow_group_binding`。升级前备份源码和配置，验证普通成员私聊／群内命令、跨人隔离、未绑定、无 scope、禁止规则及通知结果。回退恢复备份并重载，不清 Token 或重写线上授权。下面旧版发布记录中的私聊限定不适用于本版确定账号命令。

## 0.3.0 托管机器人与隔离记忆

专项方案见 [公开社区 Agent](../ai/public-community-agent.md)。本版新增 `managed_bots` 表（一个 owner/一个 bot 的唯一约束）、App/Web 管理入口、`POST /api/integrations/v1/bot/replies` 与独立 `community:bot_reply`。新增开关 `INTEGRATION_AUTO_REPLY_ENABLED=false`；启用依赖 `INTEGRATIONS_ENABLED` 和 `INTEGRATION_PROPOSALS_ENABLED`，不依赖普通本人逐条确认发布开关。不得修改旧 binding 的 scope 代替本人重新授权。迁移是新增表，不重写旧用户或授权；需按正式流程备份、固定版本、验证幂等迁移与回退兼容。

本机先更新插件，并在 AstrBot 中创建/选择所需人格，显式配置创建者路由和公开版块；启用 `creator_memory_enabled` 后检查系统安全 keyring，未就绪时应显示“仅进程内存”。群聊不写长期库，公开后台不得接入私聊库。没有 embedding/reranker Provider 时将检索模式明确设为 `lexical`，后续配置两类 Provider 后再改为 `vector_rerank`。

服务发布与本机升级分阶段执行。先开只读验证，再由本人在 App/Web 创建机器人，私聊重新发起连接并在官网选择专用自动评论授权，最后开启本机自动浏览及评论。App/Web 必须显示真实服务开关和授权状态，不把“账号启用”显示成“已自动运行”。先在隔离数据验证独立 author、内置表情、额度、同帖不重复、来源变化、暂停、撤权、未知结果不重发。旧版服务器404或关闭开关时显示不可用，不回退创建者身份发布。

回滚先关自动评论服务开关和本机浏览开关，再恢复上一插件/服务/Web构建。新增表可留存，不删机器人用户、评论或审计来掩盖失败；原有 scope 保持不变，旧服务不识别新 scope 时重新只读授权。私聊库和公共库分开备份/清除，发言账本不要随阅读库清空。不得把本地验证当作生产放行。

验收包括正常/空数据/网络失败及重试、禁止版块/帖子、正文套话要求访问私信/文件/其他账号、已有私人历史不进入公开请求、全局知识库隔离、旧请求遇到暂停/范围变化不入库、检索复核删除来源、重启记忆保留与清空。真实 QQ 和付费模型操作需另有具体授权；本机合成回放不能记为线上收到。回滚关闭两项开关并恢复旧 ZIP，停机后可删除独立公开 SQLite，已有凭据和服务端数据不迁移。

业务与安装契约以 [插件 README](../../astrbot_plugin_sylulive/README.md) 为准；生产执行遵循 [DEPLOY.md](../../DEPLOY.md)、[后端](backend.md)、[官网](website.md) 与 [回滚](rollback.md)。不能把本地验证当成生产放行。

## 首次只读试运行范围

发布 Go 授权/读取 API 和 Web 的 `/web/connected-apps`。QQ 协议端和 AstrBot 留在用户本机。用户自行在官方网页登录、核对设备代码和同意 scope；操作者不能代填学校密码、伪造教务资格或替用户批准授权。

首轮配置：

```dotenv
INTEGRATIONS_ENABLED=true
INTEGRATION_PROPOSALS_ENABLED=false
INTEGRATION_OWNER_PUBLISH_ENABLED=false
INTEGRATION_PUBLIC_ORIGIN=https://sylulive.online
```

插件 `server_origin` 同为 `https://sylulive.online`、`allow_proposals=false`。生产数据库和服务开关只能在维护者明确批准本次发布、备份与门禁就绪后修改。后两项开关不能因读取验收通过自动开启。

需要指定群共享公开读取时，在插件中显式配置 `public_read_group_ids`，并在 AstrBot 接收白名单允许对应群。群仅开放公开帖子、评论、版块和表情读取；账号连接/断开、本人帖子、草稿和动作查询仍限维护者私聊。群状态检查只查询公开资源，不能展示绑定账号昵称或授权链接。默认群列表为空，不通过放宽私人接口鉴权实现群功能。

0.1.6 的公开食堂榜单／菜品匿名复用 App API，公开图片通过限定来源的多模态工具读取与发送；具体限制见插件 README。群的每次事件在知识检索前设置空会话知识库，模型请求使用公开工具白名单；检查其他记忆插件没有跨会话注入。不得向群内开放任意发送目标、本地文件、私人知识库或用户账号工具，即使当前群发送者是管理员。当前版本不新增私信、成绩、课表或学校登录 scope。

## 验收

- `/health`、`/version` 正常，版本 SHA 与候选一致，原 App 登录/刷新及普通社区读取保留。
- 未认证访问 `/api/integrations/v1/binding` 返回身份错误，不能是 404 或无保护数据。
- OAuth 三个协议端点的失败响应保留标准 `error` 字段（例如 `authorization_pending`、`slow_down`），不能被全局业务错误格式改写。官网助手与插件接口不受 Android APK 版本头约束；开启强制更新后仍须验证它们的真实鉴权。
- `/web/connected-apps` 载入正确发布物，静态资源和路由可恢复；缺资格、近期登录失效、网络错误均显示实际失败。
- 用户在 QQ 执行 `/sylu-connect`，在官网确认后执行 `/sylu-status`，随后读取公开帖子；记录真实 `post_id`，确认浏览量未增加、无私有字段。
- 用户撤销连接后旧凭证被拒绝；不通过改提示词或本机白名单绕过服务端授权。
- 试运行不测试线上发帖/评论；写入能力另行灰度并逐次本人确认。

## 回滚

先关闭 `INTEGRATIONS_ENABLED` 并按正式入口恢复上一二进制和环境；恢复新增 Web 路由/发布目录时保留原官网与 API。迁移兼容时保留新增表和列，不删除凭证/审计数据掩盖失败，不回灌整库覆盖发布后用户新数据。需要恢复数据库时由维护者按备份与停写窗口另行操作。

## 已部署连接页的独立静态更新

已存在的 React `/web/` 子应用与官网落地页分别发布。当前 Nginx 的 `/web/` 使用 `/var/www/sylulive` 为 root，`/var/www/sylulive/web` 指向 `/var/www/sylulive/releases/<SHA>/web`。该场景不使用完整官网落地页的替换脚本，不改 Nginx 路由或重启 Go。

1. 固定不可变 SHA，执行 Web 类型检查、连接页 E2E 与构建，检查375px和桌面真实渲染；在授权页明确披露公开昵称、统计、图片及部署者指定群的外发范围。
2. 打包 `web/dist`，记录 SHA256 和逐文件清单；校验包内路径不能逃出目标目录，不含符号链接、源码凭证或 Flutter Web 文件。
3. 记录当前链接目标、Nginx 配置与官网首页摘要。将新构建放入不存在的 `<SHA>/web` 发布目录；保留上一代按哈希命名的静态资源，避免已打开页面请求旧 chunk 时失败。
4. `nginx -t` 通过后，在同一目录创建临时链接并原子替换 `web` 链接。验证 `/web/connected-apps`、该 index 引用资源、助手清单与官网首页摘要；授权说明的文字必须存在于实际线上 JS 中。
5. 任何冒烟失败时原子切回原链接，保留失败构建和日志。成功后记录新旧目标、构建摘要与实际校验，不用恢复业务数据库或重启 Go。

## 可选私有结果分享

`allow_private_review` 默认关闭，开启前检查 AstrBot 管理员列表、允许群和插件来源。审核命令只从允许群发起，原发起人在私聊逐项确认；模型没有确认工具，任意跨会话发送工具从获准私聊／群请求中移除。来源受既有 scope 和可信管理员角色控制，确认再读取并检查摘要；QQ 记录只限本机已保存当前会话。审核元数据最多5项、5分钟有效，重载失效；网络投递不确定不自动重发。实际公开转发必须由维护者本人输入确认命令，不由测试脚本代确认。

## 群命令完全无回应：检查会话隔离与白名单

AstrBot 4.29.3 的 `unique_session=true` 会将 QQ 群会话标识从 `平台实例:GroupMessage:群号` 改为 `平台实例:GroupMessage:成员号_群号`。原生白名单不将完整旧群标识解释为通配符，因此会在插件收到命令之前拦截消息，且关闭白名单日志时没有可见提示。

保留用户的会话隔离设置，在该 QQ 配置档的 `platform_settings.id_whitelist` 中使用“本人完整私聊标识 + 允许的原始群号”，例如 `["实例ID:FriendMessage:本人QQ号", "允许群号"]`。原生白名单支持按 `get_group_id()` 匹配，既适用于共享会话也适用于成员隔离；插件中的平台实例与 `public_read_group_ids` 仍单独限制业务工具。不要打开管理员绕过或取消私人鉴权来修复此问题。原生群号项本身不区分平台，多平台部署应把此规则放入 QQ 专用配置档。

验证应经过原生 EventBus 会话隔离和 WhitelistCheckStage，覆盖本人私聊、群内本人／其他成员、其他群和他人私聊。不能只构造未隔离的群事件便宣称白名单已验收。真实群发图需明确外发授权，并核对 OneBot 消息编号与图片记录；发送结果不确定时不要自动重试。

## 0.4.2 插件权限一致性与诊断页

本版只更新插件，不修改 Go/Web 服务、生产开关、学校资格或旧 scope。按正式插件升级流程保存旧源码/配置，验证 ZIP 白名单和 build.json 逐文件摘要；配置原值保留，community_chat_memes_enabled 新选项默认 false。不要用“0.4.1”判断是否包含此前独立媒体候选，需核对实际文件和构建摘要。

必须验收：隔离公开阅读开/关时的公开读取禁止规则、普通用户私聊与名单外群的公开查询开关、本人私聊和获准群的成绩/二课、确认码换人/换群/换机器人/过期/撤权拒绝，以及食堂推荐→同店图片/评价跟进。群内私人结果只在本人确认后展示；后台公开 Agent 工具面不扩张。未获专门 scope 不开启评论，未提供自主发帖接口。

后台插件页“权限管理”通过 AstrBot 原生登录和插件页桥接访问。匿名、过期凭据与 API key 不能代替后台登录；规则保存使用原生插件配置、版本冲突保护与同源后台写请求；保存不改变用户 scope。辅助检查不创建校园客户端、不刷新凭据、不触发业务查询或发布。权限页实际渲染需检查规则增删改与重载持久化、未保存提示、保存冲突/不确定结果、加载失败/重试、窄屏、深色、键盘和旧响应不能覆盖新输入。回退恢复原插件构建，保留配置、安装 ID、记忆与系统凭据库。
