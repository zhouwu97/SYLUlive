# 首页互动回复提醒设计

**日期：** 2026-08-18

**状态：** 已确认，待实施计划

**范围：** 首页“水帖 / 最新”信息流、回复通知查询与已读消费、帖子详情页的未读提示清理。

---

## 1. 问题与目标

当前用户只有进入具体帖子后，才会看到“未读回复”横幅。用户在首页无法发现自己的帖子或评论被回复，导致回复容易被遗漏。

本设计将提醒前移到首页信息流，使用户能在首页直接看到：

- 有多少条未读互动回复；
- 最新回复来自谁、回复了什么；
- 该回复属于哪一篇帖子。

点击后仍进入原帖并定位目标回复。帖子详情页不再显示“有新回复”提示，避免同一未读状态在两个页面重复出现。

## 2. 已确认方案

采用“首页信息流顶部互动模块”。模块位于“水帖 / 最新”页的搜索框下方、首个帖子卡片之前。

当存在未读回复时，模块包含：

```text
互动回复    红点    N 条新回复  >
回复人：回复内容 · 《原帖标题》
```

- 仅显示最新一条摘要和未读总数，避免首页变成完整通知列表。
- 有多条未读时，点击模块打开未读回复列表；用户从列表选择某条回复。
- 仅一条未读时，点击模块直接打开该回复。
- 首页展示提醒本身不改变已读状态。

未采用的方案：

| 方案 | 不采用原因 |
| --- | --- |
| 顶部栏仅红点或数量入口 | 用户仍无法在首页直接了解是谁回复、回复了什么。 |
| 仅在自己的帖子卡片上标注 | 原帖不在当前信息流时会遗漏；也无法覆盖“回复我的评论”。 |

## 3. 交互与未读合同

```text
首页加载未读摘要
  -> 显示模块（不标记已读）
  -> 点击单条回复
  -> 成功取得原帖后，仅标记该通知已读
  -> 打开帖子详情并定位 targetReplyId
  -> 返回首页后刷新模块
```

### 3.1 多条回复

- 主页模块仅显示最新摘要和总数。
- 点击模块时，若未读数大于 1，弹出仅包含未读回复的列表。
- 列表项展示发送者头像、昵称、回复摘要、原帖标题和相对时间。
- 点击列表项只消费该项；其余项目保持未读并继续显示在首页模块中。
- 不提供“查看首页模块即全部已读”或“全部标记已读”操作。

### 3.2 跳转与已读时机

- 跳转使用现有 `buildPostDetailRoute(post, targetReplyId: relatedId)`，复用详情页的目标回复定位能力。
- 客户端先拉取原帖。原帖可打开后，再调用现有 `POST /notifications/read-selected` 标记所选通知。
- 原帖或目标回复已删除时，显示明确提示，并消费该条通知，防止无效提醒永久滞留。
- 读接口、跳转或已读请求失败时，用户可继续浏览首页；未读条目不得被本地静默移除。

### 3.3 帖子详情页

删除以下仅服务于“详情页发现未读回复”的行为：

- `GET /posts/:id/notifications/unread` 请求；
- 未读回复横幅；
- 未读回复 BottomSheet；
- 详情页内的“全部标记已读”操作。

保留详情页的正常评论加载、评论排序、`targetReplyId` 锚点定位和回复发送能力。

## 4. 服务端合同

新增一个只返回当前登录用户未读回复的接口：

```text
GET /notifications/replies/unread?limit=20
```

接口要求：

- 强制以认证用户作为 `user_id`；不得接受客户端传入的用户 ID。
- 仅查询 `type = reply` 且 `is_read = false` 的通知。
- 按 `created_at DESC` 排序，并限制最大条数，避免首页请求无界增长。
- 返回通知 ID、帖子 ID、目标回复 ID、通知内容、创建时间、发送者基础资料和原帖标题。
- 发送者和帖子信息使用批量查询，禁止按通知逐条查询造成 N+1。
- 无未读时返回稳定空数组和 `count: 0`，不以 404 表示空态。

已读操作继续复用现有接口：

```text
POST /notifications/read-selected
{ "ids": [notificationId] }
```

该接口已有“当前用户 + 指定 ID”约束，首页只能提交用户自己收到的通知 ID。

## 5. 客户端边界

| 单元 | 职责 |
| --- | --- |
| `UnreadReplyNotification` | 承载未读回复数据，补充原帖标题字段。 |
| 回复通知服务 | 请求首页未读摘要、调用选中通知的已读接口。 |
| `ShuitieScreen` | 管理首页模块的加载、空态、刷新、回复列表和跳转。 |
| `PostDetailScreen` | 仅消费外部传入的目标回复 ID，不再自行查询或展示未读提醒。 |

不把首页回复提醒塞入已有的大型 `PostProvider`，也不改变“我的 - 通知”页、私信未读数或系统通知未读数。

## 6. 状态矩阵

| 状态 | 首页模块 | 用户操作 |
| --- | --- | --- |
| 未登录 | 不渲染 | 无请求。 |
| 加载中 | 不渲染额外骨架 | 首页帖子流正常可用。 |
| 无未读 | 不渲染 | 无。 |
| 一条未读 | 展示最新摘要 | 点击后打开该回复。 |
| 多条未读 | 展示最新摘要与总数 | 点击后选择具体回复。 |
| 请求失败 | 静默隐藏 | 下次进入、回前台或下拉刷新时重试。 |
| 原帖 / 回复删除 | 显示反馈 | 消费无效条目并刷新剩余数。 |
| 已读请求失败 | 保留本地未读条目 | 不移除、不误导用户。 |

## 7. 视觉、动效与无障碍

- 使用现有品牌色、surface、间距和圆角 token；不引入新全局颜色或 radius。
- 模块为单层轻量 surface，不将其设计成嵌套卡片。
- 点击目标至少为 44 × 44 logical px，并提供“互动回复，N 条未读，查看”的语义标签。
- 支持深色模式和 1.3 倍文字；长回复与原帖标题均截断而不遮挡数量或跳转提示。
- 不添加自动展开、列表 stagger 或其他装饰性动画；仅保留现有 Material 按压反馈。

## 8. 验收与测试

服务端：

- 未读接口只返回认证用户的 `reply` 通知，忽略已读和其他通知类型；
- 排序、最大条数、原帖标题和发送者映射正确；
- 多用户数据互不泄露；
- 无未读返回稳定空态。

客户端：

- 未登录、加载中、空态和请求失败时不显示模块；
- 单条与多条未读的摘要、数量和列表行为正确；
- 点击具体条目向已读接口提交且只提交该通知 ID；
- 路由带正确的 `postId` 与 `targetReplyId`；
- 详情页不再请求帖子内未读接口，也不渲染未读横幅；
- 覆盖浅色、深色和 1.3 倍文字布局，检查无 overflow。

## 9. 非目标

- 不改变系统推送、推送点击处理和通知权限。
- 不重做“我的 - 通知”页。
- 不增加通知偏好、静默设置或服务器端实时推送通道。
- 不改变评论本身、评论排序或回复通知的创建规则。
