# 免费表情商城与创作者实施方案

状态：已实现并完成本地验证，尚待正式发布验收。风险 R3（内容治理、权限、公开资源和版本发布）；产品决策见 [ADR-003](adr/003-free-emoji-store-and-creator-access.md)，实际检查、渲染证据及未验证范围见 [初轮报告](../reports/2026-11-03-emoji-creator-store.md) 与 [完整链路复核](../reports/2026-11-03-emoji-full-chain-verification.md)。本方案不授权推送、部署或生产迁移。

## 用户流程与状态

- 我的表情：相册/文件导入 → 安全校验 → 静态预览 → 确认安装；个人标签仅在账号隔离的本机索引中保存，管理页支持包名、对应文字与标签查找，输入面板支持当前包内按对应文字筛选。取消、权限拒绝、损坏、超限、安装恢复和切号行为保留。
- 表情商城：免费目录 → 作者/来源/封面/部分缩略图 → 详情全部表情 → 断点下载 → 校验安装 → 返回输入面板。加载、空、错误重试、暂停、恢复、损坏修复和离线已安装使用均保留。
- 创作中心：未申请/申请中/驳回/暂停/已开通；提交创作介绍及规则确认，由管理员逐项处理。失败不伪造权限，切号、同账号重新登录和管理员撤权后取消旧请求并隐藏旧内容。
- 制作：复制本机素材 → 编辑公开名称、简介、逐张文字、公开标签、封面和面板图标 → 本机草稿 → 上架效果预览 → 确认分享授权 → 提交审核。网络重试和重开同一草稿复用业务幂等身份，修改内容生成不同请求摘要。
- 我的作品：保留历史投稿、审核原因和版本。新版本选择新的本机素材，不能直接改写商城当前内容。拒绝/撤回的记录保持原状态；重新制作通过新的意图提交。

## 资源与版本

发送图沿用安全预检后的最长边 512px 规范化图；服务端静态派生图长边分别为缩略图 256px、封面 320px、图标 96px，等比缩放、不裁切、不放大小图。GIF 网格使用静态图，完整动画在放大预览或发送时加载。

`community_emoji_packs.id` 是不可变投稿/版本记录；`family_id` 是稳定商城包 ID，`version` 由服务端持锁递增。历史 v1 无 family_id 时使用自身 ID。新版本审核通过将原发布版本记为 superseded；显式版本请求可读取审核过的历史版本，但前提是整包仍公开。下架关闭整包所有版本，不能经旧版本 URL 绕过；撤回待审版本不影响商城旧版，撤回已上架作品关闭并回收整个作品版本族。

封面、图标和缩略图经过与原图相同的授权路由，不写普通公开 File，也不信任客户端提交的缩略图。目录展示元数据独立于 Manifest；资源身份继续使用 local，审核通过不产生 official 身份。

## 数据、并发与兼容

- 新增 `emoji_creators` 当前申请及权限记录，使用版本条件和事务保护审批；管理员日志与权限变化同事务写入。
- 投稿入口先验证创作者权限，最终事务再次锁定账号、复核创作者状态和版本族。原有账号幂等唯一约束与额度继续使用，存储额度包括服务端派生图。
- 本机 `creation_drafts` 与个人标签使用原有账号目录和原子索引写入；公开资料与安装 Manifest 分离。草稿保存失败可见、可重试，提交失败保留草稿。
- 旧客户端默认只拿官方目录；不改内嵌官方包及既有 Hash。历史投稿保留，不自动批量授予创作者权限。
- 新表/列通过原有 AutoMigrate 增加；首次、重复启动、旧 v1 数据和回退必须在隔离环境验证。生产服务端先于新客户端发布。

## 验收门禁

覆盖普通用户/作者/他人/管理员、本人不能自审、旧 JWT 撤权、创作者暂停后的上传和通过、相同幂等键不同资料、待审版本不替换公开版、并发处理仅一个成功、私有缩略图/封面不可越权、下架旧版本路由不可访问，以及撤回/注销后的清理与导出。

Flutter 验证本机草稿重开、标签独立、文字与封面编辑、公开预览不能下载未审核内容、失败重试、重复点击、会话失效和真实图片渲染。检查明暗主题、360px、1.3×及1.5×字号和键盘布局；Windows 不更新 canonical Golden。

发布仍须真实 PostgreSQL 行锁、代理授权、真机系统选择器和人工验收；测试通过不等于发布放行。回退与私有存储保全见 [运维入口](../ops/emoji-packs.md)。
