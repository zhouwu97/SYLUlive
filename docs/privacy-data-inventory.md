# 隐私数据台账

> 本台账描述当前代码和迁移期生产边界。配置开关可能使兼容能力处于退役、迁移或测试状态；发布前应结合生产配置复核，不以 README 单独替代审计。

## 数据分类

### App Account Data

| 数据 | 来源 | 用途 | 位置 | 风险与边界 |
| --- | --- | --- | --- | --- |

### Local Academic Data

新版客户端正在将个人教务访问迁移到设备侧。个人教务数据原则上在客户端的安全存储、本地数据库或缓存中处理，并由客户端直接连接学校系统。

| 数据 | 来源 | 当前目标位置 | 边界 |
| --- | --- | --- | --- |
| 学号、学校账号、学校密码 | 用户输入 / 学校系统 | 设备 Secure Storage / Keychain / Keystore | 不进入普通 App API、日志、RAG、MCP、队列或备份 |
| 学校 Cookie、Token、个人会话 | 学校系统 | 设备侧学校客户端会话；自动绑定核验时仅临时传递当前 Cookie/必要会话前缀 | 仅限对应 LocalSchoolProfile；服务端只向固定学校入口核对本人学号，不持久化或写日志，不交给 AI；切换账号时隔离并清理旧会话 |
| 课表、成绩、考试、学业、二课、体测 | 学校系统 | 设备本地缓存和展示状态 | 迁移期兼容服务可能仍存在，是否启用由生产开关决定 |

用户登记的跨设备教务配置保存在服务端 `academic_account_configs`，仅含 App 用户归属、教务类型、学号、状态和版本，不包含学校密码、Cookie 或会话。管理员用户管理、候选人及成员摘要可以展示有效登记学号并据此搜索，优先显示已有可信身份学号；配置登记与可信学生身份分别展示，配置本身不授予身份权限。公开用户资料不返回该学号。管理统计按有效配置、可信身份或旧教务授权的现存用户去重，不读取设备侧密码、会话或原始教务数据。

原教务绑定入口登录成功、恢复本机会话或课表读取成功后，客户端检查服务器身份；记录缺失时先对账账号配置，再调用 `/api/student-identity/verify-session`。服务器仅使用临时学校会话向固定学校本人资料入口核验学号，拒绝客户端自报验证结果、网页或目标 URL。`academic_identity_bindings` 保存核验后的学号、教务类型、方式、时间；`academic_identity_challenges` 只保存尝试摘要、IP 哈希及期限以限流和撤销在途请求。学校密码、会话、完整资料不进入这两张表、日志、备份或 AI。解绑撤销身份并为匹配配置写删除墓碑，旧会话不能自动恢复权限。

### 用户主动导出的课表与考试存档

点击课表保存/导出或考试导出后，将课程或考试的展示字段写成公共 JSON 文件；不包含学校密码、Cookie、Token、个人原始 HTML 或设备密钥。Android 10 及以上位置为 `Download/沈理校园/课表存档/`、`Download/沈理校园/考试存档/`，旧版本由系统文件选择器选择位置。保存时的提示显示实际位置；自动读取教务课表不会自动导出。分享使用应用临时目录内的同内容副本，仅在用户点击分享后交给其选择的应用。公共文件由用户管理，App 内删除、退出账号或卸载不会保证删除公共副本。

### User-authorized Derived Snapshot

部分功能允许用户明确授权上传经过限制的结构化摘要，例如二课快照，用于校园 Agent 或服务端分析。它不是个人教务原始数据的替代存储。

- 只接受约定的结构化字段：总学分、缺失分类、年度统计、最多 20 条近期活动摘要等。
- 服务端拒绝 `password`、`cookie`、`token`、`session`、`credential`、原始 `html` 和设备密钥等敏感字段。
- 客户端提供的哈希不作为服务端身份或来源证明。
- 用户可以通过对应 API 删除快照；删除后下游校园 Agent 不再读取该快照。

公开食堂榜单、搜索、活跃菜品及审核通过实拍沿用匿名 App API，不附加绑定账号凭证。AstrBot 图片工具仅下载本站公开上传路径，重新核对来源，缩放后经原生多模态链交给当前模型；每轮最多两张。公开群禁用全局知识库继承和跨会话工具；管理员身份不扩大业务 scope。已发到 QQ、模型或第三方记忆的公开信息无法由本地删除逆向收回。

AstrBot 0.1.10 通过匿名食堂详情的字段允许表补充位置、评分、部分公开评价原文／昵称／日期、评价配图和已审核菜品照片，不外发用户ID、学号、创建人、信用资料、编辑状态或完整账号对象。食堂短期引用仅在插件进程内保存编号和单调时钟时间，按平台会话、发送者及原生对话CID隔离；最多256项，30分钟后读取即失效，重载清空。后续查询重新取公开来源，下载后复核，失效时不拿旧照片代替；已进入QQ／模型的副本不能逆向撤回。

私有结果审核分享默认关闭：本机绑定本人／可信 AstrBot 管理员以确定命令请求审核，私有原文只先投递发起人私聊。QQ 来源限本机 AstrBot 已保存当前私聊，最多最近5条纯文字、每条300字，省略系统／工具／图片并遮盖常见凭据；SYLUlive 仅限既有 scope，管理员不能继承他人绑定。原发起人私聊逐项确认才向原允许群分享，确认前不进入群模型。会话偏好保存最多5项审核元数据、不存正文或凭证；5分钟到期、来源变化、撤权或插件重载使审核失效，过期元数据下次操作清理。已确认的 QQ 群副本不能撤回，留存由 QQ、AstrBot 和部署的记忆插件决定。

AstrBot 0.4.3 权限管理页只保存功能开关、规则、用户 QQ／群号与投递策略到 AstrBot 原生插件配置，留存沿用部署者的原配置与备份策略。检查输入／结果不持久化，不刷新令牌或访问个人业务接口；规则允许不能替代本人 scope。插件不再内置角色，人格取自 AstrBot 配置，其 prompt 可能送入当前会话模型；公开后台不读取本人会话历史或示例对话。卸载插件不会逆向删除原配置备份、QQ 或提供方副本。

## 留存与删除

0.3.0 新增创建者私聊检索库：只记录本机配置的创建者本人当前私聊文字与最终回复，不回填旧历史，不收群消息。正文加密，密钥由系统安全凭据库持有；不可用时仅内存，最多2000轮/180天。检索在本机按词匹配最多3轮并只交给本人的聊天模型，公共后台与群请求没有此库引用。群短时上下文仅在进程内，最多32群、每群6轮、30分钟。原始QQ/AstrBot聊天和远端模型副本分别管理。留存清除命令见插件README。

一人一个托管AI机器人由App/Web本人管理，关系表不在公共接口外露，机器人无有效登录凭据或平台管理员权限。新的 `community:bot_reply` 授权默认不选、旧授权不扩权；后台使用独立机器人身份，仅评论当轮读到的公开帖子、附有效内置表情。服务端再次检查来源、资格、禁言、暂停、撤权与额度。本机发送前预留无正文账本，结果未知不盲重发。此过程不读取创建者私聊库或共享其登录态。管理界面不通过服务端读取本机私聊记忆；暂停和清记忆是不同操作。

AstrBot 0.2.0 的可选公开 Agent 默认关闭，启用后使用隔离的公开人格/上下文和工具允许表，私聊/群的模型不继承已有聊天、全局知识库或账号查询结果；0.3.0只在已鉴权本人私聊另行注入本人的加密记忆；私有分享入口关闭。后台经 AstrBot 原生 Agent 使用显式 Provider ID，仅浏览配置允许的 SYLUlive 公开版块和帖子，匿名请求隔离账号 Cookie/Token，不跟随链接，不访问站内私信、通知、学校系统或任意网页，不自动向群投递或创建草稿。公开来源文本可包含发布者自行填写的个人信息，并非全文脱敏。其他插件的后续注入和模型服务留存由部署者管理，独立实例建议及配置见 [插件 README](../astrbot_plugin_sylulive/README.md)。

公开 RAG 保存在插件数据目录、按服务 origin/本机 owner 路由身份哈希区分的 `*.public-memory.sqlite3`：仅保存实际阅读的公开帖子 ID/版块/标题/原文（最多10000字，标明截断）/版本/读取时间，以及可选模型版本隔离的向量，不保存聊天、作者账号对象或生成式经历。上限500篇、7天；启动/读写/后台30秒检查时清理，停机期间不执行物理清理；`/sylu-agent forget` 清本机原文和向量库并使在途写入失效。向量模式复用 AstrBot 配置的 embedding/reranker，将检索词及重新核验过的公开片段交给所选提供方，最多10条重排候选、返回3篇；来源隐藏/删除/超范围/网络错误不把旧正文交给模型。已进入 QQ/AstrBot/Provider/备份的数据不逆向撤回；来源变化不会立即推送到本地，停用后可在停机状态删除该独立库。

0.1.9 的公开社区、食堂、资讯、校园地图与学校校历均匿名查询，不携带绑定账号凭证；消息接收白名单仍独立生效。可选每日签到新增独立 `checkin:write`，官网需本人手动选择，旧授权不会扩权；只允许绑定本人私聊显式命令，不含补签／自动定时。日期、连续天数及本次奖励回到本人 QQ；事实和经验沿用 App 原表，`integration_audits` 仅记录 `daily_checkin` 元数据，沿既有审计留存，不记录学校凭据或私人消息正文。

AstrBot 集成与内置 Go AI 只读工具分别控制。集成接口每次查当前授权/身份，发帖与撤权串行争用用户行锁；教务换绑/解绑、注销、撤销协议立即撤销集成并清空待发布草稿。已完成或拒绝的草稿立即清空正文，保留幂等摘要和结果；过期草稿由6小时清理周期清空，期限见留存台账。普通来源删除或改写后，待发布草稿不再返回旧正文/执行，要求重新生成；已发给用户部署的 AstrBot、历史记忆和外部模型的数据不能本地逆向撤回。本实现未连接真实用户 QQ 或外部付费模型，正式启用需固定版本联调、资格覆盖和隐私发布复核。

社区读取新增能力默认关闭。工具结果进入现有 `ai_tool_calls` 审计，可能包含截断正文；会话删除沿现有清理流程删除所属 Run 与工具审计。来源隐藏或删除后，新增工具的新读取和幂等缓存重放会重新检查；已存在的历史审计、回答、已装入运行任务的消息以及外部 Provider 已收取的数据不会因此自动删除或逆向撤回。来源删除传播、运行中授权代次复核与专门留存治理尚待后续阶段实现，不能把当前只读增量作为生产开放验收。留存现状见对应台账，不把工具调用过期字段当成自动物理删除机制。

具体留存期限以 [`retention-and-backup-inventory.md`](./retention-and-backup-inventory.md) 和产品/法律要求为准。账号注销、绑定解除、快照删除和推送关闭必须分别执行对应清理，不以删除客户端缓存替代服务端清理，也不以服务端清理替代设备侧凭据清理。

## 发布前检查

1. 核对 `SCHOOL_AUTHORITY_RETIRED` 与 `SCHOOL_ACADEMIC_ROUTES_RETIRED` 的生产值。
2. 确认个人学校凭据、Cookie 和原始教务响应不进入日志、AI、MCP、队列、备份或错误上报。

### AstrBot 本机权限诊断

0.4.2 的部署者后台只读预览处理输入平台/机器人/发起人/群号、规则结果及本机授权 scope 元数据，不查询或返回私人资料、成绩、二课、聊天正文、Token 或学校密码。不创建安装 ID/业务客户端、不刷新凭据；无新增本机或服务端持久化。当前输入/结果仅存在请求与浏览器页面内存，不发送给模型。服务端资格和授权有效性留待本人真实业务请求校验；本机凭据状态不能冒充服务端认证结果。AstrBot 部署者和原生后台登录权限仍是本地控制边界。
