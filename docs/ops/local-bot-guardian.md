# Windows 本机机器人守护

用于已安装在 `D:\AI\QQ` 的 QQ → SnowLuma → AstrBot 链路。主入口 `scripts/local-bot-guardian.py`；先验证本机固定机器人身份及已有登录。依赖本机 AstrBot 环境的 httpx、psutil，不添加远程访问或自动登录学校。

## 安装和日常操作

执行 `scripts/install-local-bot-guardian.ps1`，把已验证脚本安装到本机 `guardian/` 并注册当前用户的登录任务。任务隐藏运行、不要求管理员，不保存 Windows 密码；登录时启动并每分钟检查是否需要启动守护，OS文件锁避免重复实例。若系统拒绝注册任务，安装器明确报告并使用当前用户 Startup 启动项及当前进程，不能声称拥有任务计划服务的故障恢复能力。

守护每30秒核验服务响应、QQ本人与在线状态、反向 WebSocket、插件后台健康。连续3次失败才尝试恢复；同一服务至少间隔2分钟，指数退避，每小时最多3次。权限关闭、用户暂停、校园撤权或业务模型失败不当作进程故障。后台任务恢复不重置社区发言限额和去重记录。Dashboard JWT过期用已有本机管理凭据重新认证，凭据不写入守护状态或日志。

`D:\AI\QQ\guardian\health.json` 记录最近检查和有限状态；`state.json` 保存恢复次数与时间，日志只写固定错误码，循环日志限制大小。没有保存QQ消息、模型正文、学校资料或访问令牌。

- 暂停维护：创建 `D:\AI\QQ\guardian\paused`，随后停止/升级原服务，避免守护拉起维护中的服务。
- 恢复维护：删除该文件，下一轮重新检查。
- 停用守护：先保留暂停文件，在任务计划删除 `SYLUlive-LocalBot-Guardian`，删除安装器记录的 Startup 项，并仅终止命令行包含本机 `guardian\local-bot-guardian.py` 的进程。原机器人服务不会被停用。
- 手动只读检查：本机 Python 执行 `guardian\local-bot-guardian.py --root D:\AI\QQ --once`；若已有守护运行，文件锁会使重复实例退出，读取现成 health.json 即可。

进程恢复只匹配固定程序路径/参数/工作目录，不能终止QQ或其他Node/Python程序。端口被未知进程占用时停止自动启动并记录原因。桥接恢复继续使用 `connect-bot.py` 对固定QQ的PID、创建时间和程序路径核验；QQ重开导致身份变化时要求核对机器人，不猜选其他个人账号。

QQ退出登录、需要扫码、人机验证、电脑关机/休眠或外部平台不可用无法靠守护绕过。电脑唤醒后会重新检查和恢复；此功能不修改系统睡眠策略，不承诺断电仍可运行。服务端权限和社区策略的生产发布仍走正式运维入口。

## 验证与回退

运行 `python -m pytest -q scripts/test_local_bot_guardian.py`，插件运行回归见 `astrbot_plugin_sylulive/tests/test_bot_runtime.py` 与登录保护测试。实际安装先备份插件和守护脚本，再核验原生配置/人格摘要、已安装文件摘要、在线QQ、WS及任务心跳。进程退出恢复通过隔离子进程演练；实际重启只针对已确认本机机器人服务，不重放真实消息或公开评论。

回退删除本次守护任务/启动项，终止守护，恢复备份插件并原生重载；保留用户配置、凭据、记忆、发言账本及限流。不要删除评论记录来测试重启后的发言能力。
