# ADR 004：QQ 账号连接与学校资料能力分开

- 状态：accepted
- 日期：2026-11-16
- 决策依据：维护者明确要求先连接自己的本站账号并使用基础能力；学校连接失败只影响对应资料功能，在网页处理。

## 决策

QQ 集成的身份主体是当前登录的本站用户。查看请求、本人确认授权、领取和刷新凭据、查看连接、签到及管理自己的机器人，不要求学校核验、学校登录或预先同步资料。账号状态、现行协议、本人一次性确认、权限范围、资源归属、撤销与凭据期限继续生效。

成绩和二课仅返回本人明确同步／授权保存的摘要，需对应 scope、个人服务开关和隐私设置允许。缺资料返回 `academic_sync_required`，提示到官网「个人资料同步」准备资料；该错误不撤销连接或阻断签到。学校密码、验证码和学校网络错误在网页／教务助手的实际连接步骤处理，不增加一层本站学生资格门槛。

用户上传始终标记为 `user_uploaded_snapshot`，不表述为学校实时来源。学校记录只可用于关联同步资料的上下文和版本；本机声明、历史记录或本人上传均不会授予可信学生身份、学号唯一占用或其他平台特权。学生资格的独立规则保持不变。

学校换绑／解绑清除本人旧的成绩、二课同步副本和云端成绩缓存，保留本站账号的 QQ 连接、签到和公开社区授权。注销、撤回协议、账号不可用、密码版本变化以及本人撤销连接，继续使相应凭据失效。

## 兼容与恢复

保留 `IntegrationBinding` 的历史学校字段以兼容数据库；新连接不依赖这些字段，读取本人同步资料时使用当前资料上下文，不要求重新绑定 QQ。无新增数据库迁移。回退到旧后端会恢复旧的学校准入限制，但保留连接记录；再次部署修正版可恢复基础访问，无需清空凭据或伪造学校核验。

## 验证

必须覆盖无学校记录、本机声明和历史身份三类普通账号的连接、领取、状态、签到、刷新、撤销；缺资料后基础能力仍可用；资料修复无需重绑；学校解绑不撤销 QQ；拒绝伪造 nonce、越权 scope、其他账号访问和隐私禁止。跨运行时夹具不预置学校核验，以实际 Web、Go HTTP 与 AstrBot SDK 验证。
